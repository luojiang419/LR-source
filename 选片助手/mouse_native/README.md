# 鼠标输入协议来源

`mouse_transport.py`、`interception.py` 基于用户提供的 `D:/Myproject/USB/native/` 控制端源码移植；依据为 USB 项目 2026-10-19 的教程，全文已于 2026-10-20 集成至本项目[无线鼠标驱动改造与创意功能开发教程](../../技术文档/无线鼠标驱动改造与创意功能开发教程.md)，可直接阅读完整方法与 LR 实现对照。新版 `driver_setup.py` 在缺少驱动时调用固定哈希的官方 Interception 安装器 `/install`，许可文件随安装组件保留；复用原签名驱动，不部署未签名 HeartMouse，不绕过 Windows 安全策略。原厂安装器安装其输入过滤组件，LR 只打开已确认的鼠标控制节点。

完整安装阶段和进入遥控设置时自动检查，安装由 Windows UAC 授权；取消可重试。安装结束核对系统 `mouse.sys` 哈希，不覆盖异版驱动；首次安装提示重新插接接收器或重启，不自动重启、不热重载其他设备。已有受支持驱动直接复用。仅有签名和文件不代表过滤器已加载，设备列表仍为空时需按提示重启并检查系统拦截信息。

保留已验证驱动 SHA-256 白名单、四项 IOCTL 白名单、24 字节 MOUSE_INPUT_DATA 和动态枚举。`profiles.py` 为原 `VID_367B&PID_1919` 与罗技 `VID_046D&PID_C534&MI_01&COL01` 分别保留独立适配；罗技配置必须同时匹配鼠标接口和集合，拒绝键盘、媒体与其他鼠标。不得调用未实现的 GET_FILTER。输入路由的 `like` 是来源模块内部动作标识，在本项目回调中表示一次加星。

新旧配置可以同时连接并在页面选择；同一配置出现多只接收器时拒绝接管。页面提交槽号、配置和硬件身份，启用时重新枚举并在打开句柄后复核；忽略 `REV_XXXX`，保留 MI/COL。所有配置共用原进程锁，与旧版 LR 互斥。输入线程因设备错误退出后，重新插入并刷新设备可重建连接；不会自动恢复接管。

罗技适配的本机 REA、签名、拔插与真实输入记录见[罗技无线鼠标适配与验收](../../技术文档/罗技无线鼠标适配与验收.md)。独立诊断命令（在 LR 根目录）：

```powershell
python -X utf8 选片助手/mouse_probe.py
python -X utf8 选片助手/mouse_probe.py --capture --seconds 30 --output build/mouse-probe.json
```

第二条命令只统计输入，不写照片；到时或按 `Ctrl+Alt+F11` 释放接管。运行前停止正式遥控并正常退出已持有接收器锁的其他末帧进程。

设备须已安装教程中匹配的签名驱动。其他驱动版本须先核实协议，不能移除哈希校验冒充兼容。运行时不依赖 USB 项目目录或 HeartRelay 程序。

扩展输入保持原24字节协议：右键 DOWN/UP 位为 `0x4/0x8`，按下边沿回调 `decrease`；竖轮位 `0x400`，`rolling` 按有符号16位解释，每120单位为一格，高精度余量累积。正增量为 `previous`，负增量为 `next`，横轮不导航。左键继续兼容无参加星回调。扩展动作由 `MouseRemote` 的独立开关门控，默认关闭，配置原子保存到本机 `mouse-remote.json`；开启/关闭功能会清除旧滚轮余量。
