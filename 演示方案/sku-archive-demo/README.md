# SKU 资产归档交互演示

本轮用于确认操作逻辑，不连接生产服务、NAS 或照片库。所有匹配、文件夹选择、复制、元数据写入和校验均为样例模拟；导出的 `.xlsx` 明确标注演示，嵌入的缩略图是现有样例，不对应这些模拟文件。

当前预览：`http://127.0.0.1:18826/`。页面已由开发者启动；刷新会重置模拟状态。

## 两种操作布局

| 方案 | 操作方式 | 适合场景 |
| --- | --- | --- |
| A 分步向导（推荐） | 位置与规则 → 匹配与复核 → 归档预览 → 复制与校验 | 大批量、来源目录多、需要复核最终大档匹配歧义 |
| B 单页确认 | 配置、复核、目录预览集中在同一滚动弹窗 | 熟悉规则、希望减少步骤的重复归档 |

两个布局使用相同的范围、匹配规则与完成条件。可在弹窗关闭后切换。

## 可操作内容

- 左侧切换“细节图 / 2026 / 上午”；前两项现场范围包含 3 个深层拍摄目录、3 款、6 张记录，最终大档保留 5 张；末级包含 1 款、2 张。
- “资产归档”位于“资产库解析”右侧；点击进入所选布局。
- 选择已有款号文件夹直接归档，或现场散图匹配最终大档；输入 UNC/本机路径或打开模拟目录选择器。
- 选择 RAW + JPG 或仅 JPG 的演示数据；正式版应扫描后自动判定格式。
- 调整母 SKU 默认前缀长度（2–6 位），即时更新目标路径；单母款范围选择到现有母目录时直接复用，不重复套层。
- 散图场景默认 5 个大档均根据元数据唯一指纹自动匹配，待处理 0；1 张后期已删除的现场废片自动跳过。不需要点击连拍候选确认，可直接按最终 5 张归档并得到 5/5。真正身份字段缺失或同一身份业务记录冲突时才阻断。
- 预览 LC78 已有母目录、LC79 新建母目录，以及一个已存在且内容一致的目标；RAW 配 XMP，JPG 内嵌。
- 模拟复制进度、暂停/继续、暂停后关闭再打开；在当前页面会话内续作。刷新后的持久恢复属于后续正式开发。
- 弹窗关闭后勾选“演示校验失败”，可查看失败和重试；完成后可展开逐文件清单、导出带嵌入缩略图的 Excel。归档明细只含最终目录实际保留的文件；后期删除记录独立工作表追溯，不带虚构目标。

## 仓管核查表

“导出校验报告 (.xlsx)”生成两个工作表：归档明细和后期删除记录。前七列依次为母SKU、子SKU、存储路径、文件缩略图、归档日期、归档前路径、归档后路径；另有校验结果、配套 XMP 路径、备注。每个图片文件一行，RAW 的 XMP 在同一行对应。冻结表头与母子 SKU 列，启用原生筛选表；缩略图嵌入并设置随单元格移动和调整大小。

导出命名为 `归档校验报表-YYYYMMDDHHmm.xlsx`，例如 `归档校验报表-202611061528.xlsx`。命名使用导出当时的北京时间，精确到分钟；报告内的归档日期仍取原作业记录。真实验证脚本也使用该命名，核查页面优先链接最新日期报告，保留旧报告兼容入口。

存储路径为款号目录，归档后路径为完整目标文件名。归档前路径来自最终大档目录；废片表只记录现场旧路径。日期取作业完成记录并按 Asia/Shanghai 显示，已存在目标的原归档日期未知时保持空白；失败项的归档后路径、归档日期留空，计划目标写在备注。

本机演示接口为 `/api/demo/archive-report`，使用本机已配置的 Codex 表格运行库，仅用于当前开发演示；正式发行需要接入项目自带的离线报表依赖，不能依赖 Codex 缓存。运行库链接位于忽略目录 `.runtime/report-authoring/node_modules`，指向工作区依赖加载工具提供的 Node.js 包目录；也可用 `CODEX_REPORT_RUNTIME_DIR` 指定已有运行库链接目录。

专项检查：`node --test tests/archive-report.test.mjs tests/metadata-identity.test.mjs`。实际点击导出后，可运行 `node scripts/preview-archive-report.mjs` 对同一份报告渲染并检查两张表，证据在 `build/sku-archive-design/xlsx-preview/`。正式版需从每行实际文件提取缩略图，不能沿用本演示的样例图片映射。

## 工程边界

`src/App.jsx` 和 `src/styles.css` 实现演示，`src/metadata-identity.js` 对构造的相机元数据实际计算快门身份并唯一匹配；不读取文件内容或图片像素。`tests/metadata-identity.test.mjs` 覆盖跨格式、同秒连拍、不同相机、缺字段、子秒规范化、真实冲突和同身份重复记录合并。`public/theme.css` 为制作时复制的项目现有主题快照。没有改动正式页按钮及 Python 归档服务；真实 RAW/JPG 元数据提取与相机标签差异仍需正式后端和实拍验收。

完整设计及后续正式接入边界见 [开发任务 186](../../开发任务/186-SKU资产归档方案与演示.md)。正式需求还包括真实逐文件 SHA-256、JPG 像素与元数据读回、RAW/XMP 成对处理、来源变更检查、NAS 断线重试与任务持久恢复，本演示不声称已实现这些后端能力。

本机恢复预览：在本目录运行 `npm install --prefer-offline --no-audit --no-fund`，然后运行 `npm run dev -- --host 127.0.0.1 --port 18826 --strictPort`。构建使用 `npm run build`，构建产物及 `node_modules/` 已忽略。

## 真实数据验证入口（2026-11-06）

用户要求的真实归档副本位于项目根目录 `测试文件夹/`，内有小档、大档、sku库。真实执行使用 `选片助手/sku_folder_archive.py` 和 `tools/verify_sku_folder_archive.py`，此React页仍是模拟操作，不能把它视为已接入真实后端。

真实核查页为 `http://127.0.0.1:18827/核查页面.html` 或测试目录内同名HTML，Excel为 `测试文件夹/sku库/归档校验报告.xlsx`；8个改名真实大档依相机元数据匹配到3款，4RAW/4JPG/4XMP通过，2张现场废片自动跳过。SKU是本次测试备案值，缩略图取实际归档文件。

实际Canon字段与旧模拟字段存在差异：RAW的快门计数可在Track4，JPG在Canon，ImageUniqueID在两种格式中不完全相同。真实服务使用经验证的型号、机身序列号、原始时间与子秒、快门计数组成`capture-v2`，未依赖改名前后文件名或内容哈希。已完成本批Canon样本验证，不代表所有机型都支持。

## 归档前处理、网格与二星标签

- “归档前处理”默认勾选，A/B 共用。开启后先把已入库的小档（含保留的废片小档）和最终大档整理为母SKU/子SKU，已有母目录复用，RAW侧车同行移动，现场数据库路径同步。关闭则大小档来源结构保持不变，只生成归档目标层级。
- 整理前检查重名、链接、越界和来源变化；失败回滚移动与数据库，记录持久日志；移动与数据库提交之间的中断窗口可恢复。预览只展示计划，确认前不移动真实文件。
- 归档报告保留原始来源路径，并在备注中记录整理后路径，明细及删除记录均加可见横纵细边框。保留“文件缩略图”列，追加“图片类型”说明二星标签；用户取消了独立标签图片列和SKU预览图改名。
- 二星标签图不按普通废片跳过：大档中存在时优先归档，否则从已入库小档补充JPG。大档原片数、补充标签数、总归档数分别记录，标签不重复添加。
- `tools/verify_sku_archive_modes.py` 只在原测试素材的新副本上验证两种目录模式，成果保存在测试目录sku库下`.模式验证`；此前普通照片样例中的人工二星不作为真实标签，因此这一旧场景显式不启用标签补充。
- `tools/verify_archive_label_images.py` 用真实二星标签 `XSY_2297`、`XSY_2365` 分别验证小档补充和大档优先，两种整理模式都通过；最新成果由`.runtime/last-archive-labels.json`指向。款式图按测试指定SKU备案，不声明它与标签属于原业务同款。
- 缩略图按稳定文件身份命名，整理改变扫描顺序后，重复归档不会覆盖另一张图的预览。
