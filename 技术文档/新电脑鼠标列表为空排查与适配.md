# 新电脑鼠标列表为空排查与适配

适用现象：安装末帧后，“刷新设备”列表为空，目标鼠标仍能移动系统指针。对方已确认 Windows 10；尚未确认具体系统版本、是否重启、接收器硬件 ID 和驱动状态。本机源码检查不能替代对方电脑的实测。

鼠标在未启用遥控时正常移动是预期行为，不能据此判断过滤驱动安装成功或失败。先解决设备枚举，再验证接管和标星，不要直接重写内核。

## 先做现场确认

1. 记录软件版本／发布号，以及鼠标面板和组件提示的完整文字。
2. 确认安装驱动时出现的 Windows UAC 已允许。安装软件和系统驱动已生效不是同一个状态。
3. 退出其他末帧、旧 HeartRelay 或其他接管工具，重新插入目标接收器，重新打开末帧并刷新。
4. 若首次安装后仍为空，保存工作，使用 Windows 开始菜单的“重新启动”，登录后再次刷新。关机再开机可能受快速启动影响，不能替代这次验证。记录重启前后差异。

## 在对方电脑采集只读证据

打开 **64 位 Windows PowerShell**，逐段执行并保存输出。以下命令不安装驱动、不重载设备、不接管输入；日志读取提示拒绝访问时，可使用管理员 PowerShell 重做查询。

### 系统和实际接收器

```powershell
Get-CimInstance Win32_OperatingSystem |
    Select-Object Caption, Version, BuildNumber, OSArchitecture

Get-PnpDevice -Class Mouse -PresentOnly |
    Select-Object Status, FriendlyName, InstanceId |
    Format-List
```

插着接收器执行一次，拔出目标接收器再执行一次，插回后执行第三次，用消失和新增的实例确认目标。设备名称“通用 HID 鼠标”不能确定型号。

当前 [profiles.py](../选片助手/mouse_native/profiles.py) 仅匹配以下两类：

| 配置 | 必须匹配的硬件身份 |
| --- | --- |
| 原无线接收器 | `VID_367B&PID_1919` |
| 罗技 C534 接收器 | `VID_046D&PID_C534&MI_01&COL01` |

REV 修订字段可忽略，罗技 MI/COL 接口和集合必须保留。蓝牙连接、更换接收器或其他罗技型号可能具有不同身份；同一品牌不代表已适配。

### 驱动文件、签名、服务与类过滤器

```powershell
$mouseDriverPath = Join-Path $env:SystemRoot 'System32\drivers\mouse.sys'
if (Test-Path -LiteralPath $mouseDriverPath) {
    Get-FileHash -LiteralPath $mouseDriverPath -Algorithm SHA256
    Get-AuthenticodeSignature -LiteralPath $mouseDriverPath |
        Select-Object Status, StatusMessage, SignerCertificate |
        Format-List
} else {
    'mouse.sys 不存在'
}

sc.exe query mouse
sc.exe qc mouse

Get-ItemProperty -LiteralPath 'HKLM:\SYSTEM\CurrentControlSet\Control\Class\{4d36e96f-e325-11ce-bfc1-08002be10318}' |
    Select-Object UpperFilters |
    Format-List
```

LR 核实过的 `mouse.sys` SHA-256 为：

```text
0f12d47d01864ca5e1eb663a52b3d2c060521e57b68ff99d70e7f01506e400f9
```

文件不存在：系统驱动未部署，应检查官方安装授权与日志。哈希不同：当前客户端拒绝通信，先确认驱动来源及协议，不删除校验。文件正确但服务不存在／未运行或鼠标类过滤器未包含 `mouse`：继续检查安装注册和启动失败原因；不要直接复制历史教程的创建服务命令。服务 RUNNING 和过滤器注册存在也不能单独证明目标设备栈已经挂接。

### 系统拦截和启动失败记录

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='Microsoft-Windows-CodeIntegrity/Operational'
    StartTime=(Get-Date).AddDays(-2)
} -MaxEvents 30 -ErrorAction Continue |
    Select-Object TimeCreated, Id, Message |
    Format-List

Get-WinEvent -FilterHashtable @{
    LogName='System'
    ProviderName='Service Control Manager'
    StartTime=(Get-Date).AddDays(-2)
} -MaxEvents 50 -ErrorAction Continue |
    Select-Object TimeCreated, Id, Message |
    Format-List
```

检查记录是否实际涉及 `mouse.sys` 或 `mouse` 服务；无记录不证明加载成功。若系统明确阻止该旧驱动，应选择适用系统的签名兼容方案，不以关闭内存完整性、签名校验或测试模式作为默认适配方法。

### 应用安装记录与源码探针

实际用户资料目录可能来自安装目录的 `.framekeep-install.json`、启动器的 `FRAMEKEEP_DATA` 或项目 `.framekeep/`，不能假设始终位于程序旁。收集该资料目录中存在的 `mouse-driver-status.json`、`mouse-driver-install.log`，无需复制照片、数据库、API 配置或整个资料目录。当前安装日志主要记录安装器退出码，不是完整的驱动加载日志；没有日志也可能是应用复用了已有驱动。

有源码和 Python 的电脑，可在复制过来的 **LR 项目根目录**执行：

```powershell
python -X utf8 选片助手/mouse_probe.py --output mouse-probe.json
```

这个命令只枚举，不加 `--capture`，不会启用输入过滤；先退出其他持有接收器锁的工具。仅安装版不要求另装 Python，先收集前面的系统证据即可。

## 已确认的检测局限与修改入口

2026-10-21 核对当前源码：

| 文件 | 当前行为与适配方向 |
| --- | --- |
| [driver_setup.py](../选片助手/mouse_native/driver_setup.py) | `state()` 的 `installed` 只表示文件存在且哈希匹配，空闲时会显示“驱动已就绪”；没有核实服务加载和目标设备栈挂接。后续应区分文件部署、服务／过滤器注册、加载、待重启和可枚举。 |
| [component-ui.js](../演示方案/component-ui.js) | `driver()` 看到 `installed=true` 就继续，安装完成后的待重启提示可能被隐藏；适配时应保留该提示，不能将文件校验描述为设备可用。 |
| [mouse_transport.py](../选片助手/mouse_native/mouse_transport.py) | `enumerate()` 仅返回已匹配配置，并跳过包括错误 2、5 在内的部分访问错误。空列表可能表示控制节点不存在、访问被拒绝／占用，或读到的硬件不在配置内；当前输出没有逐节点原因。 |
| [profiles.py](../选片助手/mouse_native/profiles.py) | 新接收器先通过拔插确定 VID/PID、MI/COL，再加独立配置；不能通过匹配全部 HID 设备来解决空列表。 |

建议下一步按现场证据补充“控制节点打开结果、未匹配硬件 ID、Win32 错误码”的只读诊断，再决定修复安装／加载检测还是新增接收器配置。诊断仍须经过驱动哈希和进程互斥检查；只用现有白名单 IOCTL，不能探测未实现的 GET_FILTER。

## 适配后的验收

- 目标接收器在 Windows 中存在，应用刷新列出正确型号、接口和动态槽位。
- 用户明确启用后，目标鼠标不再移动系统指针，标星按选定方案工作，其他鼠标保持正常。
- 停止、正常退出及 `Ctrl+Alt+F11` 恢复普通鼠标；记录实物观察，不能只根据“释放成功”日志判定。
- 拔插、重新启动后可重新识别；未适配或身份含糊的设备不接管。模拟测试与实机验证分别记录。
