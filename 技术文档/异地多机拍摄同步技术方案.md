# 异地多机拍摄同步技术方案

## 交付范围

本方案面向任意数量的拍摄机器与一个办公室归档角色。演示采用 A/B/C 三台现场节点和办公室 O 节点；所有现场节点只收到相机 JPG，只有办公室节点连接最终备份路径与资产归档。办公室角色可分配给任一已授权设备，与 A/B/C/O 字母无绑定关系，也可以兼任拍摄。第一阶段以独立目录中的真实图片副本、四个真实业务数据库实例和持久 HTTP 中继进行演示；不接管生产程序或生产 NAS。

## 用户看到的行为

- 各机器加入同一共享项目，项目和清单行使用稳定 ID。原有本地清单通过明确的“关联共享项目”操作映射，不依据文件名或 Excel 内容相似度静默合并。
- “拍摄进度 → 全部拍摄”按 `共享项目＋款号＋拍摄类型` 汇总，显示 A/B 来源、拍摄次数、完成时间、冲突状态。一个款号的模特图和细节图分开计算；同一证据重传不增加数量。
- 每个业务日期、每个来源设备自动形成独立任务，例如 `2026-10-20-A.xlsx`、`2026-10-20-B.xlsx`、`2026-10-20-C.xlsx`。各端都能看到这些任务；仅接收资料的办公室不会凭空产生 O 拍摄任务。收到远端任务不切换本机当前拍摄任务、监控目录或模型开关。
- A/B 是管理员分配且项目内唯一的显示别名；设备 UUID 才是身份。同款重拍原有 `SKU-A` 规则独立于机器 A，不能混用；界面标注“机器 A”而非追加款号。
- 拍摄日期来自拍摄事件中的有效带时区时间，按项目 `Asia/Shanghai` 业务时区换日。无有效拍摄时间的记录进入“日期待确认”，不能用接收日期伪装成拍摄日期。旧日期事件在重试、换日和改名后仍归原任务。
- A 断网仍可拍摄、确认并入库。恢复网络后自动补传；B 可在 A 上传后关机的情况下继续下载和写入 NAS。

## 总体架构

```text
A/B/C… 现场业务库/发件箱 ←HTTPS→ 公网中继事件库 ←HTTPS→ 办公室业务库/收件箱
       │                                                 │
  现场只接收相机 JPG                         JPG/RAW 匹配与受控写入队列
                                                         │
                                             最终备份路径 / NAS 原图
```

公网中继常驻在可访问的服务器，客户端只建立出站 HTTPS 连接，不要求 A 公网 IP，不把桌面管理接口或 NAS SMB 暴露到公网。中继只传业务元数据，原片不属于默认传输内容；小型预览可作为独立、有限额的可选功能。

每端继续使用本机 SQLite。禁止用网盘同步或 SMB 共享正在写入的 `.sqlite3/-wal/-shm` 文件。SQLite 官方指出 WAL 需要同一主机的共享内存协作：[WAL](https://sqlite.org/wal.html)、[跨网络使用说明](https://www.sqlite.org/useovernet.html)。NAS 只放媒体文件；业务数据库放节点本地磁盘。

## 身份与事件协议

| 标识 | 范围和作用 |
|---|---|
| workspace_id / project_id | 团队与共享项目，所有请求都进行授权隔离 |
| device_id / device_alias | 永久设备 UUID / 项目内唯一显示名 A、B |
| logical_row_id | 共享清单行身份；无清单时由项目、标准化款号、拍摄类型稳定派生 |
| shot_id / asset_id | 一次拍摄证据 / 永久图片资产身份；重传不重新分配 |
| file_id / original_sha256 | JPG/RAW 各组件的永久身份与首次已确认的内容指纹 |
| event_id / device_seq | `device_id:seq`，同设备事务内递增，唯一约束防重放和冒用 |
| parents | 此次编辑基于的事件版本，可表达因果先后和并发冲突 |
| relay_offset | 中继提交顺序，独立于拍摄时间和客户端时钟 |

事件固定 schema 和字段白名单，包含项目、设备、证据身份、不可变文件身份、原始 EXIF 拍摄身份、视觉复核指纹、带时区拍摄时间、元数据、状态及父版本。现场初始事件只有 JPG 组件，不假设现场知道 RAW 文件名或哈希。办公室匹配后可通过专门授权的绑定更新追加 RAW 组件，已有组件不得删除或改换身份。中继拒绝同一 file_id 或已登记内容指纹被另一资产占用。接收方不执行远端 SQL，不接受远端目标路径；本机路径只保存在本机位置表。

生产接口：`POST /sync/v1/events` 批量上行，`GET /sync/v1/events?after=<offset>&limit=...` 增量下行，`POST /sync/v1/receipts` 报告各节点入库/冲突/写回状态，`GET /sync/v1/snapshot` 提供新设备首轮快照与后续 offset。演示实现前两项及本地持久写回状态，不假称已完成快照压缩和公网部署。

## 持久性与恢复

1. 本地确认与业务事件、发件箱写入同一个本地事务；事务成功即可继续拍摄。
2. 中继鉴权、验证事件签名、来源、父版本及不可变字段后，事件和设备序号在同一事务落库，再返回确认。确认丢失时客户端重传原 event_id，中继返回原 offset。
3. 下行整批事件先进入本地持久收件箱，游标在同一事务推进。尚缺父事件的子事件保留等待，不丢弃也不提前生效。
4. 有序投影到本机 `sku.sqlite3` 中的任务与进度；同事务登记归档投影工作。归档业务库与 Excel 导出是可重建的幂等投影，重启时从事件状态补齐。
5. 多个 WAL 数据库 ATTACH 不声称具有断电时跨库原子提交保证；以单库事件和待投影队列为恢复依据。生产接入须有自动补偿与一致性巡检。
6. 上传确认、下行游标、业务入库、文件写入四种状态分别展示。网络重试使用指数退避及抖动；无数据时降低频率。中继日志保留到所有有效设备确认，并为长期离线设备提供快照恢复。

## 进度合并与冲突规则

- 完成状态由有效拍摄证据集合派生，不互相覆盖整个 Excel 行。相同款号和类型由 A、B 分别拍摄时，汇总显示“来源 A、B / 2 次拍摄”，完成款数只计一次。
- 撤销是指定 shot_id 的新版本，不直接把整款设为“未拍摄”；若 B 还有有效证据，该款保持完成。历史事件保留。
- 因果后继覆盖其已知父版本；晚到的旧事件不能覆盖新事件。重复 event_id 内容相同跳过，内容不同拒绝并记录。
- 同一资产并发修改产生多个版本头，保持上一个共同确认版本、显示冲突、停止自动写文件。管理员选择值或合成新值后，生成引用全部冲突头的解决事件，使两端收敛。
- 演示采用保守的“整条拍摄记录冲突”保护。生产后续可以引入字段级合并，但同字段并发修改仍必须人工解决；不使用“最后接收者获胜”掩盖冲突。
- 删除、撤销和权限变更必须保留 tombstone 与审计；迟到设备不能复活被撤销记录。

## 办公室代所有现场机器写入归档文件

必须明确物理前提：办公室最终备份路径已存在对应 JPG/RAW，或之后经存储卡、文件复制等独立流程到达。只传元数据不能在 NAS 凭空产生原图；没有图片时持久显示“等待图片到达”。下文 B 仅指执行归档角色的示例设备，演示实际为 O。

1. B 订阅项目元数据，立即写入本地元数据业务库；A 是否在线不影响后续处理。
2. 原图位置从 B 授权的归档根目录索引中查找。优先核对可信 AssetId＋FileId 与已登记内容版本；无身份时只允许首次精确内容指纹匹配。
3. 文件名、目录、相机时间可帮助列出人工候选，不单独构成自动写入依据。不同内容同名图、重复候选、不相符的嵌入身份全部停止并报告。
4. 文件写入任务独立持久，记录 event/head、目标组件、expected_sha、字段、目标元数据版本及写后摘要。目录未挂载或文件未到达保持等待；重启继续。
5. 同一共享归档根指定一个写入节点。生产由中继签发限时租约与递增 fencing token，并由单一 NAS 写入网关核验 token；仅客户端租约不足以阻止旧进程写文件，不能让两台离线程序同时直写同一 NAS。演示按配置授予 O 归档角色，A/B/C 均不配置 NAS；角色判断不依据机器字母。
6. 使用现有 `MetadataWriter` 生成、读回并验证字段，提交前复核文件摘要；JPG 校验像素不变，RAW 默认独立 XMP 侧车，保留原 RAW 字节。侧车已有其他文件身份时拒绝。
7. 写入与数据库不能组成分布式原子事务：先持久保存预期结果和写入 journal，再提交文件；崩溃恢复比较 before/after 摘要及 XMP 标记。已写成功则补记完成，外部修改则复核，不盲目重写。
8. 元数据来源、原始机器及事件版本保存在审计与任务表；演示通过现有 XMP 的资产/文件/项目/区间字段关联，不改现有正式 XMP namespace。未来扩展 OriginDevice/SyncEvent 字段须版本化升级。

## 现场只有 JPG 时的 RAW 配对

JPG 的 SHA-256 只标识其自身字节，不能直接与 CR3 的 SHA-256 比较。真实样片 `XSY_5433.JPG / XSY_5433.CR3` 的相机 ImageUniqueID 也不同，不能假设相机的这个字段跨格式通用。永久 AssetId 是软件确认绑定后的业务身份，不是给尚未见过的 RAW 凭空补出的证明。

1. 现场读取 JPG 的相机型号、有效机身序列号、原始拍摄时间、子秒、可用原始文件编号与相机标识，形成版本化 capture_identity；同时发送 JPG 内容 SHA-256 与小型视觉复核指纹。保留原始 JPG 内容身份，之后自身元数据写入导致字节改变时登记新内容版本。
2. 办公室只在授权的最终归档路径建立 RAW 本地索引，读取同类拍摄身份。RAW 可以改名、换盘符或晚到，现场不需要提供 RAW 路径、哈希或文件名。
3. 自动候选必须相机型号和原始拍摄秒一致，已有序列号/子秒不能矛盾，并具备共享有效机身序列号或确实通用的图像唯一 ID。有序列号时还要同子秒、文件编号或原始文件身份等证据；缺机身身份的仅同秒同名候选转复核。
4. 对候选再从 RAW 提取内嵌 JPEG 预览，与现场 JPG 的 `dhash256-v1` 做视觉复核。演示采用保守的汉明距离不超过 8/256、画幅比例差不超过 2% 的门槛。真实样片正确 RAW 为 3/256，另一张真实 RAW 为 140/256。该感知指纹不是唯一身份，不能单独匹配或代替相机身份；改图、裁切、预览缺失或格式不支持时进入复核。门槛不能从少量样片推广为所有相机的精度保证。
5. 必须双向唯一：一条 JPG 证据只有一个可靠 RAW 候选，一个 RAW 也只能对应一条拍摄资产。多个副本或多个来源证据冲突时停止，不随便选择得分最高的一张。
6. 办公室生成受角色限制的 RAW 绑定事件，追加 RAW FileId/内容摘要/配对证据，保留原拍摄机器来源并回传全部节点；不增加拍摄次数。中继确认绑定后才允许写 RAW 侧车。
7. 元数据先到时持久等待；RAW 后到、办公室重启或现场关机后仍可续接。已绑定其他资产、外部修改、同秒连拍不同子秒、同型号不同机身、同名不同照片全部不能静默覆盖。
8. 本轮对真实 CR3 与其内嵌预览执行验证。其他厂商 RAW 格式须扩展解码与样片矩阵后开放自动绑定，不能把 CR3 验证结论当成全格式保证。

## 搜索性能：沿用已验证经验并隔离慢路径

本节以任务 162、163 的最终实现及避坑记录为准，不能引用任务 159 的旧同词缓存结果替代当前版本性能。

- 业务事件、进度与索引脏队列持久保存，按受影响 entity/款号/拍摄类型增量更新；不在每次入库后扫描全部事件、清空重建全部进度或全量刷新大库。演示使用反向索引维护受影响聚合，证据摘要有数量上限。
- 检索投影先发布，RAW 配对、ExifTool、NAS 写回、Excel 导出与预览解码独立排队。工作簿通过持久导出队列后台生成，不阻塞每次搜索或同步提交。
- 正式接入复用任务 162 的 `quick_file_index` 独立持久索引及 RAM 镜像机制，新增同步资料通过现有 dirty 队列按主键发布；不在快速查询返回前同步调用主库缩略图补全或探测 NAS 文件。
- 演示实现独立 SQLite B-tree＋FTS5 trigram 增量投影，先验证离线元数据也可快速检索，不直接修改生产检索引擎。精确/前缀查询走组合索引，包含查询走 FTS；限定返回量，使用键集分页，不做全库 COUNT、深 OFFSET、`%LIKE%` 扫描或全命中集临时排序。
- 查询不取得拍摄服务锁、元数据写入器锁、缓存收缩锁；不调用模型、不读取原图，不与预览回写访问记账串行。高频同步状态通过快照展示，不逐次扫大业务库。
- 保留 generation、稳定游标、范围和来源，更新后失效旧结果快照；前端换词取消旧请求，不让 90ms 中断后从头无限重查；索引未准备好应显示状态，不能伪报零命中。生产内存镜像失败可回退已提交磁盘索引，不能阻塞启动。
- 元数据写回改变文件摘要时按原任务 163 的主键和版本关联更新，避免写回触发 OCR/索引反复自我失效；远端已确认 SKU 不重跑模型。
- 验收分为实际同步资料即时命中、10 万条模拟规模、不同词首查、同词复查、并发增量与写入器锁占用。记录实际行数、P50/P95/最大值、EXPLAIN 与首次入库到 HTTP 可见耗时。演示目标为直接查询 P95 <50ms、HTTP P95 <150ms；这些是本机隔离验收门槛，不等同于生产 53 万条全库或 UI 端到端保证。上线前须按任务 162 的真实全库/HTTP/浏览器方式复验。

## 与现有程序的接入点

- 新服务建议拆为 `collaboration_identity`、`sync_outbox`、`sync_transport`、`sync_projection`、`sync_conflicts` 和 `archive_write_gateway`，不扩展旧备份合并为逐条实时同步。
- `SkuService` 确认/修正/撤销入口在原事务追加事件；沿用 `sku_rows/projects` 展示投影，同时增加机器来源与汇总页，接收远端事件不启动本机 OCR 或多维模型。
- `sku_metadata_backup` 继续负责迁移备份，旧手动导入不冒充协作同步；已有项目须显式建立映射。
- `AssetArchive` 的写入队列和 `MetadataWriter` 复用既有字段及原片保护，远端路径不进入写入目标。`AssetCatalog` 负责本机/NAS 位置发现，离线远端资产以“元数据已到 / 原图未到”展示。
- 日期任务表增加机器来源、共享项目 ID、拍摄类型、拍摄证据和归档状态列；手动原 Excel 保留原格式和图像，只更新软件工作副本。
- 接收事件需要触发进度缓存失效、检索索引更新及界面增量通知；不改变当前选中的本机任务。

## 公网部署与访问控制

部署公网 HTTPS 中继，正式服务强制 TLS；每台设备独立、可吊销凭据和项目范围授权。演示用本机随机凭据及 HMAC 验证来源，仅允许回环 HTTP，非回环地址必须 HTTPS；凭据不写入报告或 Git。生产还需凭据加密存储、轮换、速率/体积限制、备份恢复、日志脱敏、服务健康检查和租约网关。

原有 `127.0.0.1:8779` 管理端、局域网 8780 工作台和 8770 参考库保持用途。新增公网同步接口独立，不能放开现有只读边界。HTTP 条件更新可参考 [RFC 9110 If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)；事件 parents 为本方案实际因果依据。

## 分阶段上线和验收

1. 本轮：隔离演示、真实图片副本写回、自动化边界测试、HTML 可视化报告。
2. 正式客户端接入：业务事务发件箱、共享项目关联 UI、全部拍摄与机器来源、日期任务表、持久状态及缓存失效；兼容旧库和离线使用。
3. 中继部署：确定服务域名/服务器、TLS、账号与设备权限、备份、快照、日志保留和告警；在 A/B 两台实体机测试断网及长期离线。
4. NAS 网关：租约 fencing、权限目录、真实 NAS 断连/重挂载、JPG/RAW/XMP、外部软件同时编辑与崩溃恢复；先影子匹配，再小项目启用写入。

验收不是证明所有故障下绝对不会混乱，而是逐项证明已覆盖场景不会静默覆盖，并对未覆盖的公网、NAS、断电和大规模负载明确保留上线门槛。
