# 内置多模态与 OCR：部署与真实样片验证

## 新电脑自动部署

运行约 12.6 MB 的“末帧选片安装器.exe”，安装阶段通过魔搭校验下载全部模型、CPU/CUDA 运行时和必要依赖；安装器不包含这些大文件，不依赖开发机目录，也无需手动执行 Python。新资料默认启用内置模型，已有用户选用保持。

已安装用户选择内置模式后，首次点击任意 OCR／视觉识别操作会自动准备相关模型，并在页面显示进度；准备结束继续原操作。后台任务也从统一推理入口补齐。失败保留断点，可重试后再次识别。配置存于资料目录 `components/local-models.json`，模型与原照片分开，卸载保留。

固定组件定义见 `选片助手/component-manifest.json`，统一准备逻辑为 `component_setup.py`。下文脚本部署方法保留供开发与诊断使用。

验证日期：2026-10-21。结论：可以直接集成到软件，现已实现软件管理的独立推理运行时，不需要安装、启动或连接 LM Studio。外部 API 配置仍可保存和切换。

## 已部署的结构

桌面工作台 → 原解析队列与模型卡片 → `local` 内置通道 → 软件启动的官方 llama.cpp CUDA 子进程 → 本地 GGUF 权重。

这属于应用内置推理功能，运行时以随软件部署的子进程运行。模型进程仅监听随机回环端口，使用每次启动生成的鉴权密钥；密钥不写入卡片或启动命令。它不是用户另行维护的模型服务器。按需加载、同模型复用、不同模型串行卸载切换；请求期间不允许其他队列卸载正在使用的模型。关闭引擎正常释放，Windows Job Object 用于引擎异常退出时收回模型进程。不会终止其他软件的模型服务。

本机部署目录：

- 运行时：`.runtime/llama.cpp/`，官方 llama.cpp `b11773`，Windows x64 CUDA 12.4。
- Qwen：`.runtime/models/qwen/`，`Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf` 和 Q8 视觉投影，共 5,536,191,744 字节。
- OCR：`.runtime/models/ocr/`，`GLM-OCR-f16.gguf` 和 Q8 视觉投影，共 2,270,175,296 字节。
- 配置：`.runtime/local-inference/local-models.json`，按模型 ID 指定运行时和权重路径。
- 新程序：`dist/末帧选片-内置模型/`；运行 `启动内置模型版.cmd`。与正在运行的旧版演示分目录，避免覆盖被占用的引擎文件。

模型文件均由国内 ModelScope 下载，下载器逐文件检查仓库给出的 SHA-256，清单保存在各模型目录的 `download-manifest.json`。独立运行时来自官方 GitHub Release，并核对固定 SHA-256；没有使用 LM Studio 的程序文件。权重约 7.27 GiB，不纳入 Git 或普通更新包。

## 推荐使用方式

GLM-OCR 用于 SKU 文字读取；Qwen 用于资产属性解析。Qwen 在这张手写标签上存在字符错误和错误自信，不能作为款号自动确认依据。GLM 没有提供校准置信度，软件保持 `unscored=true`、`confidence=0`，自动对账继续进入复核，不为了通过测试伪造分数或自动写入。

在“设置 → 模型配置”打开“使用内置模型”，软件自动选用 GLM-OCR 与 Qwen 并绑定多模态用途，同时锁定所有卡片及配置操作；鼠标、键盘和直接接口请求均不能修改选择。关闭开关后恢复此前选用及用途绑定，再点击卡片切换外部 API。开关重启后保持，缺少内置卡片时自动补充；旧配置默认关闭，保留原行为。

内置通道不填写 URL 和 API 密钥。已有 Chat、Responses、OCR JSON、PaddleOCR 外部配置保留。加载与停止由软件负责，不需要单独打开服务窗口。开启时已有外部队列在后续请求前检查模式，已发出的请求不会被中断。

模型默认上下文 8192、单模型单路执行，图像最多 4096 token。显存不足时会减少 GPU 层数并将视觉投影放到 CPU；这一降级路径尚未做性能验收，不承诺仍有上述速度。普通队列的“2 张”对外部 API 继续有效，内置模型内部串行执行以控制显存。

## 可复现命令

在项目根目录运行：

```powershell
python -X utf8 选片助手/download_local_models.py
python -X utf8 选片助手/setup_local_inference.py --download-runtime --register
python -X utf8 选片助手/benchmark_local_models.py --label build/ocr-validation/label.jpg --products build/local-model-validation/XSY_5194.jpg build/local-model-validation/XSY_5234.jpg build/local-model-validation/XSY_5294.jpg build/local-model-validation/XSY_5378.jpg build/local-model-validation/XSY_5458.jpg --expected-code LCJ81166
```

`--expected-code` 只用于输出后比对，不进入提示词。添加卡片不会覆盖外部卡片或自动更换原选用。离线推理不需要联网；首次下载运行时和模型需要联网。当前配置记录本机绝对路径，移到另一电脑需要重新登记路径；发布便携模型包时应随包重写配置并保留 llama.cpp、CUDA 运行库和模型的许可证。

原始 benchmark、运行日志、隔离的打包验证与截图位于 `build/local-model-validation/`。该目录和模型权重均被 Git 忽略。

15 项相关回归通过。独立发行目录的打包引擎经真实浏览器操作完成添加两类内置卡片、绑定 Qwen 资产模型、选用 GLM、点击 OCR 并填入 `LCJ81166`，约 4.281 秒；无页面脚本错误，原图与星级保持，外部卡片保留，关闭后引擎退出。结果见 `build/local-model-validation/packaged-final/result.json`，截图已检查。该验收覆盖打包引擎及其界面，未声称操作了 Tauri 原生窗口。

随后内置开关新增验证：17 项相关回归通过；更新后的打包引擎验证了开启锁定、直接接口不能绕过、刷新保持、关闭恢复原外部选择，1440/375px 无页面横向溢出；开启状态真实 OCR 3.406 秒正确读出 `LCJ81166`。结果见 `build/local-model-validation/switch-packaged/result.json`。
