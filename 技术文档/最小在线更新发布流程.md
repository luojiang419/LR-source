# 最小在线更新发布流程

更新源沿用 `jiangjiang419/framekeep-updates`。客户端实际读取 `public/latest.json`；上传到其它目录、仅更新 README 或 `minimal-latest.json` 都不能让旧客户端发现更新。

## 正式编译顺序

1. 检查工作树并保护已有改动，读取当前任务记录和公网已签名版本。
2. 执行 `python -X utf8 更新系统/scripts/release.py prepare`。工具取本机与公网较高的 SemVer 后递增补丁位，发布号取当前 UTC 或上一发布号加一秒中的较大值；同步 `update-config.json`、Cargo.toml、Cargo.lock 中本项目条目、tauri.conf.json 和 SharedTheme.cs。每次正式发布只执行一次，普通调试不执行。
3. 执行 `python -X utf8 更新系统/scripts/build_tools.py`，再执行 `python -X utf8 选片助手/build_release.py --stage-only`。后者重新编译引擎、桌面程序并暂存到 `build/tauri-release/SHIYING 数字资产`。
4. 使用 `build_minimal_update.py --base 基线快照目录 --base 历史兼容快照目录 --stage 暂存目录 --output 新输出目录 --notes 本次说明` 生成最小包。至少提供一份完整基线；历史最小快照按版本顺序合并到完整基线。工具检查三处配置、桌面 PE 版本及冻结模块与当前源码一致，拒绝用旧二进制改清单冒充新版本。
5. 运行更新专项和必要的功能回归；在隔离目录验证历史基线实际冻结 worker 覆盖、失败回滚、资料与运行时保持及下一次更新环境可用。将当前 `version`、`releaseId`、`package_sha256`、`status: passed` 和详细结果保存为验证 JSON。
6. 执行 `python -X utf8 更新系统/scripts/publish_minimal_update.py --snapshot 输出目录 --verification 验证JSON`。工具先上传不可变最小程序包与入口并完整匿名回读，再维护新装基线，最后激活 `public/latest.json`；版本未递增、验收身份不匹配或远端出现其它新版本时停止激活。
7. 使用旧版真实 `UpdateClient` 连接公网，确认 `available/downloaded`、版本及实际包哈希；新版本应报告已最新。记录提交及发布状态，保留完整基线和最小快照，清理本轮已确认无用的运行副本。

## 最小包与新装

- 最小包复用 OCR、模型、DLL、PYD、Python 标准库及 FFmpeg/CUDA，不因 ZIP 时间戳变化重发标准库。没有业务源码变化的卸载入口也复用原制品，避免重复携带内嵌更新环境。
- 旧运行库仅接受已签名历史基线中登记的大小和 SHA-256 变体；复制后必须与源字节一致，未知或损坏内容仍拒绝。兼容记录只用于旧环境复用，不能取消完整性检查。
- `public/install-latest.json` 单独保存完整基线。新装引导器复用既有已发布基础安装器，不上传第二份 OCR 或运行库；安装基础版后软件会提示当前最小更新。不能让空目录直接安装差异包。
- `manifest.json`、`envelope.json`、基础 `SHIYING-Windows-x64.zip`、`SHIYING-Setup.exe` 及必要的 `native-sources.json` 是后续差分依据，仍在使用时保留；源码签名私钥不得进入发行包。
