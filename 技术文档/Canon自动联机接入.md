# Canon 自动联机接入

## 新电脑如何使用

在 EOS Utility 的「链接软件 → 记录…」中选择当前安装的「末帧选片.exe」。末帧检测到 EOS 已选中本软件后，自动读取 EOS 的 `SaveFolder`，递归监控存储目录及即时拍摄／日期子目录；新建日期目录无需再次添加。重启后同样自动跟随，保留 EOS 当前路径和命名规则，历史末帧目录只用于手动回填。未关联时保持待命，不主动改写 EOS 设置或弹窗。

EOS Utility 继续负责相机连接和照片传输；末帧接收完整路径并接入现有监控、RAW/JPG 合并及预览缓存。自动跟随以 EOS 保存根目录作为会话，照片通知来自其子目录时不重建监控，能继续发现新建的同级拍摄目录。如果 EOS 首选项尚未落盘，可信桌面照片通知可先接入实际照片目录，落盘后跟随保存根目录。通知不反复唤醒或抢占窗口焦点。

EOS 带照片路径拉起末帧时，本次运行的首个有效桌面通知会开始联机，并从资产检索等页面返回现场拍摄、载入拍摄目录。历史关闭状态只限制普通启动时的后台探测，不拦截这次明确的照片接入；若本次运行已手动关闭联机、停止监控或改用手动目录，后续通知仍保持暂停。每个通知只处理一次，普通索引刷新不会切换工作页，弹窗和暂停浏览期间延迟跳转。

自动检测只读取配置。主动点击「跟随 EOS 保存目录」可登记链接并恢复接入；此操作不应用历史末帧目录或命名规则。主动应用新的保存目录才改写对应字段。EOS Utility 3 已运行时，写入操作等待 EOS 关闭，不关闭相机软件，也不把磁盘修改当作 EOS 内存已切换。软件重启后旧待生效保存设置不自行继续应用。

本次启用后，未安装 EOS Utility 时会显示状态，安装后重新检测。当前识别范围是 Windows EOS Utility 3，其他产品／不兼容配置会显示错误并保留原配置，不修改 Canon 二进制、系统注册表或相机固件。

## 控制与恢复

自动跟随时左栏显示「联机拍摄 · 自动跟随」。点击它可打开可选的保存目录弹窗，并填入上次保存位置；启动和刷新不自动弹窗。目录支持本地路径、映射网络驱动器（例如 `Z:\拍摄`）及 UNC 共享（例如 `\\192.168.1.10\照片\拍摄`），需提前连接并具备写入权限；路径显示与资产归档共用盘符／共享名解析，盘符根和共享根不会出现空名称。

应用后设置的是 EOS Utility 的实际保存规则：保留相机原文件名，按照片拍摄日期自动建立 `YYYY-MM-DD` 子文件夹，例如 `\\192.168.1.10\照片\拍摄\2026-10-22\IMG_0001.JPG`。日期与文件名预览仅为示例，末帧不会复制或重命名已有照片。

EOS 未运行时立即合并保存配置并监控所选目录。EOS 已运行时，新选择先暂存，弹窗明确显示“等待生效”；关闭 EOS 后由后台自动应用，再打开 EOS 开始拍摄。不会强制退出 EOS，也不把写入磁盘首选项当作其运行中内存已经切换。关闭自动接入后，EOS 退出时仅恢复仍由末帧接管且未被用户后来修改的字段，包括保存目录和命名规则。

“现场监控”面板提供「Canon EOS 联机接入」开关及「跟随 EOS 保存目录」。

- 已关联时启动自动跟随；历史 enabled=true 不能独自触发主动登记或旧保存设置写回。
- 关闭开关后停止 Canon 自动监控并记住关闭状态，本次运行需重新启用；重启后新的 EOS 照片通知可以开始本次联机。自动跟随的关闭不恢复／改写 EOS 配置；手动应用保存目录的关闭仍按原有字段所有权规则恢复。
- 独立手动监控优先；手动选择监控目录或点击「停止监控」会暂停本次自动接入，点击「跟随 EOS 保存目录」恢复。
- 原有拍摄会话、评级和图片均保留。EOS 更改保存根目录后自动切换；子目录照片通知保持根监控，避免漏掉新建的拍摄子目录。

登记前的链接字段和原配置快照保存在资料目录的 `canon-link/registration-*.json` 与 `*.original.config`。恢复时只恢复由末帧登记且尚未被用户改动的链接字段，不把整个旧配置覆盖回去。

## 实现与边界

- `canon_probe.ps1` 使用 Windows .NET Framework 的只读程序集元数据和版本无关 StrongName 规则计算配置位置，不执行 Canon 类型。计算结果与本机实际 EOS 3.20.21.1 用户配置路径相符。
- `canon_link.py` 检测安装、合并登记字段、备份和恢复、检测 EOS 运行状态，并将已保存目录或图片通知接到 `FolderWatch`。写入前再次检查 EOS 是否运行及原配置是否变化。
- POST `/api/canon/destination` 校验现存绝对目录和写入权限，持久化保存根目录并应用／暂存 EOS 的原文件名和日期规则；GET `/api/canon` 同时返回选定目录和生效状态。未运行桌面登记服务时不能改写 EOS 保存配置。
- Rust 主程序处理首次启动参数和单实例参数，通过资料目录的 `canon-link/inbox/` 原子落盘通知；后台引擎就绪后用实例令牌发送 `/api/desktop/canon`。进程重启前未处理的通知仍然保留，无效通知改为 `.rejected` 以便诊断。
- 已有 `/api/watch` 通过 `source=canon` 标记自动来源；前端在适当时自动进入新会话，仍保留保存队列、暂停跟随及人工评级。
- GET `/api/canon` 提供状态，普通工作台令牌 POST `/api/canon` 管理开关；照片入口另需当前桌面的 `X-Framekeep-Desktop` 实例令牌。
- 非桌面启动不会自动改动 Canon 配置。隔离桌面测试设置 `FRAMEKEEP_CANON_REGISTRATION=0` 只禁用外部登记与目录探测，仍可验证照片通知，不影响实际 EOS 设置。

这不是重新实现相机控制或绕过 EOS Utility。实测覆盖软件通知和本机配置登记；真实相机曝光、传输耗时以及长时间连拍仍应由实际拍摄验证。

## 本轮验证

以下为历史自动接入方案的验证记录；当前已关联自动跟随规则见 [082-参考目录批量选择与EOS自动跟随](../开发任务/082-参考目录批量选择与EOS自动跟随.md)，更新了任务 072 的启动门控。

50 项验证分批通过：44 项 Python／浏览器功能回归、5 项 Rust 单元测试，以及 1 项最终发行桌面的 Windows 单实例集成。

- 新用户无配置时创建登记配置，并由实际 .NET `ConfigurationManager` 读取；中文／空格路径、安装位置变更、已有 EOS 运行时延期、原设置恢复和用户后续选择保护。
- 无需输入监控目录即可进入照片会话；同目录不重置 generation，换目录旧四星评级保留；四主题界面与关闭自动接入检查通过。
- 实际打包桌面首次图片参数只处理一次，后续启动经过 Windows 单实例 IPC 也只处理一次；前台窗口句柄不变，新目录自动接入，3 张 JPG 共生成 6 份缓存，队列清空。
- 本机真实 EOS 配置已由程序自动登记为当前 `dist/末帧选片/末帧选片.exe`，.NET 读取确认 `IsLinkedAppOther=True`、JPG/CR3 通知为 True；41 项其他首选项的值与备份一致。
- 新版桌面 PID 58192、引擎 PID 2860，健康 `busy=false`；Tauri 首屏 1859ms。此记录是进程／HTTP／原生就绪指标；四主题截图来自隔离浏览器，不冒充原生截图。

日志、截图、`native-result.json`、`registration-preservation.json` 等证据在忽略目录 `build/canon-link-acceptance/`。发布保持版本 1.0.0；用户在另一任务完成的导航状态灯和启动修复一并保留。
