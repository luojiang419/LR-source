# 罗技无线鼠标适配与验收

本次沿用[无线鼠标驱动改造与创意功能开发教程](无线鼠标驱动改造与创意功能开发教程.md)的 A 路线，为罗技无线接收器新增独立控制端适配，保留原接收器配置。不是重新编译或签名新的内核驱动；没有修改接收器固件和 Windows 自带驱动。

## 设备证据

2026-10-20 在本机 Windows 10 x64 19045 实测：

| 状态 | 观察 |
| --- | --- |
| 初始连接 | 罗技鼠标 `HID\VID_046D&PID_C534&MI_01&COL01\8&21BD65C4&0&0000` |
| 用户拔出 | `046D:C534` 全部接口消失，另一只 `VID_09DA&PID_8736` 鼠标仍在线 |
| 用户插回 | 原鼠标集合恢复，PnP Status=OK |
| 驱动枚举 | 当次槽位 `driver:13`，硬件 ID `HID\VID_046D&PID_C534&REV_5101&MI_01&Col01` |

型号未知，不能仅由接收器 PID 推断具体鼠标型号。罗技配置只匹配 `MI_01/COL01`，不匹配其键盘、媒体和供应商集合；原 `367B:1919` 配置继续保留。槽位动态枚举，不写死为 13。硬件修订 REV 可忽略，但 MI/COL 必须保留。

REA `inspect-with-objdump` 使用本机 `C:\Program Files\LLVM\bin\llvm-objdump.exe`，完整输出记录在忽略目录 `build/logitech-adapter/rea-*.json`。REA 通用适配器的 provider 字段叫 `gnu.objdump`，实际执行程序为 LLVM；本次取得的是静态汇编，不是 Ghidra 伪代码或运行轨迹。

在驱动映像地址 `0x1622a` 开始的 Device Control 分派中，依次减去 `0x222004`、`0x0c`、`0x30`、`0x40`、`0x80`，最后比较 `0x100`。其中当前客户端使用的分支如下：

| 请求 | 处理地址 | 本次核对 |
| --- | --- | --- |
| `0x222010` SET_FILTER | `0x11310` | `0x11330` 检查输入至少 2 字节，随后读取 USHORT |
| `0x222040` SET_EVENT | `0x113c8` | 分派指向事件注册处理路径 |
| `0x222100` READ | `0x11724` | 分派指向输入队列读取路径 |
| `0x222200` HARDWARE_ID | `0x118bc` | 分派指向硬件身份路径；实际枚举成功 |

沿用已核实的四项 IOCTL 和 24 字节 `MOUSE_INPUT_DATA`，未增加 GET_FILTER/GET_PRECEDENCE；没有因兼容新设备而放宽驱动哈希。上游安装器执行 `/install` 成功，安装文件哈希再次匹配。安装器提示重启；本次用户拔插罗技接收器后即可枚举、接管并收到输入，未重启整机，也没有重载另一只鼠标。其他机器是否需要重启应由实际加载结果判断。

## 使用与恢复

在“鼠标遥控”选择“罗技无线鼠标 · C534”，启用后左键加星；右键减星和滚轮浏览仍各自按开关控制。新旧配置可同时列出，按选择启用；同一配置多只接收器仍拒绝含糊接管。

页面连同槽号提交配置及硬件身份。后端重枚举，并在句柄打开后再次核对，拒绝槽位被其他型号或集合复用。新旧配置共用原排他锁，兼容旧版 LR。设备错误使输入线程退出后，重新插入并点击“刷新设备”可重建控制端；需要手动再次启用。

停止遥控、`Ctrl+Alt+F11`、页面失联 10 秒和程序正常关闭沿用原恢复机制。若没有正在持有接收器锁的 LR 程序，可从项目根目录独立诊断：

```powershell
python -X utf8 选片助手/mouse_probe.py
python -X utf8 选片助手/mouse_probe.py --capture --seconds 30 --output build/mouse-probe.json
python -X utf8 选片助手/mouse_probe.py --release
```

采集不写照片，默认 30 秒，允许 1—120 秒，到时或恢复快捷键释放。`--release` 仅对确认唯一且身份复核通过的所选配置发送过滤归零请求，不操作其他鼠标。

## 实物与自动验证

45 秒限时采集收到 **920 包、5 次左键、4 次右键、向下 23 格、向上 16 格**；结果见 `build/logitech-adapter/hardware-capture.json`。程序记录已释放后，用户反馈鼠标仍不能移动；再次独立向同一罗技设备发送 `SET_FILTER=0`、解除事件并关闭句柄后，用户确认“已恢复移动”。该反馈无法单凭日志确定是结束反馈时间差还是原驱动停用行为，不把它写成已定位根因或已修复的结论。新版最终启停验收另记任务文档。

随后用真实发行包、独立临时数据和三张合成照片进行40秒实物联动，收到 **671 包、6 次左键**，记录19次照片/星级状态变化，观察到加星、减星及双向浏览。通过页面正常停止后，用户确认“能正常移动”；页面无脚本错误。此轮结果见 `build/logitech-adapter/packaged-hardware/result.json`。未用真实照片做标星测试。

全量165项测试执行133.696秒，157项通过；8项因本机缺少公开R6 II RAW样片跳过。新增16项专项覆盖新旧共存、精确匹配、身份变化、选项、断连释放与刷新重建，并用真实 Chrome 加临时 HTTP 服务检查选择、启停及无脚本错误。最终复核加强了身份不符时的拒绝路径，避免清理时向错误设备发送filter0，随后重跑鼠标专项并重建引擎。最终交付状态见[当前开发任务](../开发任务/022-罗技无线鼠标独立适配.md)。
