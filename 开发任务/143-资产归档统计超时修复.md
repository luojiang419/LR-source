## 定位与实现

- 真实运行线程栈在进度请求中观察到元数据全库统计以及 `PreviewCache.connect` 设置 `synchronous` 等待；单独只读统计约 2 秒，运行中 HTTP 可超过 20 秒。将 HTTP 改为单任务后台快照，首次明确“正在读取”，保留上次成功值，错误后自动恢复；预览统计使用只读连接及独立测速锁，避免等待写连接配置和队列领取锁。
- 全目录重扫会递增 `scan_epoch`，但尚未走到的旧素材仍在线。原队列却据此取消有效持久任务；移除这一误判，按在线/移除/排除目录判断。历史 cancelled 项在重新发现时恢复入队，完成缓存仍复用，损坏文件的重试上限保留。
- 新增独立的归档 OCR 配置和 UI 复选框；旧配置继续跟随现场 OCR，明确设置后不依赖拍摄会话。按源文件和模型版本持久化 OCR→视觉→搜索入库断点，沿用已有阶段互斥。
- 前端将请求超时解释为进度暂不可用，成功刷新后自动清除旧错误，避免永久残留 `signal timed out`。开关保存期间保留用户选择，修复异步重绘回弹。
- 证据目录 `build/archive-state-timeout/`：只读诊断、线程栈、回归日志、真实例图的 `real-pipeline/result.json`。模型配置副本和产物仅保存在忽略目录。

## 2026-10-30：缩略图优先与手动模型阶段

- `VisionScheduler` 统一限制缩略图解码、OCR 和视觉推理：已有模型请求先收尾，解码才能进入；缓存队列未完成时禁止新的模型请求。API 协议的独立并发也不能绕过阶段互斥，同一阶段保留既有硬件并发设置。
- `PreviewWarmer` 用轻量队列计数与实际目录发现状态维护阶段门槛；解码失败需先重试/移除，已移除目录和无关现场旧失败不会永久阻挡归档。`/api/catalog/decode` 提供正式启动/继续与失败重试，同时停止归档、现场 OCR 和多模态自动任务。
- 软件启动只恢复缓存，模型不自动恢复运行。归档增加独立的“手动启动 OCR”“手动启动视觉解析”；OCR 完成不会自动进入视觉，视觉阶段可复用已保存 OCR 文本。图片与视频均保留断点；视频切换阶段时保留同一采样计划的 OCR，独立 OCR 不抹掉已保存的视觉结果。
