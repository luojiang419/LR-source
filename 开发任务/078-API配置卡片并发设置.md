- 新增／编辑 API 配置显示最大并发数，范围 1–64，默认 4，卡片展示实际配置；保存及重启保持，旧 API 配置兼容默认 4，本机 local 固定 1。
- 同一卡片的 OCR、二星、全自动及多模态共用实际请求上限；不同卡片独立；提高并发后普通 API 批量任务可填满配置容量，不再固定为 1 或 2 路。

## 实现

- `model_providers.py` 保存严格整数并发数，1–64，默认 API=4、local=1；旧卡片缺省兼容，编辑未传此字段保留原值，非法值不部分保存，密钥留空沿用原加密值。
- `provider_concurrency.py` 为每个卡片 ID 统一管理在途请求，OCR、二星、多模态与连接测试共用容量，不同卡片独立。普通等待 FIFO，二星按优先级和最新事件取得空位；取消／暂停／关闭时校验等待任务。调高唤醒等待者，调低不打断已有请求，后续须等到新上限内。
- `label_concurrency.py` 为普通 API OCR、全自动和二星分配有界工作线程，优先取二星，普通队列填满卡片容量；`asset_analysis.py` 按实际排队卡片容量扩展 API 工作线程，API 不再受旧的普通本机 1–2 路限制，local 仍保留资源保护。
- `sku_service.py` 给普通 OCR 任务补充请求代次，取消重试后旧响应不会覆盖新结果。对并发星级 XMP 写入，按已登记的元数据版本链校验实际指纹，允许内容未变的管理写入；真正像素替换仍拒绝，中文路径使用既有 ensure_ascii=False 指纹规则。
- `assistant-settings.js` 添加／编辑时显示“最大并发数”，卡片显示保存值；协议切到 local 固定为 1，切回 API 保留草稿。`asset-analysis.js` 将旧并发控件明确为“本机模型并发”，提示 API 在卡片设置，避免显示 4/2 这种误导上限。
- 资产批次快照不把并发数算入识别输入，调整容量不会重复解析相同图片。README 和避坑指南已同步当前语义。
