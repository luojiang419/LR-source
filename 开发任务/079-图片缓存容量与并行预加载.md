- 设置 → 预览显示可保存 1–256 GB 整数图片缓存上限，默认沿用 10 GB；重启保持，缩小后按 LRU 淘汰可信缓存，监控与归档合计受限。

## 新增目标

- 设置缓存根目录，提供后台迁移，迁移校验完成后切换，失败保留原目录。
- 提供含数据库与缩略图的可校验备份、导入/导出；不执行外部 SQL，不打包照片或密钥。
- 按照片完整内容 SHA-256 匹配可移植缓存，不依赖盘符、目录名或文件名；重复导入幂等，不接受仅同名/同大小的弱匹配。首次匹配需要读取指纹，但不需要重新解码图片。

## 第二阶段实现

- `cache_storage.py`：位置指针在资料目录持久保存，缓存根目录使用专用标记；在线迁移先复制校验，再用生成读写屏障收尾并备份 SQLite，原子切换路径。保留源副本并登记清理清单，旧图清理按句柄验证 SHA-256，不删除未知文件或业务数据库。缓存设备离线不覆盖原指针，明确提示临时本机缓存。
- 可移植身份为完整文件内容 SHA-256 的组合，盘符、路径及文件名不进入身份；尺寸、方向、解码与 recipe 版本同时匹配。首次跨路径需读取完整内容，之后缓存本机文件版本摘要；源文件变化期间拒绝登记错误指纹。旧缓存补指纹不重解码。
- 备份 v2 使用 ZIP64 + 独立 JPEG + 每 1024 份预览一个 JSON 索引块，每块与总清单校验 SHA-256。导入使用本机自建临时 SQLite 做流式校验、排序、去重；兼容 v1 清单，不执行备份提供的 SQL。按额度选择最近使用条目，未知同名文件保留并报告冲突，重复导入及先归档后导入可直接复用已有内容。
- 缓存目录自动排除于选片扫描、监控与归档，避免缓存递归入库。迁移后任务灯读取当前缓存位置，缓存管理纳入关闭/更新忙碌检查；导入完成后重试页面未成功加载的预览。
- 设置页加入路径迁移、旧缓存清理、备份导入导出与指纹准备；Tauri 增加专用文件夹/备份文件选择器。业务照片、评级、SKU/OCR 数据库仍由原业务备份负责。

## 百万规模加固与实测

- `cache_totals` 与 `portable_names` 用同事务触发器维护数量、待处理、失败、迁移指纹覆盖及发布序号；设置与任务灯不再反复 COUNT 全表。SQLite UPSERT 对触发器冲突策略的影响已修正并覆盖别名重复绑定测试。
- 排队按 128 条提交；工作线程明确使用 `pending_active_order` 部分索引，已失败任务不再参与候选扫描。LRU 用 `(accessed,name)`，领取任务和淘汰排序均无临时 B-tree。
- 启动每次最多核对 256 份登记图，其余访问时校验；缩小容量后台每批最多 16 份，失败保留原上限，可重启接续目标。
- 启动不重复构建再删除旧 LRU 索引；用量维护表只在首次缺失时聚合初始化，避免每次启动又扫描百万元数据。移除已被部分索引取代的两份旧队列索引，减少写放大。
- 迁移不在内存保留百万份清单，使用私有 SQLite；初拷按名字游标每批 256 条，收尾按发布序号索引只读新增/更新项，SQLite 快照使用 backup API 并 quick_check。旧位置清理复用连接并每 128 条提交。
- RAW 预览优先配对 JPG，再尝试 RAW 内嵌预览；新图片不在首屏等待完整文件 SHA-256，后台补齐；候选采样只用于排除，命中时仍完整 SHA-256 验证。并行同源指纹通过分段锁避免重复大文件读取。
- `benchmark_preview_scale.py --rows 1000000` 实际建 100 万预览索引与 100 万持久队列项：造索引 163.26 s、生产排队 193.62 s、首批 512 条元数据读取 10 ms，状态 P95 5.471 ms、真实缓存命中 P95 18.415 ms、领取 P95 26.080 ms、全失败空队列 P95 2.036 ms、受限重启 0.720 s。索引 759644160 字节，RSS 34.49 MB/峰值 39.01 MB/增量 4.02 MB。数据造于临时目录，结束自动释放；结果保留 `build/cache-scale/result.json`。
- 测试仅有 64 张真实小 JPEG，热缓存 Windows 本机；不代表百万原片解码或 NAS 冷读。全局资产库沿用既有分页接口；现场 `Store.records` 与 `/api/state` 仍按会话装载，不能把百万资料全部塞进单个现场会话。后续应先分离现场流与长期归档，再将会话记录/状态与前端视图分批化。
