## 交付设计

1. 助手配置改为分类卡片（多模态、OCR、文本）。参照 shiying：点击卡片保存该类别选用，编辑/删除不触发选择；配置与选用持久化，API 密钥不回传前端。保留原 Markdown 配置兼容入口。
2. 导入 xlsx 原件副本到本机任务目录，在独立 `sku.sqlite3` 保存项目、工作表、Excel 行、原款号、规范款号、拍摄状态及识别证据。每页在实际活动列末尾添加/复用“拍摄状态”，不改源文件；原图片、公式、样式和其他 ZIP 部件保持。
3. 项目显式绑定当前照片目录，“当前拍摄类型／工作表”为必选项，只匹配和回写所选页，没有跨页自动匹配。识别任务在二星入队时冻结工作表，随后切换拍摄类型不改变旧任务归属。款号相同但出现在不同页是独立对账项。
4. 星级保持二星约 1.2 秒才排队识别，避免快速加到三/五星误触。后台记录照片指纹与原始识别，识别前、提交前复核星级和目录；幂等重试不重复计数。取消二星撤销其贡献，其他有效证据仍可保留已拍状态。
5. 标准化仅处理大小写、全半角、空白和分隔符，不全局把 O 改成 0。先精确匹配，再用带易混字符低代价及相邻转置的编辑距离排序，结合第一/第二候选差距、字符改动量、两路识别一致性判断。低置信、近似候选扎堆、跨页重复均待确认，不直接写“已拍摄”。
6. 确定款号自动更新工作副本状态；待确认提供原文、候选、工作表/行和人工确认/忽略/重试。所有决策留证据，可导出含状态的原格式 Excel。未拍摄样本不伪造为已拍摄。

## 已落地模块

- `选片助手/model_providers.py`：分类配置与显式选用、DPAPI 密钥保护、原 Markdown 兼容迁移。配置保存在本机，不回传密钥；编辑/删除不选用其他模型。
- `sku_vision.py`：Responses、Chat Completions、OCR JSON、PaddleOCR 四类 HTTP 协议。只给模型标签照片，不给款号目录以免按目录猜测；图片文字视为数据，不能变成指令。每次请求 45 秒超时、返回大小限制，失败转可重试记录。
- `sku_match.py`：NFKC/大小写/分隔符标准化；O/0 等仅参与加权距离，禁止全局替换。易混替换 0.2、普通增删改 1、相邻转置 0.7。唯一精确读数须 confidence ≥0.9；模糊自动须两路不同 URL/model 指向同一行、各自 confidence ≥0.9、代价 ≤0.35、相似度 ≥0.97、次名差距 ≥0.06。候选扎堆、多码、同页重复、读数冲突进入复核，相似度不是准确概率。
- `sku_workbook.py`：只定位表头和有效款号行，增量写状态，不重建原文件；第一表 D 列、第二表 C 列。原件副本固定保存，后续可重复生成工作副本。
- `sku_service.py`：独立 `sku.sqlite3`（项目/行/任务/配置）、二星 1.2 秒防抖、照片指纹和页冻结、幂等任务、重启恢复、改星/人工撤销贡献、导出失败不丢结论。未选页不自动识别；界面将点击时的项目和页保存到 `skuMarkers`，迟到鼠标事件按当时上下文归属。
- `server.py`：沿用本机令牌/Origin 保护的模型及 SKU API。产品图接口只接收已知行 ID 与图片序号，由后端定位受管原件，不接收任意路径。
- `演示方案/assistant-settings.js` 和 `sku-reconciliation.js`：配置卡片、常驻拍摄页选择、导入/搜索/筛选/导出、标签图/读数/候选/复核；产品图缩略图与放大。`app.js`、`mouse-remote.js`、`formal.js` 接入星级与异步保存。
- Tauri `save_sku_workbook`：项目 ID 限定 32 位 hex，从受管工作副本经原生另存为对话框复制导出；浏览器使用下载接口。

## 用户反馈：预览图的 #NAME?

用户明确指向提供的表格预览图，而非腾讯文档或本机 Excel。源 B 列为 `_xlfn.DISPIMG("ID_...",1)`，腾讯文档支持，通用 artifact 表格渲染器不支持，源表和状态副本均显示 `#NAME?`。不能据此判断图片丢失。

已实现 `cellimages.xml → r:embed → .rels → xl/media` 索引，直接取原内嵌位图，另支持标准 drawing 锚点。85 行都有图片，映射到 67 个不同媒体部件，原包的 68 个媒体部件（含未引用项）全部保留。已有任务无图片映射时自动补索引，不需要改库表或重导入。

重新生成的只读预览在 `build/sku-acceptance/100拍图10.19-图片兼容预览.html`，两页截图为 `native-preview-0.png`、`native-preview-1.png`，已实际查看首图，产品图片正常显示。它是直接读取原图的兼容预览，不宣称给通用公式计算引擎新增了 DISPIMG 功能。原格式 Excel 导出仍保持原公式；普通 Excel 的兼容性取决于版本，需要通用浮动图版时另做副本，不能暗中转换原件。
