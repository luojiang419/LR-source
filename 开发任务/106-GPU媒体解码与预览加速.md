## 目标与验收

- NVIDIA GPU 上 JPEG（含 RAW 内嵌 JPEG）优先 nvJPEG 解码，GPU 完成带抗锯齿的缩放和方向变换；其他图片与 RAW 完整解码后的像素也接入 GPU 缩放。
- 视频封面与播放优先硬件解码/缩放，播放优先硬件 H.264 编码；不支持的专业编码、驱动错误、无 GPU 与显存不足自动回退，保持暂停/定位/关闭和原片只读。
- 有限并发、复用设备/上下文、缓存命中不重新解码、不强制清空已有缓存；不依赖用户安装 CUDA Toolkit、PyTorch 或 Python。
- 用真实 GPU 执行证明加速路径，验证 8 种 EXIF 方向、色彩/尺寸/缩放误差、失败回退、损坏图片和视频、原文件哈希、视频声音/定位及任务回收。
- 记录 GPU/CPU 实测和各格式限制；完成源码、冻结程序、签名完整安装包的一致性核验。

## 实现与验证边界

- `gpu_media.py`：CUDA Driver API、nvJPEG GPU 混合解码、GPU JPEG 编码、两路可复用解码会话及设备/固定内存缓冲；Lanczos 抗锯齿缩放和八方向变换。普通 NVIDIA GPU 使用 GPU 混合解码，不声称具有数据中心卡的专用 JPEG 硬件。
- `media_engine.py` / `preview_codec.py`：JPEG、RAW 内嵌 JPEG、其他解码后像素和 OCR/旧客户端 JPEG 转码接入；原 RAW 解包、LibRaw 完整处理、非 JPEG 图片解码和 WebP 压缩仍由 CPU 执行。原图、评级、既有缓存和缓存 recipe 保留。
- `gpu_video.py` / `video_playback.py`：标准视频优先 CUDA 解码/缩放/NVENC；专业编码 CPU 解码后上传 GPU。初始硬件失败在发送第一段 MP4 前自动尝试兼容路径，流中断仍由既有错误提示和重新打开处理。极小画面使用 CPU 保留原尺寸。
- 本机 FFmpeg 9.0.2 要求 NVENC API 13.1 / 驱动 610+，现有 580.97 仅支持 13.0；配套固定哈希的 FFmpeg 8.1.1 兼容组件，真实验证 NVENC 成功，不更新系统驱动。CUDA 图像 DLL 来自 NVIDIA PyPI 固定版本和固定 wheel/文件 SHA-256，所有许可证随发行包保留。
- 新增 `/api/gpu-media` 和设置页状态，区分就绪与实际照片处理计数；`FRAMEKEEP_GPU=off` 可诊断关闭。首次初始化由后台预热完成，图片无兼容驱动时保留 CPU。
- 回归暴露并修复图片上传与非阻塞 CUDA 流之间的同步问题；修复预览关闭后的异步焦点恢复/清理竞态，避免重新打开或输入框空格受干扰。

## 最终性能与交付

- 最新图片基准：480px 中位 CPU 133.12 ms / GPU 82.72 ms（1.61 倍）；1800px CPU 208.19 ms / GPU 93.47 ms（2.23 倍）。相对全分辨率 CPU 解码后 Lanczos 缩放，GPU 输出 PSNR 为 44.55 / 51.15 dB；原 CPU draft 路径为 39.91 / 32.77 dB。CPU draft 与 GPU 全尺寸解码并非逐像素相同，不将二者的相互差异直接称作质量下降。测试源文件 SHA-256 不变。
