## 目标与验收

- “昨天”“上个月”按照 Asia/Shanghai 和当前日期计算，优先拍摄时间，无有效拍摄时间回退文件修改时间；自然月不能被最近 30 天替代。
- “女人穿着红色外套”“女人穿着蓝色牛仔裤”根据已解析的主体与服装关系查询，不因红背景、其他人的服装或视频另一帧的属性错误命中。
- 新视觉输出补充主体服装结构；旧结果从已有解析文本建立兼容索引，无法确认的关系不伪造。查询不读原图、不访问模型和 NAS。
- SQLite 使用参数化条件、FTS/业务索引、有界首屏、稳定游标；旧库迁移在后台分批执行，不阻塞应用就绪。
- 正式资产检索与快捷搜索接入同一智能检索入口，呈现理解出的时间/条件；独立新布局演示不得把示例结果冒充生产数据。
- 隔离数据验证语义正反例、日期边界、过期/离线/配对、分页、旧库升级；基准记录真实数据量、冷热响应、EXPLAIN 和与归档首屏的对比。

## 实现

- `选片助手/search_intent.py`：本地时间/同义词/着装条件规划，查询不请求模型。支持昨天、前天、本周/上周、本月/上一自然月、今年/去年、近 N 天、明确日期与范围；Asia/Shanghai；跨年/闰年边界已测。支持人物/颜色/服装、材质/场景/动作等词、同义与口语改写、且/或条件。无法识别的内容保留为元数据关键词，不宣称任意复杂句都能无歧义理解。
- `retrieval_schema.py`：视觉输出增加逐人 `subjects -> clothing`，明确禁止把背景、手持物或别人的衣服混入着装；旧记录字段仍兼容。解析配置版本提升，新解析使用新契约；只有正常开启解析/相应任务时才调用既有模型。
- `smart_index.py`：帧级 FTS、人物服装颜色关系、拍摄时间索引与待更新队列；原始视觉结果仍保存在既有 SQLite 表。写入同事务更新派生索引，替换/删除/指纹变化使旧索引失效。搜索只读取索引与有界摘要，不批量返回完整模型 JSON。
- 旧库通过后台主键游标分批补齐，不在初始化同步重建全库。重启后的 queued 元数据用 payload.stamp 原始指纹确认缓存有效；首次日期补齐期间，修改时间回退只涵盖已检查的主键段，避免把旧拍摄日期误算成昨天。无已缓存元数据的新库不做多余补齐。
- `smart_query.py`：参数化 SQL；日期索引/修改时间索引各取有界页后合并；着装走有序复合关系索引，属性须同一人、同一帧。通用高频词沿时间索引点查，稀疏查询退回 FTS 候选；有总预算和稳定键集游标。结果未取完时返回 has_more，不用全库 COUNT 阻塞首屏。
- 首屏 JOIN 根目录必须保持驱动顺序，日期排序使用驱动表的 item 字段；实际 EXPLAIN 已确认消除了旧日期链路的全量临时排序。
- `asset_intelligence.py` / `server.py`：统一智能检索入口、只读轻量 search-state 与后台线程启动；复用 CatalogSearchRequests 的页面隔离/代次取消和断线检测。旧关键词路线也接入 SQL 取消；百万记录无匹配扫描实测约 29.92ms 取消。
- `演示方案/asset-retrieval.js/css`：正式搜索框默认“智能搜索 / SKU”，显示理解出的日期/着装/关键词；旧库补齐时明确提示不完整；SKU 仍走原有精确/前缀优先路径。初始化不等待整库解析统计，完整统计仅在用户打开设置时读取。
- `桌面程序/src/main.rs`：全局快捷键准备也使用轻量 search-state，避免大库统计拖延搜索窗口就绪。
