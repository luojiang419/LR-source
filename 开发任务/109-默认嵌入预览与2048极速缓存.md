## 目标与验收

- 默认采用相机内嵌/附属 JPEG，符合尺寸时直接复用压缩码流；超过上限仅快速缩到 2048，预览不再编码 WebP。
- 后台每张素材一次领取完成所需小图与 2048 清晰图，复用本次读取结果，不再等待全库小图完成才生成清晰图；前台与后台均限制最大 2048。
- 不默认展开 RAW 像素，不对原图做色彩编辑；保持方向、JPG/RAW 配对、视频封面、标星与 OCR 兼容。
- 用户补充：NAS 不做专属并发限流，按 CPU/内存硬件预算全速处理；已移除中途加入的 NAS 八路限流。
- 旧缓存仅删除已登记且大小/哈希/归属核对通过的生成文件；保留照片、索引、评级、SKU 和配置，以及未登记或被外部替换的文件。旧 4096/WebP 任务转入新策略，历史排除路径不继续处理。
- 做有意义的方向/码流/尺寸/重启/删除边界测试，实际运行新程序检查接口与界面，记录测速范围及限制。

## 实现与检查

- `preview_codec.py` recipe6 改为 JPEG Q85、无 optimize；合适的嵌入 JPEG 只整理头与最小方向 EXIF，压缩扫描数据不变；过大的图片缩到 2048。继续识别历史 JPEG/WebP 以兼容备份，但新预览不编码 WebP。
- `media_engine.py` 共用 `warm_previews`：相机内嵌 JPEG 与方向同次提取，配对时优先内嵌图；每张只读取一次，为 420/480 与 2048 两尺寸复用压缩数据或像素。普通后台不做完整原片指纹，手工迁移指纹和已导入缓存的跨盘复用继续支持。输入捕获记录不被内存 JPEG 数据污染。
- `preview_cache.py` 每次领取完成一张，移除严格按尺寸的全库阶段阻挡；旧 >2048 任务更新为 2048，保留失败次数；加入按请求顺序领取索引。后台记录有效性检查补扫描 epoch、回收站和排除路径。NAS 未加专属限流，现有硬件预算本机为 28 路。
- `asset_catalog.py` 前台首次 RAW 提取也复用本次数据准备 2048，切换尺寸不再重新打开 RAW；视频每张只抽帧一次再做两尺寸。
- `server.py`、`video_preview.py`、`asset-viewer.js` 统一上限 2048，前台不再自动请求 `decode=1` 或升级 4096；GPU 状态/设置文案同步默认 JPEG。
- 安全退役只使用登记生成键、原哈希与 Windows 同句柄验证删除；原片、未知文件、外部替换文件和硬链接均保留。批次生成只持有一层 generation 租约，避免在线迁移与内部再次申请租约互等。

- 真实安装库启动复查先遇到 HTTP 就绪等待：主线程栈在 `SharedRatings._seed_large` 恢复评级的数据库提交中。预览线程改为 `autostart=False`，在初始化后统一 `start()`，避免启动期间已全速竞争磁盘；运行中仍是 28 路，无 NAS 专属限流。最终实际桌面首屏指标 17918ms，健康检查正常。
