## 目标与边界

分析并实际部署 Qwen2.5-VL-7B-Instruct Q4 和 GLM-OCR。沿用现有模型卡片与解析工作流，支持本地与外部 API 同时配置、按用途选用。采用 llama.cpp 本机回环服务作为软件管理的推理子进程，无需把大模型链接进桌面程序。下载来源仅国内镜像，模型和运行日志放忽略目录，不提交权重。

昨日基准来自 `build/ocr-validation/label.jpg`，正确款号 `LCJ81166`，对应真实照片 `XSY_5232`。昨日 GLM-OCR 结果保留在 `manual-real-result.json`，约 2.61 秒；多模态基准无法可靠读取首行。验证原图只读，不触发生产库的自动元数据写入或拍摄对账。

## 中文启动器无法启动修复

- 实际执行 `powershell -NoProfile -ExecutionPolicy Bypass -File 启动内置模型版.ps1` 复现 ParserError。原脚本 UTF-8 无 BOM，Windows PowerShell 5.1 按系统 ANSI 解码，中文路径和错误文字被误读；CMD 同样缺少明确代码页。此前只验证打包引擎，没有覆盖该真实启动入口。
- PowerShell 脚本改为 UTF-8 BOM，CMD 先切换代码页 65001，均保留 CRLF；失败时暂停以保留错误信息。同时去掉主程序的隐藏启动标志。
- 从真实 `.cmd` 入口启动成功，桌面 PID 221704，前端就绪 1604ms，原生窗口标题“末帧选片”、可见性 True；引擎 PID 240952，`/api/health` busy=false，提供方接口包含内置开关。重复启动复用同一桌面窗口，原演示引擎保持运行。桌面窗口保留供用户使用。
- 本轮只修改启动器和文档，模型和解析逻辑未变；无需重建引擎。提交见 `fix: make builtin model launcher work in Windows PowerShell`。
