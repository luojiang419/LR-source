## 验收标准

- 已有普通解析、旧二星或共享推理容量占满时，新二星仍独立发送 API OCR 请求，不等待旧任务结束。
- 连续标记不同照片均可并发；同一任务不重复请求。普通批量队列继续推进，内置 local 协议保留其资源限制。
- 全自动扫描尚未到达的二星图片也立即创建任务；暂停、取消、重标、切换文档和进程关闭时校验请求代次与照片身份，旧结果不能覆盖新结果。

## 实现

- `label_concurrency.py` 增加独立二星 API 调度。每个持久任务通过条件 UPDATE 原子领取，再启动独立工作线程；多个新二星直接发送请求，普通队列继续执行，不用中断旧推理。
- `vision_scheduler.py` 允许独立 API 标签跳过普通容量等待；本机 local 协议仍受原资源约束，普通任务设置保持。实际模型可同时计算的数量由服务端控制；即使服务端已满，客户端也不会等旧任务结果才发送新请求。
- `sku_service.py` 抽出共用的任务处理，兼容旧数据库新增 run_token 请求代次。取消后重标、旧响应晚到及普通/独立调度竞争均校验代次、任务状态和图像身份；结果修改仍串行提交，暂停与关闭保留。
- API 先执行识别，随后登记归档区间，避免归档写图锁阻塞新请求；尚未识别完成的二星仍作为已有区间边界，后款先返回也不能吞掉前款区间。
- `full_auto_ocr.py` 标二星时直接为尚未扫描到的照片创建全自动任务，不等后台扫描；已在识别的同一张不重复发送。
- `sku_vision.py` 为内置与 LM Studio 的 glm-ocr 共用原生 `Text Recognition:` 提示，关闭 JSON 输出要求；保留原文与无置信度状态，其他模型的格式回退逻辑保持。
- README 同步 API 并发、本机资源限制和 GLM 原生提示的实际行为。
