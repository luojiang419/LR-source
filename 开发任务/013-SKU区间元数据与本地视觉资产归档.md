## 1. 本轮目标与现有实现边界

用户要求 SKU 标签表示“一款拍摄结束”，由相邻结束标记划分图片区间；把 SKU 等备案信息写入照片元数据，即使分散到不同目录，也能重新检索归档。同时支持 Shift 范围选择和右侧批量填写元数据；配置 LM Studio 本地视觉模型（例如 Qwen VL），默认并发处理两张图片，解析维度后续确定。

012 已具备二星标签识别、模糊匹配、工作表隔离、人工复核与 Excel 状态，但没有给产品照片批量归属 SKU、没有文件写回，也没有跨目录资产身份。当前事实：

- `media_engine.capture_record()` 的 capture ID 来自相对路径，fingerprint 包含路径、大小和修改时间；均不能作为跨目录永久资产 ID。
- `Store.append_live()` 保持同目录 RAW/JPG 配对编号，但元数据写入会改变 fingerprint 和快照。
- `SkuService` 以照片 fingerprint 检查识别前后的有效性，目前由一个工作线程串行执行所选模型。
- `app.js` 只有一个 `selectedId`；缩略图复选框代表选片/星级，不能直接复用为备案多选。
- 模型卡片按多模态/OCR/文本独立选用，本机 localhost HTTP 已允许，但还没有 LM Studio 连通测试、任务用途绑定或通用视觉解析队列。

下文保留设计依据；实际落地模块、物理表/接口映射及验证边界见第 11 节。设计表按逻辑职责描述，代码使用较小的物理表及不可变 JSON 快照承载对应信息，不把未开放格式或真实模型验收表述为已完成。

## 2. SKU 结束区间规则

### 2.1 正常拍摄

```text
开始拍摄 → 图001 图002 图003 → 二星标签 A
           └──── SKU A ────┘   标签为 A 的结束证据

标签 A 之后 → 图005 图006 图007 → 二星标签 B
              └──── SKU B ────┘  标签为 B 的结束证据
```

对同一拍摄流，归属范围为 `(上一结束边界, 当前结束边界]`。本次 SKU 写给标签之前的产品照片，当前标签作为证据另存；默认也给标签写同款元数据，但标记 `role=sku_label`，不计入产品图数量。上一张结束标签不归入下一款。

第一次绑定时创建“开始拍摄”起点，仅接收之后的新照片。已有目录的历史照片需要在界面指定起点或 Shift 手动备案，不把原目录全部历史照片自动算成第一款。最后一款尚未拍标签时显示“待结束”，可补拍标签或在面板手工结束并填写 SKU。

### 2.2 拍摄流与稳定顺序

- 拍摄流 `stream_id` 固定项目、工作表/拍摄类型、接收来源和拍摄段，不使用“当前界面选中的页”推断历史照片归属。
- 首次稳定入库时分配不可变 `ingest_seq`，记录拍摄时间、相机序列信息和接收时间。拍摄排序使用可信的原始拍摄时间/子秒及相机顺序；同时间用 ingest_seq 定序。没有可信拍摄时间时退到接收顺序，并在区间上显示该排序依据。
- 区间保存 `start_boundary_id/end_boundary_id`、排序键和明确的 asset_id 成员清单；已经确认的成员不能随 UI 排序或文件修改时间改变而重排。
- RAW/JPG 是同一个拍摄资产的两个文件组件。后到配对组件沿用该 asset_id 和归属，不新开一张图片。
- 迟到照片：若可信拍摄时间落在已封口区间，列入“迟到待补入”；提示后补写，不能静默移走其他区间成员。无可靠时间、拍摄时间冲突或多相机时钟未校准时进入待确认。单相机可信顺序为首版默认，多相机不按混乱的文件到达顺序自动合并。
- 切换工作表/拍摄类型时开启新拍摄段。原段未结束则保留“待补标签/待手工结束”，新页不接收原段未归属照片；之后切回同页也不跨不同拍摄段自动连接。

### 2.3 标签失败与撤销

二星稳定后先持久化候选结束边界和区间快照，再调用 OCR。识别失败、未配置模型、模糊待确认都保留边界；后一个标签开始新的区间，不能吞并前一段。只有 SKU 被可靠匹配或人工确认后，才把该段变成可写入备案任务。

边界状态为 `candidate → waiting_sku → confirmed`，或 `needs_review/cancelled`。快速加到三/五星，未达到二星稳定时间的，不产生边界。候选边界被明确判为普通照片时，可发起合并预览；已有确认区间不静默重算。

012 的“取消二星撤销对账贡献”要联动归档：若只在库中待写，取消对应写入；若已写照片，生成可追踪的补偿/撤销任务，标记“已撤销，文件待同步”。数据库事务不能回滚已经写入的文件，不能显示成已全部撤销。

区间被重新识别成另一 SKU 时显示受影响图数和已有冲突，按新的 assignment_revision 生成更新任务；人工锁定的归属不被自动覆盖。

## 3. 永久资产身份与文件内元数据

### 3.1 身份与位置分离

`asset_id` 为拍摄资产 UUID，与文件名、目录和 SKU 独立。RAW 与配对 JPG 共用 asset_id，各有 `file_id`；同文件复制到多个目录，登记多个 location。路径只表示最后已知位置，不作为资产主键。

读取身份优先级：

1. 文件/伴随 XMP 内的 Framekeep AssetId/FileId 与库记录核对。
2. 没有身份字段时用已登记的完整内容 SHA-256 找精确副本。
3. 相机/时间/尺寸/视觉近似只能建议关联，不能据文件名或感知哈希直接认定同一资产。

元数据写回会改变文件 SHA-256，所以每次保留前后哈希和版本记录；不能用写入前的哈希当永久 ID。外部软件复制了 ID 却改变内容、同 ID 出现内容冲突时，标为待核对版本/派生件，不自动合并覆盖。缩放/修图导出应记录 parent_asset_id/derived_from_file_id，具体导出流程接入后生成派生身份。

### 3.2 字段协议

自定义 XMP namespace：`https://framekeep.local/ns/asset/1.0/`，prefix 为 `fk`。ExifTool 配置注册该命名空间；同时写标准关键词，方便支持 XMP 的其他软件按 SKU 查找。

| 写入字段 | 内容 | 规则 |
| --- | --- | --- |
| `XMP-fk:AssetId` | 永久资产 UUID | RAW/JPG 同拍共享 |
| `XMP-fk:FileId` | 文件组件 UUID | RAW 与 JPG 分开 |
| `XMP-fk:SKU` | 原始款号展示文本 | 不用模糊标准化结果覆盖原始款号 |
| `XMP-fk:ProjectId` | 拍摄/对账项目 UUID | 跨页同 SKU 可区分项目 |
| `XMP-fk:ShootType` | 稳定类型代码或工作表标识 | 另在库保存当时显示名，不只存“细节”等可改文字 |
| `XMP-fk:SegmentId` | 所属拍摄区间 UUID | 人工直接备案可关联人工批次 |
| `XMP-fk:MetadataRevision` | 本文件已应用元数据版本 | 乐观并发、重试、撤销核对 |
| `XMP-dc:Subject` | `SKU:LC…`、`ShootType:detail` 等关键词 | 合并既有关键词，去重，不整列覆盖 |

数据库保存操作者、原始/规范 SKU、依据、标签、时间、改前值与改后值等完整审计；这些内部信息不必全部暴露到文件里。不把 SKU 写进拍摄日期、相机型号、标题或描述，也不改星级。自定义字段用于精确重建备案，标准关键词作为通用查询入口；不保证所有第三方软件会保留未知 XMP 字段。

### 3.3 文件格式策略与可携带边界

本需求的目标模式是“单文件携带”：对通过格式验收的文件内嵌 XMP，移动/改名后仍可读取 SKU。JPEG 首先实现；TIFF/PNG 等按格式逐个验收后加入白名单，不能根据扩展名一概宣称可无损写入。

Canon R6 II 的 CR3 必须列入后续专项验收。当前 ExifTool 13.59 的可写列表包含 CR3，尚不足以证明本机样片写后仍可被 Lightroom/相机软件正确读取。CR3 验收包含 RAW 解码/内嵌预览、拍摄参数、评级、LR 识别和重写后的可重读，再允许在“单文件携带”模式写回。该步骤用样片副本进行，不先动用户原片。

另提供“RAW 伴随模式”：RAW 原件保持，写/合并同名 `.xmp`，归档时把二者作为一组移动。只搬走 RAW 且丢掉伴随文件时，无法承诺从 RAW 元数据读到 SKU；若原始字节未变，末帧可通过库中哈希重关联。界面必须区分“已内嵌”和“仅伴随文件”，不能把两者都标为单文件可携带。未通过格式验收的写入请求暂停该文件并解释原因，不能悄悄降级却显示成功。

“任何文件夹都能找到”指备案信息跟文件走，重新扫描目标目录可恢复索引。软件不可能在不知道位置、磁盘离线或无访问权限时即时找到所有副本，也不保证 Windows 资源管理器已索引所有 XMP 字段。全局快速查询由末帧资产库提供，迁移目录首次重新定位后即可查询。

## 4. 右侧元数据写入与 Shift 多选

元数据面板放在现有右侧信息栏，作为可折叠“资产备案”区，与星级控件保持独立。

```text
资产备案                         已选 24 张 / 48 个文件
SKU 款号        [ LC7877499-P6             ]
拍摄类型        [ 细节图 ▼                  ]
项目            100拍图10.19
写入范围        RAW + JPG（跟随项目格式策略）
已有归属        一致 / 混合 / 存在冲突
来源            手动选择 / SKU 结束区间
[预览变更]      [备案并写入元数据]
数据库 已备案   文件 已内嵌 20 / 待写 2 / 失败 2
[重试失败项]    [查看记录]
```

- 普通点击聚焦并选择单张；Ctrl+点击增减离散选择；Shift+点击从锚点到目标建立连续选择，网格、列表、胶片条共享同一 selectedAssetIds。
- 多选只作用于当前页面可见顺序：当前筛选/排序决定 Shift 区间，不偷偷选入被筛掉的照片。切换筛选、排序或目录时清空批量集合并重置锚点，避免留下隐藏选择。新传图不扩展已经选好的集合。
- 原有缩略图复选框继续表达选片/星级；备案多选用独立选中边框和数量，不能把四星/五星或“已选片”当作批量写入范围。
- 面板显示单值/“混合值”，不会自动把当前聚焦照片的 SKU 填给所有照片。动作提交前冻结 asset_ids、file_ids、目标 SKU/类型、各自 expected_revision；异步请求期间切图不改变目标。
- “预览变更”列明首末图、拍摄时间、图数/文件数、原归属→新归属和格式策略；预览本身不写文件。
- 无 SKU 时按钮不可提交。已有不同 SKU 默认进入冲突项；用户在面板选择“仅补空白”或明确覆盖冲突项。手动提交建立锁定归属，后续自动区间不能覆盖。
- 相同 SKU 的模特图和细节图保存不同 shoot_type/scope。工作表改名不改变稳定身份；手动输入表外 SKU 允许独立备案但注明“未关联清单”，不能将任意 Excel 行标为已拍。
- 手动备案不自动影响二星标签、边界或 Excel 拍摄状态；需要完成清单时由明确的区间确认或单独“同时关联清单”操作完成。

项目设置提供“标签确认后自动备案并写入”开关；开启后，不需要现场每款点按钮。仅对已经可靠确认 SKU、无冲突且格式已验收的区间自动写入；复核和未结束段等待处理。

## 5. 独立数据库与一致性

保留 `.framekeep/framekeep.sqlite3`（照片索引/星级）与 `sku.sqlite3`（清单/标签对账）；新增两库，按用途分离，不复制媒体二进制到数据库。

### 5.1 `asset_archive.sqlite3`：备案与位置的主库

| 表 | 核心字段及约束 |

| `catalog_links` | catalog_session_id/capture_id/file_component 唯一、asset_id/file_id；兼容旧 ID，不重写星级主键 |
| `project_scopes` | scope_id PK、project_id、原始工作表名/标识、显示名及改名历史；保留“模特/细节”稳定身份；重新导入不同清单时不凭同名直接合并 |

| `capture_bindings` | stream_id/asset_id 唯一、ingest_seq、frozen_order_key；接收上下文冻结 |

| `metadata_jobs` | operation_id/file_id/target_revision 唯一、写前版本/写后哈希、lease、结果及失败原因 |
| `audit_events` / `outbox_events` | 不可变操作记录；可恢复的跨模块事件、事件 ID 和投递/消费状态 |

索引包括 `(normalized_sku,project_id,scope_id)`、segment、capture_time、asset_id/file_id、sha256、location 状态和 metadata job 状态。SKU 等精确条件走 B-tree；后续文本描述检索可用 FTS5，图片向量索引按未来维度决定，不预先引入大型向量服务。

### 5.2 `vision_analysis.sqlite3`：解析定义、队列与结果

| 表 | 核心字段及约束 |
| --- | --- |
| `analysis_schemas` | schema_id/version PK、名称、JSON Schema、提示词模板、输入策略、状态；不固化未来维度 |
| `analysis_batches` | batch_id、选定方案/版本、provider_id、model_snapshot、requested_by、统计 |
| `analysis_jobs` | job_id、batch_id、asset_id/file_id、input_revision/hash、schema/prompt/model/config版本、status、attempt、lease/heartbeat、priority |
| `analysis_results` | result_id、job_id、raw_response、validated_json、schema_valid、模型/方案版本、耗时、完成时间；历史不覆盖 |
| `analysis_current` | asset_id/schema_id → 当前有效 result_id；源版本变化后标 stale |
| `scheduler_settings` | 设备/服务资源组、最大并发、超时、重试策略；初始全局上限 2 |
| `event_receipts` | 来源事件 ID 去重，跨库任务创建与恢复 |

统一启用外键、WAL、busy_timeout、schema_version 迁移，写事务保持短，不跨网络调用持有 SQLite 锁。SQLite 外键不能跨数据库，跨库引用由服务校验并定期查孤立项；一致性依靠持久化 outbox、唯一幂等键和补偿，不假设三个数据库与磁盘文件能一起原子提交。

012 的 SKU 确认/撤销事件应与相应 `sku.sqlite3` 结论在同一事务写 outbox。资产库确认 assignment 与元数据 jobs/outbox 同事务提交；视觉库消费事件时以 event_id 去重。各库 schema migration 由各自服务管理，可从快照重建派生索引，不自动删旧对账记录。

## 6. 元数据写入流水线

```text
SKU 确认 / 手工备案
        ↓
冻结区间或多选目标 → 校验冲突、文件能力和归属版本
        ↓
资产库保存归属 + 写入任务（queued）
        ↓
逐文件加锁 → 读取当前值与文件版本 → 写同目录临时副本
        ↓
读回目标字段 + 检查非目标元数据/图像内容
        ↓
替换前再次核对原文件 → 原子替换/平台支持的受控替换
        ↓
记录新哈希/metadata_revision → 通知索引/监控更新 → applied
```

单文件 `queued → running → verified → applied`，另有 `conflict/failed/cancelled/rollback_pending`。任务只在读回目标正确、文件提交完成后标 applied；一个批次可以部分成功，展示真实数量，重试仅补失败项。

写入器使用随包 ExifTool，通过参数数组/UTF-8 参数文件调用，不能拼接 shell 执行 SKU；自定义 namespace 配置随应用发布。已有 XMP/关键词采用字段级合并，保留未知 namespace、星级、拍摄参数、方向和色彩信息，不用重新编码图像来“写元数据”。

每个文件串行加锁；写入并发与视觉推理分别限制，首版文件写入默认 1。写前先确定文件已传输完成、关闭相机写句柄；磁盘满、只读、文件占用或网络目录不支持同等替换语义时不冒充成功。临时文件在同卷，扩展名/路径不进入照片监控匹配；保留可恢复备份和操作 journal，批次稳定后按已定义保留策略清理，不能清掉未提交或可撤销操作依赖的备份。

跨崩溃恢复：若文件已替换但库尚未记 applied，读回 file_id/revision/目标值判定并补齐；若只写临时副本，核对源版本后继续或清理。外部编辑发生时标冲突，不直接覆盖。

与现有监控的协调必须按**文件 + operation_id + 预期前后版本**判断内部写入，不能简单屏蔽目录若干秒。内部元数据变化更新 catalog fingerprint 与预览缓存版本，但不产生新拍摄资产，不改星级或区间。正在执行的 SKU/OCR 任务以输入图片内容版本验证，元数据自写不应误判图像已变；真正图像替换依然作废旧任务。

`image_revision` 和 `metadata_revision` 分开记录：已验证的本工具元数据写入只递增后者；外部变更先核对图像输入再确定是否递增前者。解析幂等键用实际输入图片摘要，提示词若引用 SKU 等备案上下文，还要包含对应 context_revision，避免沿用旧 SKU 条件下的结果。

只撤销本工具拥有且未被后来修改的字段。发现 revision/字段值不同则停止该文件补偿并提示；不把整份旧文件覆盖回去以抹掉用户后续修图。

## 7. LM Studio 卡片与解析并发

### 7.1 配置与用途绑定

沿用 012 配置卡片，增加“本地视觉服务”预设。保存卡片仍不自动选用，点击卡片才选择；配置示例为 `http://127.0.0.1:1234/v1`、实际已加载的 Qwen VL 模型标识、可空或按服务设置填写的密钥。远端/局域网部署按项目网络规则验证地址；本期默认本机。

新增用途绑定 `sku_label` 与 `asset_analysis`：分别指向明确卡片。这样归档模型的更换不意外改变 SKU/OCR 选用，二者也可显式共用同一卡片。删除被绑定卡片后相关任务暂停，不能改用其他云端或本地模型。

连接检测由本机后端访问服务的 `/v1/models`，再用一张测试图做视觉请求验证；仅 models 列表成功不能证明模型支持图片。通过 Chat Completions 兼容协议发送 `image_url` data URI，不需要浏览器直接访问模型服务。模型须已加载且支持视觉输入；有些服务不支持 JSON Schema/response_format，则降级成提示词约束 JSON 后由客户端验证，不能跳过验证。该能力来自实际检测结果，不根据模型名称猜。

卡片/设置提供模型、超时、输入长边、最大输出 token、资源组和全局并发（首版 1 或 2，默认 2），另显示最近检测结果。关键参数随任务冻结，API key 只保留受保护引用，不写任务结果或文件元数据。

### 7.2 两张并行的调度含义

- 一个任务处理一个拍摄资产的一张代表图，默认优先配对 JPG 或 RAW 清晰内嵌预览；RAW/JPG 不作为两张重复分析。完整 RAW 解码按方案要求另定。
- 默认两个 worker 允许同时发出两个独立图片请求；不把两张合成一张图，也不要求模型在一个响应里猜两张的归属。
- `SKU 标签识别` 和 `资产视觉解析` 共用本机推理资源组的全局容量 2。可以独立暂停普通解析队列，SKU 标签任务优先；已在运行的请求不硬杀，腾出槽位后先处理标签，避免两个解析再叠加标签形成 3 路抢显存。
- 现有 SKU 单线程工作器需接入该协调器或通过共享容量令牌请求；不能只是新增一个两线程池而让总并发失控。相同后端/同 GPU 的不同卡片也共享资源组，不能只按卡片 ID 各算 2。
- 严格持久化领取、租约和心跳；失败退避重试，崩溃后回收过期租约，不重复提交已完成的幂等任务。幂等键涵盖 asset/file 的图像输入版本、方案/提示词版本、模型/参数版本。
- 429/暂时不可用按可重试错误退避，显存不足将当前资源组有效容量降为 1 并显示原因；不能把失败结果填成空 JSON 当成功。
- 2 路客户端并发不保证 LM Studio 实际 GPU 同时执行两张；服务也可能内部排队。实际吞吐和显存上限必须在用户本机模型测试后给出，不事先承诺速度。

### 7.3 解析维度后定，底座先固定

解析方案通过 `schema_id + version + JSON Schema + prompt + input_policy` 配置。用户之后确定服装品类、颜色、材质、视角、人物或瑕疵等维度时，新增方案版本，不给每个维度加一套数据库列。本阶段不替用户决定必填维度，也不对所有历史照片自动启动未定义解析。

每次记录 raw_response、合法 JSON、校验错误、模型、方案/提示词版本、输入版本和耗时；旧结果留存。未知值按 schema 允许的 null/unknown 保存，不强迫模型猜测。图片里的文字和外部内容作为数据，不能修改解析指令。

AI 推断与已确认 SKU/人工备案分开存储。视觉模型不能自动改权威 SKU；其字段只有在后续方案明确映射且经过相应确认后，才可走同一元数据写入流水线。源图或方案变化使当前结果 stale，重跑产生新结果，不篡改历史。

## 11. 实际实现与交付

- `选片助手/asset_archive.py`：独立 `asset_archive.sqlite3`；assets/files/locations/versions/catalog_links 维护永久身份、组件、多位置和已知内容哈希。assignments、previews、operations、metadata_jobs、audit 保存变更、版本冻结、写入/撤销状态。streams/bindings/segments 保存拍摄段、结束边界和明确成员；事件回执去重，主库星级 ID 不迁移。

- 视觉库由同一进程两个线程事务领取，运行任务在进程重启时回到 queued；单实例进程内不需要分布式心跳。原文/结果独立保留，未接入向量库或用户尚未定义的业务解析维度。
- 实际接口为 `/api/archive/start|configure|close|segment-apply|streams|selection`、`/api/assets`、`/api/assets/<id>`、`/api/assets/relocate`、`/api/metadata/preview|apply|retry|revert|operations`、`/api/analysis`、`/api/analysis/schemas|batches|control|results`、`/api/providers/bind|test`。浏览查询目前按 SKU、项目/类型及分页；未来解析字段/向量筛选按维度继续扩展。
- JPEG 通过内嵌验收；RAW 通过伴随模式，源字节不改。CR3 内嵌、TIFF/PNG 等不在当前写入白名单，明确报失败而非静默降级。多相机时钟校准、派生图人工身份冲突消解和外部软件删除全部元数据后的视觉近似关联不自动推断，可通过人工备案处理。
