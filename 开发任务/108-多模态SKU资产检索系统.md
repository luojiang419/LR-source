## 架构与完整链路

沿用 `asset_catalog.sqlite3` 作为位置与 SKU 权威库，通过版本化附加表存储解析任务、逐帧结果、属性倒排、可重建向量和归组提案，SQLite WAL、短写事务、索引检索、稳定分页。解析工作线程与交互查询分离，模型调用使用现有容量限制和密钥保护。

目录扫描 → 持久待解析任务 → 当前文件版本校验 → 缩小预览/视频采样帧 → VLM 严格 JSON → 多维属性/文字证据 → 倒排索引和视觉向量 → 文件夹一致性判定 → SKU 提案/人工确认 → 多路检索 → 缩略图/原目录定位。

解析维度参考 DIT-tools：摘要、主体、品类、款式、颜色、材质、纹理、场景、构图、镜头、光线、情绪、人物/动作、品牌/文字、用途；支持自定义维度。逐帧结果保留时间点，不将不同帧属性误当同一对象证据。

同色不构成同款证明。归组同时要求款式/品类/颜色一致、完整解析覆盖、无多主体冲突、有效 SKU 证据及现有 SKU 规则；疑似组保留可解释的提案，人工归属优先，自动结果不得覆盖人工修改。非公司款号文件夹不直接当款号。

检索先按 SKU 精确/前缀匹配、全文与维度召回，视觉向量独立召回后融合，显示命中原因。图像相似度与语义描述分别标注；模型缺失显式报告，不用随机向量冒充 CLIP。媒体内容不存数据库。
