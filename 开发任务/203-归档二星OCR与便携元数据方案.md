## 已确认的九项补充决定

以下来自用户逐项选择；同一问题的旧推荐表述以本节为准。用户随后明确授权开发并使用真实文件副本验证。

| 项目 | 已确认规则及落地约束 |
| --- | --- |
| 1 单端编辑 | 保留数据集独占写入，避免边拍边修造成混乱。其它设备可以核对／导出，必须待原端正常交接后才能修改；首版不引入多人同时提交修改的服务。 |
| 2 修改范围 | 默认只修改当前明确选择的数据集及本次预览确认的成员；其它小档、大档、归档副本不被自动反向修改。可以展示关联副本差异，跨数据集同步作为独立显式操作，首版不自动执行。 |
| 3 两星语义 | 现场拍摄沿用主动两星为款末标记；归档在“款号修正”模式下主动两星才创建款末边界。普通评级、外部导入两星不直接触发 OCR／重新分款；已有明确标签身份可原样恢复。 |
| 4 SKU 范围与格式 | 业务唯一性按“客户／品牌命名空间 + 实际 SKU”判定，保留原文字、前导零、大小写及短横线。搜索可有规范化键，但不得因此合并不同字面款号。真实色号与重拍后缀单独记录，不靠截断字符串判断。 |
| 5 视频 | 首版支持手工填写及对明确选中视频批量指定一个 SKU；不参加照片二星区间，不依据相邻照片自动推断。单视频多 SKU／按时间段分款不纳入首版。 |
| 6 恢复完整性 | 文件中增加组版本、预期产品／标签数量及成员摘要；界面分别展示当前范围找到数量、记录中的预期数量。仅恢复单图 SKU 不等于整组完整，证据不足标“完整性未知”。 |
| 7 后期字段保留 | 用户确认实际后期操作中元数据均保留，之前已有验证。作为既有业务事实，不再列为未决风险或要求重做相同验证；用户未指定此前验证文件，本轮不虚构验证报告。新增格式／流程变化仅验证变化部分。 |
| 8 误操作与撤销 | 批量修正先预览实际路径、组、数量和新旧值；记录按操作的历史与撤销。撤销只补偿该操作仍有效的字段，不恢复整个旧库，不覆盖后来其它有效修改。 |
| 9 备份与原图保护 | 区分元数据冗余、业务恢复点与原图备份；沿用 RAW 不改字节、JPG 像素校验及未知字段保护。整盘故障依赖独立备份／NAS 恢复点，不宣称同盘多份元数据等于备份。 |

### 对现有设计的补齐

- **修正模式**：归档提供明确“款号修正”开关和状态；默认普通浏览／评级。模式切换不把已有普通两星自动转为标签；历史两星可预览后明确转换。保存 `boundary_kind` 和触发来源，恢复时不靠星数猜角色。首版原有现场主动标两星的习惯保持。
- **命名空间兼容**：数据集记录客户／品牌作用域，文件级恢复字段同步携带作用域 ID 与必要显示名称；新增占号、唯一约束、搜索分组和导出均纳入作用域。旧记录沿用既有默认作用域，不从文件夹名猜客户，也不批量重命名已有 SKU。来源作用域缺失且发生同款歧义时分开显示待核对，不全局猜合并。
- **视频字段保存**：首版视频采用同目录按完整文件名对应的文件级 XMP（例如 `clip.mp4.xmp`），配合 `.shiying` 保存 SKU 和文件身份，避免为改款重写大型视频。新增读写及索引适配支持这种配对；不声称第三方软件都能识别这一约定。图片后期元数据保留的既有验证，不扩展为新视频格式已验证。批量操作只处理实际选中项，不把当前分页当作目录全量。
- **数量口径**：组内预期数量绑定明确范围和组版本。归档目标以最终实际保留清单为准，不把已确认后期删除的照片算缺片；独立导出子集同时保存本子集范围与原组追溯。仅加载子目录时不能因为本次未扫描其它路径便宣称整组丢图。
- **撤销权限与流程**：撤销同样要求当前数据集写权限，检查原操作的文件身份、当前业务修订和后继修改；有竞争修订时列出不可直接撤销项。已写图片／XMP 的撤销生成补偿写任务并读回验证，保留历史，不直接删除旧事件。目录整理的撤销须另外预检源／目标和同名冲突，不与“改回 SKU 字段”等同。
- **恢复点**：关键结构迁移／大批量整理前保存一致的轻量业务恢复点及操作清单，恢复点包含未完成的持久任务。文件写入遵守已有空间策略，不擅自恢复整图库临时复制；JPG 直接写回的断电边界如实保留，字段历史不能恢复损坏的像素。部署时核对已有照片备份／NAS 恢复能力，未配置时明确显示“无独立原图恢复保障”，不替用户创建未知外部备份目标或修改 NAS 策略。

## 1. 目标与推荐结论

资产归档成为现场拍摄的后续修正工作台：同样可以按 2 星划分款号区间、OCR 识别、手工改款、查看目录拍摄记录及导出 Excel。用户换电脑后只需添加照片所在路径，即可恢复这些业务信息，无需复制本机庞大的媒体索引或预览缓存。

推荐采用“统一业务服务 + 文件夹便携档案 + 本机查询投影 + 图片后台补写”：

1. 现场与归档共用标星、OCR、区间、确认、撤销规则，不另建一套归档 OCR 逻辑。
2. 图片进入目录即持续记录已提取的身份与拍摄信息；标 2 星时先可靠保存评级、边界和区间成员。OCR 完成后再追加原文、候选和确认款号，不能声称标星瞬间已有尚未识别出的款号。
3. 文件夹携带仅包含本目录业务资料的轻量 SQLite 快照与增量记录；NAS 不承载多个客户端共同原地修改的 SQLite 工作库。
4. 其他客户端自动读取便携档案并建立本机查询投影；已确认款号直接可用，图片内嵌元数据尚未完成也能查看、导出和准备归档。
5. 图片元数据是兼容其它软件的输出，便携档案是本软件跨设备恢复的业务依据。保留每次修改的来源、版本和冲突，避免旧 XMP 把人工修正覆盖回去。

用户补充的强制要求：SKU 及必要恢复字段必须同时落在图片内／同目录 XMP，不能只存在 `.shiying`。便携档案负责即时共享和完整历史，文件级元数据负责脱离档案后的 SKU 搜索、图库与基本分组恢复；文件级写入及读回全部通过后，才显示具备此项恢复能力。

## 3. 归档右栏与操作设计

右栏采用两个常驻标签页，默认记住用户上次选择：

| 标签页 | 内容 |
| --- | --- |
| 照片设置 | 当前预览、文件名、0–5 星、SKU 输入、当前区间范围和产品图数量、OCR 解析当前图、OCR 资料／选择 SKU、照片信息、元数据写入状态。 |
| 目录拍摄 | 当前实际文件夹路径、日期筛选、已确认／待识别／待复核／未闭合数量、款号分组列表、标签与产品图引用、便携档案状态，以及固定底部的“导出拍摄文档”。 |

- 区间编辑默认作用于所选照片所属的整款；按钮明确写“确认整款 SKU（N 张）”。现有逐图／多选修改保留为独立作用范围，不能悄悄改变原来的单图语义。
- 标 2 星立即显示“已保存，正在识别”；重复点击已有有效二星仅展示状态，主动“重新识别”才创建新版本任务。
- 无 SKU 时可直接手填确认，不强制依赖 OCR 成功或联网。识别失败保留边界并显示重试；多候选进入复核。
- 普通图片点击“OCR 解析当前图”只提取辅助资料；形成款末分组须明确标 2 星或使用“手动结束本款”。
- 目录状态分开显示：“本机已保存”“文件夹档案已同步／待同步／失败”“图片元数据待写／已验证／失败”。只有远端记录发布并回读校验后，才显示文件夹已同步。
- 切换目录、翻页、搜索和排序不能改变区间范围；右栏导出范围在按钮上方固定显示，不默认跟随搜索结果缩小。
- 视频支持单个手填及明确多选的批量 SKU 指定，不进入照片二星分组；设计文件保留一般资料编辑。
- 键盘 0–5 沿用现场习惯，文本框及弹窗内不触发；两个标签支持键盘切换，窄栏内纵向滚动。

### 3.1 文件夹内素材卡片标识

- 添加资产路径并点击实际文件夹后，图片／视频卡片下方固定两行：第一行文件名，第二行 `SKU：实际款号`；尚无款号显示 `SKU：未确认`，纯路径推断的候选明确标“待确认”。
- 文件名和 SKU 各自保留完整悬停提示，长内容单行省略，不撑宽卡片；选中态及四种主题保持可读。
- 缩略图右下角显示已保存的 1–5 星，明确零星时不显示；格式／RAW+JPG 标识上移避让。视频已有评级也可显示，照片的二星 OCR 行为不扩展到视频。
- SKU 修正、星级变更和后台资料恢复后更新卡片；列表读取现有索引，不在每次绘制缩略图时逐图读取 NAS 或运行 OCR。未来文件元数据恢复和便携档案导入统一更新同一索引。

本项与整体方案一同待确认，拟接入 `演示方案/asset-library.js` 与 `asset-workspace.css`。候选状态应前置，避免长款号省略后看不到“待确认”；选中态使用主题配套文字色，保证深色主题可读。此前隔离试改已撤回，其截图不代表现用功能。

## 4. 区间、修正与历史目录规则

### 4.1 区间定义

同一拍摄流内，区间为 `(上一款结束标签，本次结束标签]`。仅明确的款末标签作为边界，普通二星评级不等同于标签。当前二星标签保存为 `role=sku_label`，默认同款，但不计产品图数量；上一标签不重复归入下一款。末尾无结束标签的照片显示“未闭合”，不继承上一款。

流标识使用数据集、原始拍摄目录、相机、拍摄类型及业务上下文，不使用当前盘符。照片排序和区间成员在确认时冻结，保存 `stream_id + sequence + member_asset_ids + revision`；移动到母子 SKU 目录后仍保留原流，不按新物理目录重切。

### 4.2 历史散图首次使用

有便携档案或可信现场记录时恢复原起点和顺序。纯历史目录第一次进入修正模式时展示该流的起止范围，默认首张至末张，可调整起点；用户执行首次分组前确认这份明确范围。保存后不反复询问。父目录递归浏览不合并子目录或不同相机的流。

没有可信时间时保存现有稳定顺序，并在预览中标明；后补 EXIF 不自动重排已确认区间。迟到照片可自动进入尚未确认的开放区间；影响已确认区间时进入“新增照片待归组”，由用户核对，不静默扩大整款。

### 4.3 改星与撤销

- 款号修正模式／现场拍摄内主动 `非2星 → 2星`：保存新边界并触发 OCR。普通评级或外部导入两星仅保存评级；转换为款末标签需明确操作。
- `2星 → 非2星`：该标签不再作为有效边界，取消未完成任务；迟到结果须核对边界版本，不能复活旧确认。
- 清零同步保存 `ocr_reset` 撤销记录，阻止重新扫描恢复旧结果；撤销只影响该边界产生的自动归属，不删除其它人工锁定字段。
- 移除中间边界会影响邻接区间：先给出变化范围，已有确认／人工锁定的归属列入复核，不把两款直接合并。重新二星使用新修订，历史占号保留。
- 同一原款号的不同标签继续使用现有稳定 `SKU/SKU-A/SKU-B` 规则。已分配实际款号随档案恢复，跨客户端不重新编号；并发抢占同一后缀时标冲突并停止相关归档，不能按客户端时间随机选一条。

## 5. 便携档案的位置、内容与身份

以用户选定的实际拍摄文件夹作为数据集根，通常是“当天／拍摄类型”目录。日期是业务字段，不依赖目录名推断；跨午夜目录可包含多个拍摄日期，但不跨日期自动合并开放区间。

拟新增结构：

```text
NAS/拍摄/2026-11-09/细节图/
  IMG_0001.JPG
  IMG_0002.CR3
  .shiying/
    dataset.json                         # 格式版本、数据集UUID、时区
    snapshots/<generation-id>.sqlite3     # 已封存、仅含本数据集的快照
    snapshot-commits/<generation-id>.json # 摘要、父版本、事件覆盖水位
    events/<writer-id>/<event-id>.json    # 不可变小事务，含完整业务变更
    commits/<writer-id>/<event-id>.json   # 小事务发布完成记录
    previews/<content-hash>.jpg           # 可选小型标签／代表图，不存全量预览
```

默认自动维护，无需用户导入导出。`.shiying` 是业务数据，必须随照片复制，不属于可清理缓存。仅复制照片而漏掉它、且图片元数据还没写完时，无法保证跨机恢复；目录菜单提供“复制照片及随行档案”以避免遗漏。

拟新增逻辑表／记录：

| 数据 | 必须保存的内容 |
| --- | --- |
| dataset / streams | 数据集 UUID、格式版本、原始流身份、时区、起点、排序依据、拍摄类型、文档/业务上下文。 |
| assets / file_instances | 永久资产 ID、快门身份、JPG/RAW 文件实例 ID、相对路径、旧路径别名、格式、文件版本及来源。 |
| capture_metadata | 相机型号、机身序列号、原始拍摄时间、子秒、原始编号、必要 EXIF/XMP 字段及提取状态；保留原始值和算法版本。 |
| ratings / intervals / members | 明确零星、评级来源、标签身份、边界版本、区间成员、角色、原 SKU、实际 SKU、母 SKU、重拍版本、拍摄日期。 |
| ocr_readings / decisions | 原文、候选、置信信息、模型／规则版本、人工选择与锁定、确认或撤销版本。 |
| operations / conflicts | 操作 UUID、客户端实例、依赖版本、受影响实体、幂等键、撤销及冲突；不以设备时钟判定覆盖。 |
| metadata_receipts / path_moves | 期望业务修订、每个文件实际写入与读回结果、前后文件版本、路径迁移、错误及恢复凭据。 |

“所有元数据”指恢复本软件评级、分款、拍摄记录与整理所需的业务和身份字段，加上已提取的照片信息；不复制无关项目、全局素材索引、模型、整图备份和全部 MakerNotes 二进制。尚未提取的字段明确为待补齐，不能造空值覆盖已知数据。

身份分四层，禁止混用：

1. **资产身份**：已有可信 `AssetId` 优先复用；尚未写入照片时先在随行档案分配并持久保存，之后补写保持一致。
2. **同次快门身份**：沿用 `capture-v2` 的相机、序列号、原始时间／子秒与原始编号规范化规则；RAW/JPG 可是同一资产的不同文件实例。缺失编号的后期 JPG 仅允许既有受约束的唯一匹配回退。
3. **文件变化签名**：大小、mtime、现有 `fingerprint` 用于判断是否变化，不能作为跨设备永久身份；本机路径指纹不直接搬到另一台机器冒充有效作业。
4. **内容校验**：SHA-256 用于已登记副本验证与归档复制；相同文件可据此复用已有身份，但不能用不同格式文件的字节哈希匹配同次快门，也不靠画面相似或同名猜款。

文件未变化、登记相对路径精确对应且不存在身份矛盾时，可直接恢复目录投影；改名／移动优先用永久身份和快门身份恢复。文件被同名替换、业务身份冲突或证据不足时进入复核，不能只凭路径加大小认定同图。完整性检查按变化和实际归档需要后台执行，不在每次两星操作时读取整目录全部大档。

### 5.1 相对路径的明确约定

便携档案中的文件引用统一使用以下结构；不把本机盘符、UNC 前缀或安装目录写成跨设备关联键：

```json
{
  "dataset_id": "dataset-uuid",
  "asset_id": "asset-uuid",
  "file_id": "file-uuid",
  "relative_path": "LC78/LC7877847/IMG_0001.JPG",
  "capture_identity_version": "capture-v2"
}
```

- 相对路径始终相对于包含 `.shiying` 的数据集根，使用 `/`，保存文件名原始大小写；Windows 查找按实际文件系统语义处理，不用无条件小写合并不同文件。
- 客户端自己的本地配置保存 `dataset_id → 当前根目录`。A 映射为 `Z:\拍摄\细节图`，B 映射为 `\\NAS\摄影\细节图`，两端都用“本机根目录 + 同一 relative_path”定位图片。
- 数据库的文件主键是永久 `file_id`；路径是可变位置，不把绝对路径或相对路径本身当作永久身份。根迁移只更新本地映射；内部整理更新相对路径和旧路径别名，资产及文件 ID 不变。
- 直接选择某个子目录时，先确定其所属数据集根，再将当前选择转换为根内范围；不能把 SKU 子目录误当新根，拼出重复的 `SKU/SKU/图片`。
- 每次拼接拒绝绝对路径、盘符、UNC、`..`、替代数据流和越界链接，规范化后核对仍位于当前根内；离线缺失只显示不可用，不清掉资料或改配同名图片。
- 原相对位置存在且版本／身份无矛盾时优先使用；不在原位置时，用已验证永久身份、快门身份或已登记内容摘要定位。出现多个候选或同名替换时复核，不使用“同名优先”猜配。
- 便携的移动历史同时保存 `before_relative_path` 和 `after_relative_path`；操作所需绝对路径只在本机运行时生成。本地诊断日志可记录实际路径，但不作为其它客户端恢复的依据。
- 子集导出以目标文件夹为新的相对路径基准，重新生成子集根描述和来源映射；保留永久资产／文件身份，不直接复制仍以旧根为基准的路径表。

## 6. NAS 发布、即时保存与多客户端一致性

### 6.1 为什么不共享写 SQLite

SQLite 官方指出跨网络文件系统访问受锁和文件系统语义影响，WAL 要求同机共享内存，不适用于多机通过网络文件系统共用工作库。因此，本机 SQLite 可以使用既有模式，NAS 只保存封存快照与不可变增量文件。读取端先复制并核验到本地，再用只读 SQLite 打开；不能简单把现有 `sqlite3.connect()` 改成 UNC 路径。

参考：[SQLite 网络文件系统说明](https://www.sqlite.org/useovernet.html)、[WAL 限制](https://www.sqlite.org/wal.html)。

### 6.2 一次标星／确认的可靠提交

1. 统一服务先检查本数据集写入占用及基线，再在本机权威事务里保存评级／边界／确认与便携发件箱；跨现有数据库的其它投影使用同一操作 UUID 幂等投递，不假定多个独立库天然原子。未取得占用不能生成共享业务修改。
2. 归档和进度界面立即显示本机已保存；便携发布队列独立于 OCR 推理、ExifTool 和缩略图队列，按操作先后与依赖处理。
3. 发布事件到同目录临时名，关闭、刷新并回读校验后，发布唯一命名的完成记录。消费者仅接收完成记录指向且摘要有效、依赖完整的事务；看到半文件、缺依赖时等待补齐，不当作删除或成功。
4. 本机记录远端发布收据后才显示“文件夹档案已同步”。NAS 不可写／断网时保留本机持久队列，重启续传；其它客户端此时只能看到上一次已发布内容，界面明确同步时间和待同步状态。
5. 标星事件先保存区间与已知元数据，识别完成再追加确认事件；区间成员较多时用分块载荷，但只有所有分块齐全、总摘要正确才整事务生效。
6. JPG 内嵌、RAW 的 XMP 兼容写入继续独立执行，按当前业务修订读回核验后保存收据；原图像素与未知 XMP 字段保护沿用现有策略。

临时文件改名不等于任意 NAS 都承诺断电持久化；断网、客户端崩溃及 NAS 重启后重查完成记录与内容。部署验收覆盖实际 SMB 配置，未确认前不承诺绝对零丢失或固定毫秒延迟。

### 6.3 快照、并发与冲突

- 根据用户进一步明确的要求，首版采用**每个数据集同时只有一个写入端、允许多个读取端**。任意设备都能成为写入端，但必须先完成占用或交接；不默认开放多个客户端同时发布修正。本节替代此前多写者自动合并作为默认运行方式的描述。
- 在 `.shiying/write.lock` 使用 Windows／SMB 服务端实际执行的文件句柄共享限制。写入端以 `CreateFileW` 请求读写访问，仅允许读共享、禁止其它写入／删除共享，并在编辑会话中持续持有句柄；另存的 owner 描述只用于显示设备与会话，不作为互斥依据。其它程序内部所有修改入口和后台队列必须共用该写权限门禁。
- 争用失败的客户端进入只读模式，可浏览、搜索、预览和导出，显示“正在由设备 A 编辑”。只读端不修改评级、款号、边界，不补写图片，不提交修订、不执行整理；本机缓存的重建不属于共享业务写入。
- 锁的粒度是数据集，而不是整个 NAS；不同拍摄目录可以由不同设备同时编辑。数据集根不得在编辑期间从软件外部改名或替换；软件自身根迁移需先结束编辑并在目标重新取得占用。
- 正常交接时，原端停止接收新修改，等待正在执行的图片写入完成，将未执行任务及业务修订可靠保存／发布，结束该会话的后台发布和写图，再关闭锁句柄。新端取得排他写权限后必须重新读取已提交最新版本，才能恢复任务或接受修改。
- 客户端崩溃后按 SMB 服务端实际释放情况重新竞争句柄；不能仅凭锁文件仍存在判断被占用，也不能凭“心跳超过 N 秒”删除锁强行接管。断网／锁状态不确定时立即停止共享业务发布与写图，保留本机待恢复记录，恢复连接后重新取得占用并核对基线。
- 每次占用分配独立 writer／会话 UUID，事件含序号、基线版本与父提交。发布必须经过持锁会话内的串行队列；会话结束后旧 OCR 回调只能作为待核对结果，不能继续落库发布。基线不一致的离线操作必须复核或重算，不能直接覆盖当前确认。
- 文件锁是软件之间的协作互斥；不阻止不遵守协议的外部软件修改照片。SMB 断连、服务端恢复和延迟 I/O 必须实测；不能仅靠本机测试声称已解决跨机互斥。若 NAS 无法提供符合要求的共享锁语义，则停用共享写入，改用服务端单写协调后再开放；不能以普通心跳文件代替强互斥或宣称绝对防双写。
- 已有多分支、独立副本或离线草稿仍可能带来冲突。不同字段仅在验证基线及依赖后合并；同一字段、边界或重拍占号冲突保留双方并复核，不能按设备时间选择胜者。
- 快照由本机已合并投影构建，记录覆盖的每个 writer 水位与依赖头；使用 SQLite backup／独立事务导出保持一致，封存为无外部 WAL 依赖的单文件，校验后再发布快照完成记录。
- 多个读取端各自下载同一已封存快照到本机，读取本地只读副本并重放已发布增量，无需争取写锁。写入端另建新版本，不覆盖读取端正在使用的文件；读取端在本机完整事务应用后切换版本，允许看到稍旧但完整的版本，不展示半个区间。
- 多个快照可共存；加载一个覆盖充分且有效的快照，再重放未覆盖事件，不能只按时间选“最新快照”。已有分支必须检查其依赖和来源，不能遗漏交接前已提交的记录。
- 快照是加速层；增量可恢复尚未压入快照的修改。快照触发按事件数量／体积和空闲时间合并，避免每次标星全量重写。建议初始阈值 100 个事件或空闲 30 秒，实际压测调整。
- 第一阶段自动合并生成快照，但不自动删除未证明已覆盖的业务事件。历史压缩须保留基线、撤销记录和覆盖证明，旧／离线客户端重新接入必须完整补齐；该目录不按普通 30 天缓存规则清理。
- 数据集首次初始化使用排他新建并回读身份；初始化竞争产生不同 UUID 时明确冲突，不把两组照片默认为同一库。整文件夹备份复制保留数据集身份；用户明确“创建独立副本”才分配新数据集并保留来源映射。

“自动读取”是已发布记录的最终一致读取。首版界面不允许两个端同时编辑同一数据集；当前写入端退出／交接后，另一端才能修改。需要多人同时提交修改请求时，再增加服务端串行事务、版本比较和过期写入拒绝，不把共享文件方案直接当成服务器事务系统。

参考：[SQLite 在线备份说明](https://www.sqlite.org/backup.html)、[Windows CreateFileW 共享权限](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。

## 7. 换设备加载、权限与故障处理

1. 添加资产路径后，在所选根和扫描到的照片目录检测 `.shiying`；直接导入已整理的子目录时，在已授权范围内向上查找所属数据集。读取上级档案只投影当前选择范围，不扩大归档来源。
2. 不扫描整个盘或任意 UNC 父路径；数据集在授权根外时提示选择对应拍摄根，不能暗中越界。多个嵌套数据集以最近所属关系处理，重复身份与冲突显式报告。
3. 分别校验格式版本、大小限制、快照摘要、`quick_check`、事件依赖和路径边界；JSON 只作为数据，SQLite 本地只读、禁扩展加载，不执行档案提供的 SQL／命令，不跟随越界链接。
4. 以数据集 UUID 映射当前根路径，便携记录使用相对路径。`Z:\...` 改成 `\\NAS\...` 后不会丢款号；本地会话、项目和文件引用 ID 做来源映射，永久资产／文件 ID 保持。
5. 恢复本机评级、OCR 资料、区间、文档行及拍摄证据；外机 `queued/running` 作业恢复为“待处理”资料，不直接执行来源机文件写任务或自动启动现场监控。
6. 文件夹权限只读或已被其它写入端占用时，可加载、核对与导出。若提供草稿功能，草稿只保存在本机且不改变当前共享资料；取得写权限后重新核对原基线，有冲突先处理。
7. 活跃目录用通知加轮询补偿，初始建议 2 秒检查增量，后台／无变化时退避；离开页面停止高频轮询。目录列表分页、事件目录分桶、增量水位和快照避免每次浏览重扫整库；索引提示不是唯一事实来源。
8. 档案损坏时保留原件、回退上一个有效快照并重放有效事件；回退后显示“恢复至版本 X，仍有 Y 条不可用”，不能把旧状态冒充最新。更高版本格式只读提示升级，禁止旧客户端重写。

## 8. 按文件夹导出拍摄文档

- 固定入口放在“目录拍摄”底部；无手动改动但已恢复现场记录时也可导出。范围为当前实际文件夹及递归子目录，默认选定拍摄日期；多日期支持“全部日期”。点击前展示路径、日期、款数和图片数。
- 文件名采用 `文件夹名称_YYYY-MM-DD.xlsx`，日期指所选拍摄业务日期（Asia/Shanghai），不是任意当前时间。全部日期采用 `文件夹名称_起始日期_结束日期.xlsx`；无可信拍摄日期时才使用导出日期并在文档注明。
- 例如 `细节图_2026-11-09.xlsx`；重复导出保留已有文件，追加 `_01/_02`，过滤非法字符及 Windows 保留名。
- 主表每个独立区间一行：原款号、实际款号、母 SKU、拍摄类型、拍摄日期、产品图数、标签图、代表图、确认状态、确认来源、修改时间和相对目录。重复款号的不同分组不合并。
- 明细表逐文件列出相对路径、角色、星级、资产／快门身份、业务修订、文件夹同步状态、图片元数据写入状态；另列待识别、未闭合、冲突和缺失文件，方便核对。
- 导出冻结目录范围与业务版本；生成期间新修正不改变当前文档。表内记录导出时间、范围及档案版本；统计来自同一快照。
- 复用现有双图 Excel 渲染和后台任务，但新增目录数据适配器，不为导出偷偷绑定／切换现场文档，不在每次拍摄或标星时自动生成大 Excel。
- 缺图时保留对应记录并注明缺失；缩略图嵌入且限制尺寸与生成并发。导出失败不回滚已保存的款号或便携档案。

## 9. 与母子文件夹自动整理的衔接

读取来源依次核对：当前数据集有效人工确认与便携业务记录、本机同源已确认记录、图片／XMP 中带业务修订的字段、目录候选。只有同一来源的可比较版本才能判断新旧；两个独立确认不一致，或外部改过文件但无版本关系时列冲突，不能简单用“数据库优先”覆盖。

便携档案恢复完成、身份和 SKU 已确认即可生成整理预览，不等待所有源图内嵌写完。目标仍是 `归档根/母SKU/实际SKU/原文件名`；母子映射优先复用当前规则／映射表。`SKU-A` 的重拍版本身份独立，母 SKU 不靠去掉后缀重新猜。

必须调整当前总拦截，而不是直接删除保护：

1. **准备计划**：冻结数据集业务版本、归属、最终目录文件清单及来源签名。未确认款号、身份冲突、未发布的外机修正或扫描不完整必须明确阻断相关项。
2. **复制归档**：来源已稳定且没有正在执行的写入时，可根据冻结业务数据在目标副本写入并核验元数据。源图还有“排队未开始”的兼容写入不必阻断；先协调这些任务，防止复制时源内容变化。
3. **原地整理**：暂停受影响路径的新写入，等待正在写的文件结束，校验版本；同一来源同时存在另一个整理／写入者时阻断。跨客户端的原地移动必须取得可验证的目录操作所有权，首版仅允许明确交接后的单操作端，不凭不可靠的超时锁接管。
4. **拍摄监控中**：允许便携记录和修正，允许准备只读预览；仍禁止移动正在拍摄的源目录。停止监控后再执行整理，不破坏相机保存路径。
5. **执行与恢复**：保留现有不可变计划和移动日志，更新本机路径、原→新指纹版本及便携路径别名；已完成移动但档案未发布时进入“移动完成、档案同步待恢复”，重启按同一操作 UUID 重放，不重复移动。
6. **随目录携带**：原数据集根保留 `.shiying`；复制到另一归档根时生成该任务实际文件的便携子集，保留来源身份与修订。仅复制某个 SKU 子目录也应有自包含子集，不只留下指向旧 NAS 的绝对路径。
7. **目标一致性**：照片、配套 XMP、目标业务档案全部核验且完成记录发布，才显示完整成功。JPG 写元数据后校验像素与字段，RAW 保持字节不变并校验 XMP；源图有待写任务不等于目标可以漏写。
8. **现有业务规则保留**：预期数量以最终大档实际保留清单为准；后期删片单列追溯，未匹配但仍存在的文件不能当删片。标签优先最终大档，缺失时按现有现场来源补充，产品图与标签数量分开。

多端可并行读取，任意设备取得数据集独占写权限后可修正。业务修改、物理写图与原地移动统一受数据集写权限约束；不再默认允许多端同时逻辑修正。

### 9.1 归档后正确匹配必须维持的约束

目标是“原拍摄目录断开、原客户端缓存清空后，另一台电脑仅加载目标目录，仍能恢复准确归属”。不能仅验证当前电脑归档后仍看得到旧数据。

每个已完成归档文件都必须满足：

1. 可从目标目录随行档案找到唯一文件记录，并校验该记录指向的实际文件；不能有记录但文件缺失，也不能有文件却无归属记录而宣称全部完成。
2. 款号、评级、角色、拍摄类型和分组来自已确认的业务修订；母子目录名仅为展示与定位，不能成为重新分配款号的依据。
3. 永久资产、逻辑文件、区间身份不因盘符、根目录、文件名或元数据补写而改变；位置和字节版本单独登记。
4. 再次导入相同来源与修订幂等复用；同一身份出现不同有效确认时列冲突，不生成另一条貌似全新的拍摄记录来掩盖冲突。
5. 目标档案不依赖源绝对路径、源业务数据库、源作业目录或源网络在线状态。

### 9.2 区分身份、位置与文件版本

| 标识 | 含义 | 归档时的变化 |
| --- | --- | --- |
| `asset_id` | 已验证的同一次快门／照片资产 | 移动、复制及已验证 RAW/JPG 配对保持；不同快门不因同款而共用。 |
| `file_id` | 同一逻辑文件表示，例如原始 JPG 或原始 RAW | 精确复制、改名及本软件元数据补写保持；RAW 与 JPG 各自不同。重新导出／转码产生新 `file_id`，保存 `derived_from_file_id`，且仅在证据充分时关联原资产。 |
| `location_id` | 某数据集内的一个存储副本位置 | 原地移动保持位置记录并更新路径；复制增加新的目标位置，源位置仍存在。 |
| `group_id` | 某次确认的拍摄区间／重拍分组 | 保持；区间成员按 `asset_id` 保存，不能根据归档后目录排序重新划分。 |
| `business_revision` | 款号、评级、区间等业务的确认版本 | 仅在业务修正／撤销时新增；物理移动不会伪造一次新确认。 |
| `file_version` | 某次实际文件内容与配套 XMP 版本 | JPG 补写、XMP 修改或重新生成时变化，记录前后摘要及操作来源。 |
| `dataset_id` | 一个独立可编辑档案范围 | 原地整理保持；新建独立归档数据集时生成新 ID，并保存来源数据集与修订关系。 |

目标可采用如下记录；下列 ID 仅示意，不用于按字面计算身份：

```json
{
  "dataset_id": "archive-dataset-uuid",
  "asset_id": "original-asset-uuid",
  "file_id": "original-jpg-file-uuid",
  "location_id": "target-location-uuid",
  "relative_path": "LC78/LC7877847/IMG_0001.JPG",
  "group_id": "original-group-uuid",
  "business_revision": "decision-uuid",
  "sku": "LC7877847",
  "role": "product",
  "origin": {
    "dataset_id": "shooting-dataset-uuid",
    "relative_path": "IMG_0001.JPG",
    "business_revision": "decision-uuid"
  },
  "archive_operation_id": "archive-operation-uuid"
}
```

原 JPG 与 RAW 的同次快门身份必须按现有 `capture-v2` 及机型字段验证。若目标是此前未登记的 RAW，根据身份确认后登记它自己的 `file_id`，不能把 JPG 的文件 ID 直接写给 RAW。缺失或重复的身份不能强行分配同一个资产。

### 9.3 目标随行档案必须自包含

- 每个归档记录包含完整有效确认、永久身份、冻结分组、目标相对路径、原相对路径、文件/XMP 校验、必要拍摄字段和迁移收据；来源信息用于追溯，正常读取不回源查询。
- JPG 目标内嵌软件命名空间内的资产／文件／分组 ID、SKU、评级、拍摄类型及业务修订；RAW 原件不改字节，相同信息保存在正确配对的 XMP 中。XMP 保留已有调色及未知字段；不能用新侧车覆盖用户编辑。
- 目录档案仍是完整业务恢复依据：内嵌／XMP 是兼容与丢失档案后的辅助恢复，不能承诺只靠几个图片字段恢复全部 OCR 历史、撤销和分组证据。
- 每个可独立携带的范围必须有自己的有效档案。新归档库可采用“上级目录索引 + 各 SKU 子目录自包含数据集”：上级 `.shiying` 仅索引子数据集，不另存一份可编辑的重复权威记录；各子目录中的路径以各自根为基准，例如 `IMG_0001.JPG`。
- 若目标已经是一个有效数据集，则沿用其权威根，不悄悄在内部再建重叠可写数据集。仅单独搬运内部某个 SKU 时，由“复制照片及随行档案”生成新根下的独立子集；软件明确提示普通资源管理器只复制照片无法携带完整记录。
- 独立归档目标／子集分配新的 `dataset_id`，保留原 `asset_id`、`file_id`、`group_id` 与来源版本。两个独立副本的后续人工修正不会自动互相覆盖；重新相遇时依据共同来源和修订关系核对。整体备份可保留数据集 ID，但不能将两个已分叉备份都当作同一个实时写入目录。
- 原二星标签不再存在于目标时，仍保留标签资产、识别原文和确认摘要；按现有规则需要补入的标签照片另作真实文件校验。缺少标签不能导致已确认产品图重新失去归属，也不能虚构标签文件存在。

### 9.4 归档提交协议与中断恢复

照片文件、SQLite、XMP 和 NAS 发布不是天然的一个事务。应通过持久状态机与幂等恢复协调，而不是声称一次 SQLite `COMMIT` 能同时保证所有文件移动。

1. **PREPARED**：取得源和已有目标数据集的写权限，新目标取得独占创建权；多个锁按稳定标识顺序获取，任一失败即释放已取锁。冻结业务版本与实际文件清单，生成唯一操作 ID、目标相对路径及覆盖全部条目的计划摘要。新目标获得 `dataset_id` 后固定映射，不能在中途更换身份。
2. **FILES_VERIFIED**：逐文件复制／移动到受控目标，保存进度。RAW 校验原始字节摘要；JPG 分别记录复制前字节摘要、元数据写入后摘要以及解码像素保持证据；XMP 单独校验。禁止用写入后的 JPG 摘要与未写元数据的源直接判相等。
3. **CATALOG_READY**：生成或更新目标档案，登记目标相对路径、身份、确认与分组，以及逐文件验证收据。目标先有暂存记录，完成前不能当作已确认的新目录导入；已有数据集读者继续使用前一完整版本。
4. **COMMITTED**：目标文件与配套资料回读验证通过，发布引用本次业务版本、文件清单摘要和档案摘要的完成记录；加载端看到完成记录且依赖有效后才接入新内容。NAS 暂时只看到完成记录但缺依赖时继续等待，不当成完成或删除。
5. **RECONCILED**：同步本机目录索引、来源位置别名、原→新指纹链和源端归档收据。此步失败时目标已提交状态不丢失，标为“目标已验证、来源登记待恢复”，以同一操作 ID 补齐，不能再移动／复制一遍。

原地移动会使旧路径在中途消失：写入开始前先发布本次受影响位置的“迁移中”记录，读者对这些位置显示迁移状态而非错误重配；整个操作完成后再切换新路径。迁移中仍可读已有元数据，不承诺旧路径下照片始终可打开。

恢复必须同时核对计划、实际文件、摘要、目标提交和业务版本：未提交且目标不完整时续作；已提交时只补登记；双方内容不一致时停在“需要恢复”，保留实际文件。不存在跨文件系统无条件原子的移动；跨卷操作按复制、验证、提交处理，源文件删除仅在任务明确授权且恢复条件满足时执行。

### 9.5 新客户端的归档后匹配流程

1. 从选定目录发现有效档案，确定权威数据集根／子数据集边界，将当前实际根映射到 `dataset_id`；仅加载已完成提交，迁移中内容单独展示。
2. 将快照和增量应用到本机，在数据集中用 `file_id/location_id` 取出相对路径与确认信息，拼接当前根；优先恢复已确认分组，不能重新按星级遍历推算。
3. 文件与已验证归档版本一致、且身份无矛盾时，直接恢复。全新位置／可疑替换优先核对文件内永久身份和快门字段；归档收据中的完整摘要可进一步验证原样副本。大小、mtime 相同只能作筛查，不是同图证明。
4. 目标经软件改名／整理时按已提交的路径迁移关系定位；经外部改名但未改内容时可在当前授权范围内按已登记内容摘要找到副本；存在可用永久 ID／可靠快门字段时可进一步关联。重复文件记录为多个位置，不任取一个覆盖。
5. 外部重新导出／转码后即使仍是同次快门，也登记新的文件表示和来源关系；无法唯一确认时待复核。同款、同名、相近拍摄时间或相似画面不足以自动关联。
6. 多个档案引用同一个资产时保留各位置，只有具有共同修订链、角色和分组一致时才合并业务投影。发现同一永久 ID 指向不同快门、同一文件出现不同确认或两分叉人工修正时阻断相关项；不把物理路径唯一性当成业务一致性。

### 9.6 再次归档与修改后的版本保护

- 幂等判断使用源 `file_id + 已验证源文件版本 + business_revision + 目标数据集/位置` 和可重放请求键；若目标已有对应收据，还须核对实际文件及字段有效，满足后才跳过。
- 相同图片和相同修订重复执行复用原位置、确认及分组，不重复占用重拍后缀；目标同名但内容或身份不同不得覆盖，可按已确认规则稳定改名，并同步 RAW/XMP 与路径映射。
- 源端产生新的 SKU 修订时，不能因为照片已经归档而直接跳过。目标没有独立修改、来源链连续且得到当前操作授权时，展示新旧款及需要迁移的目录后执行；目标已有另一人工修订时复核，不按修改时间自动覆盖。
- 归档后用户在目标直接修正 SKU／评级，形成目标数据集的新业务修订并补写目标元数据。原现场记录仅保留来源；旧客户端的待写任务必须核对其数据集、文件位置、基线与修订，不能根据旧款号把目标改回去。
- 归档源已删除／离线不影响目标读取。正常再次归档以当前可用目标档案和实际文件为依据；只有任务需要原始文件且目标不足时才明确要求补源。

### 9.7 无法自动恢复时的边界与状态

界面区分“身份及归属已验证”“位置待更新”“文件已变化待核验”“身份／款号冲突”“归档未提交／待恢复”。只有前者可自动进入完整归档；其它状态保留已知资料，不猜配、不悄悄清空。

照片仍在但 `.shiying` 丢失时，可从已完成内嵌／XMP 中恢复可证明的字段，并标记历史记录不完整；两者都丢失、相机身份也不足时，无法保证恢复原款，需重新 OCR／人工确认。方案保证的前提是有效随行档案或足够的已验证身份与业务证据仍存在，不承诺破坏所有证据后仍能准确找回。

技术边界参考：[SQLite 事务提交说明](https://www.sqlite.org/atomiccommit.html)、[网络文件系统一致性与锁限制](https://www.sqlite.org/useovernet.html)。本方案中的跨文件恢复协议是拟新增应用逻辑，不是 SQLite 自动提供的能力。

### 9.8 强制文件级 SKU 冗余及无档案重建

#### 写入位置与时机

| 文件范围 | 必需的持久位置 | 完成条件 |
| --- | --- | --- |
| 现场小档 JPG／JPEG | 图片内嵌 XMP，沿用既有 `XMP-fk` 命名空间；标准关键词保留 `SKU:实际款号` 作为兼容搜索入口 | 整款确认后自动进入高优先级持久写队列；每张产品图及标签图独立写入、读回一致。不能只写标签或代表图。 |
| 现场若包含 RAW | RAW 同目录配套 XMP，保持 RAW 字节不变 | 原 RAW／XMP 身份及必要字段配对读回通过。 |
| 归档目标 JPG／JPEG | 目标图片内嵌 XMP，不能只更新目录档案 | 写入归档冻结的有效业务修订并完成像素保持、字段读回与实际目标位置核对。 |
| 归档目标 RAW | 目标 RAW 旁的 XMP，不能放入可独立丢失的 `.shiying` 目录中 | RAW 字节校验和 XMP 配对、字段验证均通过；复制／改名时一起处理。 |

保持此前 JPG 内嵌、RAW 使用 XMP 的格式策略，不因丢失便携档案而改写 RAW 原件。已有 RAW 使用同名主干 `.xmp` 时优先沿用、合并保护用户字段；同主干多个 RAW 造成配对歧义必须阻断复核。兼容既有 `IMG_0001.CR3.xmp` 读取方式，但其第三方软件兼容性需单列验证，不能静默改名破坏现有配对。

“同步写入”定义为：每次确认、改款、改星、撤销及有效范围变化都可靠生成对应文件任务并自动执行，确保最终一致；不要求阻塞现场界面等整目录大文件写完。为保留即时操作速度，前台先显示已保存和写入进度，但不能把入队成功当作文件写入成功。RAW 与 JPG 各自独立落盘，不依赖另一种格式存在才能恢复。

#### 每张图片／XMP 必须携带的恢复字段

以下为字段契约；沿用已有物理标签并扩展缺少项，不建立另一套与现有命名空间冲突的自定义字段：

| 语义 | 现有标签／拟扩展标签 | 用途 |
| --- | --- | --- |
| 永久资产与文件身份 | 已有 `AssetId`、`FileId` | 改路径后恢复同图、区分 RAW/JPG 文件表示。 |
| 实际生效 SKU | 已有 `SKU` | 正式 SKU 搜索与图库分组；`SKU-A` 必须保存完整值，不退回原 SKU。 |
| 原款、母款、重拍版本 | 拟扩展 `BaseSKU`、`ParentSKU`、`ShootVersion` | 恢复母子映射与稳定后缀，避免重新占号。 |
| 分组身份 | 已有 `SegmentId` 对应本方案 `group_id` | 从文件直接恢复原区间；同 SKU 不同区间不误合并。 |
| 作用域与组完整性 | 拟扩展 `CatalogScopeId`、`Customer`、`Brand`、`GroupRevision`、`GroupProductCount`、`GroupLabelCount`、`GroupMembersDigest`、`GroupManifestScopeId` | 恢复客户／品牌范围和明确子集的组完整性依据；未记录时显示未知，不以当前扫描数量冒充原组总量。 |
| 角色、类型、日期 | 拟扩展 `PhotoRole`、`ShootDate`；已有 `ShootType` | 区分标签和产品，恢复拍摄类型、日期及正确统计。 |
| 确认状态与修订 | 已有 `MetadataRevision`；拟扩展 `AssignmentState`、`DecisionId`、`DecisionParents`、`DecisionSourceId`、`MetadataSchemaVersion` | 识别确认／清除、修订来源及可比较继承关系，防止旧写任务恢复已撤销 SKU。已有数字 revision 不能单独比较不同客户端／数据集的新旧。 |
| 明确人工评级 | 标准 `XMP-xmp:Rating`，含明确零星 | 重建有效星级，不能因为值为 0 就忽略。 |
| 兼容关键词 | 标准 `XMP-dc:Subject` 的受管 `SKU:...`、`ShootType:...`；沿用既有 Windows 属性字段 | 通用关键字检索；修改 SKU 时移除旧受管词，保留用户其它关键词。 |

原始相机身份字段保持，软件新增字段不覆盖相机原始 EXIF。完整 OCR 原文与审计历史可继续由便携档案保存；基本 SKU 搜索与正确图库展示不得依赖 OCR 作业、候选记录或原现场文档存在。字段值限制长度、验证格式，新增标签必须同步扩展 `metadata_writer.py` 中的 ExifTool 配置、读写字段清单和写后验证；只有写了 JSON 而读写器未支持不算实现。

#### 丢失便携档案后的恢复流水线

1. 新客户端发现 `.shiying` 不存在／不可用时，仍正常增量扫描照片及同目录 XMP，按批读取业务字段。界面标识“从文件元数据恢复”，不要求导入源缓存库，也不自动重新 OCR。
2. 文件内明确的有效 `SKU` 和确认状态形成 `file_metadata` 来源证据；只有标准关键词且唯一有效 SKU 时按兼容规则恢复并标注证据等级。多 SKU、内嵌与 XMP 不同且无可验证版本关系时进入复核，不任取第一个关键词。
3. 把证据恢复到本机资产归属与评级表，再通过统一数据源接入 SKU 库的持久查询投影，主动使搜索索引、款号列表、图片网格、数量及封面失效重建；不能只让资产归档搜索得到、SKU 数据库仍为空。
4. 源码已能从 `XMP-fk:SKU` 或唯一 `SKU:` 关键词更新资产索引，但当前 `sku_library.py`／`sku_library_index.py` 主要依赖 OCR、拍摄及资产关联。因此须新增可持久去重的“文件元数据证据”来源，并提供照片引用适配；不能伪造 `jobs/ocr_choices` 或绑定现场相机来强行显示。
5. SKU 库按实际 SKU 展示照片，并保留 `SegmentId`、角色与日期以恢复独立分组；RAW/JPG 保留各文件位置，按现有显示规则配对，产品数量按资产去重，标签独立计数。只有文件字段能证明的信息才恢复；缺少标签图片时显示缺失，不生成不存在的预览。
6. 直接从当前实际路径生成本机相对路径与位置记录；永久资产／文件 ID 保持。若文件没有数据集根描述，读取时可用本机临时范围映射；取得写权限并显式补建档案时才建立新数据集 ID，不反向更换文件的资产身份。
7. 后续找到原便携档案时，以永久身份、决策 ID／来源链核对并幂等合并；相同确认只保留一次投影。字段恢复证据不是一次新的人工决定，不能凭恢复时间覆盖原有更高版本或人工冲突。

#### 完成状态与可保证的恢复范围

- 状态分别计数“业务已保存”“文件夹档案已同步”“文件元数据已验证 N/M”。整款 M 包括实际应处理的每个 JPG、RAW 配套 XMP 和标签，不因首张成功而标记整款成功。
- 现场新确认／修正后，只有 N=M 且对应当前业务修订，才标记“可脱离便携档案恢复”。有新修订未写完时立即撤销该完成标记，显示仍有多少文件待更新。
- 归档的最终完整成功要求目标所有预期文件／XMP 的当前修订写入读回通过，且目录档案完成发布。失败项保留错误、支持按文件重试；源小档尚待写不影响读取便携信息，但不能冒充源小档也已具备独立恢复能力。
- `.shiying` 全部丢失后，只要 JPG 内嵌或 RAW 配套 XMP 的已验证字段仍在，就必须可以重建所述 SKU 搜索与图库。读回验证后的更改、源目录离线、路径改变都纳入恢复验收。
- 如果最新修订仍在队列中，且本机记录与便携档案此时同时丢失，只能恢复文件中最后已经写入的版本；不能保证找回尚未写进任何存活介质的新值。RAW 原件不写业务字段的策略下，若其 XMP 也丢失且没有其它身份关联证据，同样不能声称保证 SKU 恢复。
- `.shiying` 和 XMP 都属于业务资料，不进入日常缓存清理。此设计提供丢失后的冗余恢复能力，不将用户提出的故障场景解释为授权清理这些资料。

技术格式参考：[Adobe XMP 规范](https://developer.adobe.com/xmp/docs/xmp-specifications/)、[ExifTool 自定义字段配置](https://github.com/exiftool/exiftool/blob/master/config_files/example.config)。

## 10. 旧数据迁移与兼容

- 新拍摄默认维护随行档案；旧已登记目录通过“生成／补齐文件夹档案”按选定范围从现有库恢复，不遍历导出全部缓存库。自动生成只写已确认事实，待识别内容保持待识别。
- 旧目录只有照片、无可读软件记录且元数据未写入时，无法凭空恢复款号；通过二星 OCR 或手工确认补齐，再生成档案。
- 已有现场作业和区间优先按永久身份关联，归档视图创建来源适配上下文，不能把当前现场绑定切换成归档目录。
- 新档案来源进入现有归档来源枚举时，必须同时检查搜索、清单、导出、冲突处理和进度统计调用方；不能只补一个 SKU 显示字段。
- 局域网实时同步与随行档案使用同一永久身份、操作来源和幂等键；同一修改从两路到达只应用一次。当前接收模式的只读约束继续有效，不能被归档修正入口绕过。
- 版本升级只新增表／适配器与兼容读取，不批量重写旧照片，不自动启动原来已取消的 OCR 或元数据任务。

## 12. 必须验证的验收场景

1. 归档目录含产品图 1–3、二星标签 A、产品图 4–5、二星标签 B；得到两个区间，产品数量分别 3 和 2，标签独立计数。
2. 中途补打边界、清零、改三星、再次二星以及识别结果乱序返回；旧款号不复活，邻段受影响内容可复核，重拍后缀不串组。
3. 搜索只显示部分照片、分页、逆序浏览、不同相机、同名跨子目录、跨日和迟到照片均不改变已确认成员。
4. 人为暂停图片元数据写入；确认两款并等待文件夹档案同步，关闭客户端 A；全新资料目录的客户端 B 仅添加 NAS 路径，能恢复全部已发布业务信息、导出及准备整理。
5. A 正在编辑时 B 能读取、搜索和导出，但无法改星、改款或启动整理；两个端同时申请编辑只能一个取得句柄。A 正常交接或崩溃且 SMB 已释放后 B 才能取得权限；旧 OCR 回调、旧队列与离线草稿不能覆盖 B 的新版本。不同数据集可分别编辑；实际 SMB 断网重连和服务端恢复不得双写。
6. 盘符改 UNC、根目录重命名、JPG/RAW 同次快门配对、同名替换、相机身份缺失、后期 JPG 丢失 MakerNotes；只有证据充分时自动关联。
7. 标星提交后崩溃、事件写一半、完成记录先可见、快照缺失／损坏、断网、只读共享、NAS 重启；无假成功、无静默回退覆盖、无重复确认。
8. 正在写入源图时整理被保护；仅排队未写任务按协调结果处理；现场监控中不能移动源目录。恢复后照片、XMP、业务档案及指纹链保持一致。
9. 原地整理到母子目录，再把一个 SKU 连同其便携子集复制到独立根；第三客户端不依赖源 NAS 仍可正确恢复和导出。
10. 导出 `文件夹_拍摄日期.xlsx`，验证多日范围、同名不覆盖、原款／实际款、双图、缺图、待处理与逐文件状态，统计符合冻结版本。
11. 与已有局域网同步同时收到同一操作，幂等不重复占号；接收只读模式不被新增接口绕过。
12. 使用 1 万与 10 万照片的隔离清单验证增量加载和 NAS 访问次数；记录两星本机保存、远端可见、跨机首屏 P50/P95 及档案体积。初始目标分别为 200ms、2 秒、3 秒（已生成快照、局域网正常且不含 OCR 推理），仅作为待测目标；首次补齐 EXIF、整库扫描与真实模型耗时另列。
13. 归档成功后断开原拍摄 NAS，使用全新资料目录／第三台客户端，仅加载目标；产品、标签、评级、分组、原 SKU／实际 SKU、OCR 与元数据状态均能恢复。先检查本机库中没有源数据，防止测试误用旧缓存。
14. 归档前后及第三端重载逐项对比永久资产／文件／分组身份、业务修订、成员集合及数量；原地整理保持身份，复制增加位置，RAW/JPG 文件 ID 不混用，后期导出新增文件表示。
15. 目标根由映射盘换成 UNC、整体改名，再用软件改名文件、外部原样改名文件及同名替换文件；前两种按根映射／迁移恢复，外部改名按唯一证据恢复，同名替换不能误继承。
16. 在 PREPARED、文件复制中、元数据补写后、CATALOG_READY、COMMITTED 及来源登记前分别中断；重启只能续作或补登记，不能虚报成功、重复重拍占号或使旧路径覆盖新路径。
17. 同一个目标连续归档两次、目标内容被改后重试、源改 SKU 后再归档、目标另行改 SKU 后旧源重连；分别验证幂等跳过、变化复核、版本迁移与人工分叉保护。
18. 单独复制一个 SKU 的自包含数据集到独立目录，断开原归档根后重载；相对路径以新根为准，不重复拼接母子目录、不访问源绝对路径。只复制图片而漏掉业务档案时显示恢复能力限制。
