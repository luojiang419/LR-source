## 目标与验收

- 选片页二星解析、正确确认并入库拍摄进度后，整款 JPG 自动写入内嵌 SKU，RAW 使用同名 XMP；不把数据库入库当成文件写入成功。
- JPG 的 Windows “属性 → 详细信息”通过“主题”和“标记”可见款号；保留用户其他标记、相机信息、星级和像素。
- 选片页及拍摄清单改号同步覆盖当前款新 SKU，旧 SKU 标记移除，不误改相邻款。
- 写入任务完成后回读实际文件；失败可见、可重试。已有确认区间缺少操作或文件任务时自动修复，避免单靠已入库状态跳过。
- 使用隔离真实 JPG/RAW/XMP 和 Windows Shell 属性读取验证，不修改用户提供的源图片。

## 已发现的代码缺口

- `metadata_writer.py` 当前仅写自定义 XMP-fk:SKU 和 XMP-dc:Subject，Windows 属性处理器未必展示自定义命名空间；没有专门写 XPSubject/XPKeywords。
- `_queue_confirmed_interval(..., only_missing=True)` 仅检查同 SKU 区间存在，未要求实际写入操作或任务存在，可能把归档记录当作补写已经完成。
- 原选片提示区分“已提交/排队”，但缺少随当前照片读取的持久 SKU 文件状态；拍摄清单改号的空批次存在无条件“全部完成”提示。

## 最终实现

- JPG 写 `XMP-fk:SKU`、标准 XMP 关键词及 `XPSubject` / `XPKeywords`；改号移除旧 SKU 标记，保留其他标记，撤销恢复 XP 原值。
- 已确认二星的恢复检查要求实际操作存在，补漏掉的文件任务，描述/标题任务不能冒充 SKU 写入。当前现场旧版私有 XMP 的已成功任务会补齐 Windows 属性，保留原字段撤销基线。
- `process_one` 实际提交主文件与已有侧车之后再回读 SKU、备案字段、星级和 XP 属性，通过才记 applied。选片和拍摄进度按当前资产 revision 显示已写/待写/失败，可重试，旧款号已成功不覆盖新款号待写状态。
- 新增 XP 字段会使用户实际 JPG 的 `IFD1:ThumbnailOffset` 移动；对缩略图原始字节完整校验后才接受指针变化。注入缩略图内容变化会拒绝提交；原像素及相机字段保护保留。
- 匹配 JPG/RAW 不依赖每张 JPG 都有 XMP；继续使用型号、序列号、拍摄时间/子秒及图像身份判断。JPG 内嵌，已有 JPG XMP 同步；RAW 后拷可靠匹配后创建同名 XMP。用户询问是否全部建 XMP，已说明当前无需为匹配扩大为所有 JPG 生成侧车。
- 已登记 RAW 的改款通知和持久队列保留；跨机仍需导出/导入 SKU 元数据库，共享图片目录不会共享数据库。不声称 Windows 原生属性会读取任意 RAW 的外部 XMP。
