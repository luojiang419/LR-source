## 交付边界

本轮落实全局资产库的百万记录检索和 Everything 文件路径辅助搜索，不把当前 `/api/state` 一次加载整个拍摄会话冒充百万级工作台。生产照片及评级不用于造数、不修改；基准只在 build 隔离库运行。Everything 仅通过公开 SDK/IPC 查询，不打开 Everything.db，不依据文件名自动合并资产或写原片。

## 验收

1. SKU 精确/前缀及项目/拍摄类型过滤走索引；稳定复合游标翻页，不强制全量 COUNT，不逐条查询关联。
2. Everything 进程超时/不可用可降级已备案路径，响应标明来源及不完整性；返回新路径候选须另行验证资产身份。
3. 页面可使用新检索与独立文件搜索；真实浏览器验证，合成百万资产计时明确数据结构、冷热条件、P50/P95/P99和限制。
4. 原有区间/元数据/RAW 补写必要回归通过；本地提交，方案及结果写在本文件。

## 存储与检索分工

继续使用已有 SQLite WAL 单机数据库，避免仅因记录达到百万就增加数据库服务。百万行不是 SQLite 的容量上限，关键是查询路径、行体积、写入并发和 IO。当前本机基准已经验证本轮结构；多人同时写入、跨主机集中协作、持续写入积压时再评估 PostgreSQL，不把 SQLite 文件共享到 NAS 供多台机器同时写入。

| 数据层 | 权威内容 | 本轮处理 |
| --- | --- | --- |
| framekeep.sqlite3 | 拍摄目录、现场顺序、人工星级 | 保持现场行为，未改造成全局百万列表 |
| asset_archive.sqlite3 | 资产 UUID、文件 UUID/版本哈希、SKU、项目、细节/模特类型、路径、归属历史、可恢复写入与 RAW 补写任务 | 新增复合索引/反向关联索引，提供独立全局分页检索 |
| vision_analysis.sqlite3 | 模型/方案版本、JSON 解析结果、原始响应与任务状态 | 新增队列、近期任务、按资产查结果的索引；保留原始 JSON，不盲目为未知维度增加列 |
| sku.sqlite3 | Excel 项目、工作表、款号、拍摄对账 | 仍按工作表隔离；OCR 只能在当前拍摄页候选中匹配 |
| Everything 索引 | Everything 已覆盖的文件名与路径 | 官方 SDK/IPC 只读查询，结果和业务库 locations 关联；不解析其私有数据库、不假设能查自定义 XMP SKU |

资产身份由 UUID 与版本证据确认；路径只是位置，同一资产允许多组件、多副本。检索不扫描文件、不读 EXIF、不解 RAW、不现场 hash。跨目录查询后，只有显式重新定位/备案流程才读取元数据和核对哈希；Everything 的名字/路径命中不能触发静默合并或写原片。已登记的路径匹配也标为 `identity_verified=false`，不代表该路径当前内容已重新核验。界面 online/offline 是历史登记状态，不是每次查询的磁盘探测结果。

## 已实现的检索路径

- `asset_search.py`：规范化沿用 `sku_match.normalize`（NFKC、ASCII 字母数字、大写；显示 SKU 保留原文）。精确用 `normalized=?`；前缀用 BINARY 范围上下界，不走 `%词%`。非空但没有字母/数字的款号拒绝搜索，避免意外变为全库查询。
- 项目/拍摄类型是精确条件，以 `(project,scope,normalized,created,id)` 及相应子组合索引适配。细节图查询不会因为文字包含而误入模特图。排序为 SKU、created、id 全降序，复合键使相同时间也能稳定分页。
- `GET /api/assets/search?sku=&scope=&project=&mode=prefix|exact&cursor=` 返回最多 60 项、`has_more`、`next_cursor`，不强制 COUNT。最多保留 100 项的内部调用上限，查询预算 1 秒。游标绑定筛选条件，变更条件必须从第一页开始；实时修改 SKU 后结果自然变化，不提供跨请求快照导出语义。
- 位置与目录链接一次批量获取，新增 `files(asset)`、`locations(file)`、`catalog_links(asset,session,capture)`，消除每项单独关联。单页位置子项最多 2000 个，超限返回 `locations_truncated`；详情单独读取。只绘制当前 60 行，缩略图使用懒加载，不在首屏等待所有预览。
- 原 `/api/assets?...offset=` 为已有调用兼容而保留，仍有精确 COUNT/包含匹配，不能作为百万检索入口。正式归档页面已全部切换新接口。
- 资产元数据队列、区间/近期记录、视觉队列/结果、RAW 状态查询增加对应索引。`relocate()` 不再遍历全库路径做 `is_file()`；本轮重定位仍是指定子目录的身份扫描，不是全盘百万后台扫描器。

## Everything 接入和降级

1. 本机 Everything **1.4.1.1032**；官方 SDK 来自 `https://www.voidtools.com/Everything-SDK.zip`，源码附 MIT 许可。安装脚本锁定 archive SHA-256 `f5716d9513cce6b462b5170a0a2e7e081e191d9bcac6774f5decc061497df443`，只下载 SDK，不修改用户 Everything 配置。
2. `setup_everything.py` 放入 `.runtime/everything/Everything64.dll`、`Everything32.dll` 与 `LICENSE-SDK.txt`；构建复制到便携包 `runtime/everything/`，无许可证不打包。没有组件时可使用业务库，不是必须安装的硬依赖。
3. 每次实际 SDK 查询放在独立隐藏子进程。SDK 使用全局可变请求状态，主服务通过互斥门只放行一路，避免并发串查询；子进程隔离避免 DLL 的同步 IPC 挂起主服务。父进程设置 **1.5 秒超时**，超时终止并回收子进程。状态探测缓存 10 秒，查询结果不做长时缓存。
4. `GET /api/search/status` 返回能力；`GET /api/search/files?q=&offset=` 返回路径、已备案资产、来源、覆盖范围、耗时和更多页标记。只允许字面文件名/路径，拒绝引号、控制符、通配及表达式组合；程序附加图片/RAW 扩展名条件。每页 60 路径，最多翻至 offset=10000，深处应缩小条件。
5. Everything 不可用、初始化未完成、IPC 权限隔离、繁忙或超时，回退本机 locations；回退包含匹配仅有 **250 ms 扫描预算**，超预算明确 `incomplete=true`。离线后端最坏可包含 1.5 秒超时加回退时间，因此不承诺任何条件都低于一秒。正常 Everything 结果只表示它的索引覆盖，未索引目录、NAS、离线磁盘和刚改名文件存在漏项/陈旧可能。
6. 新位置展示“未备案候选”，由现有“扫描并重新定位”核验 XMP FileId/AssetId、版本哈希；改名后仍可找回正确资产。不会根据相同 IMG 编号把不同相机、日期或产品自动串款。

## 后续 OCR/视觉搜索投影设计（维度确认后实施）

本轮没有对未知解析维度做全文/向量实现。建议增加**可重建搜索库** `asset_search.sqlite3`，与资产权威库和模型原始响应分开，避免搜索索引膨胀影响现场写入：

- 热文档保存 `asset_id, metadata_revision, schema_id, schema_version, sku, project, scope, rating, ocr_text, keywords, updated`；只把选定字段投影，历史大 JSON、base64 和图像绝不复制进去。动态属性采用方案白名单/类型验证；确定需要过滤的字段建类型化投影，不对任意 JSON path 建无限索引。
- OCR 全文可选 FTS5：英文/数字分词索引与中文 trigram 分路；启动时检测实际 SQLite FTS 能力。中文/子串少于三个字符不走 trigram 全库模糊扫描，提示加长或结合项目/类型缩小范围。全文结果先取有限候选 ID，再与资产库批量关联，不把海量 ID 拼入 SQL。
- 手写 SKU 模糊匹配继续沿用 012 的混淆字符加权距离（0/O、1/I/L 等），但应先用当前工作表+前缀/长度/字符片段索引产生有限候选，再最多比较 100–300 款；不对百万图片执行逐条编辑距离。精确 SKU 优先，模糊置信度和第二名差距不足时人工确认；不把近似匹配当权威归属。
- 在**各自源数据库事务内**写 outbox（event_id、asset_id、revision、变更类型），搜索 worker 按修订号幂等处理，支持更新/撤销/删除 tombstone，记录各库水位。失败保留事件重试，前端显示索引水位/延迟；整库重建用新文件构建完成再原子切换，禁止边清空边服务。
- 文件搬移不能仅靠 Everything 推断稳定身份。维护后台小批候选核验队列、目录/卷覆盖信息，扫描断点可恢复；同一卷可后续对接 USN/变更日志，异卷/网络目录走有边界的增量扫描。Everything 继续只提供位置候选。
- 语义相似图/自然语言检索如需要再建向量索引（明确 embedding 模型版本、维度和重建成本）；“SKU 精确查找”不应先经大模型网络调用。

## 容量、写入与恢复

本轮实测 100 万 assets、200 万 files、200 万 locations、100 万 links（六百万业务行）与索引，主库 **1,242,472,448 字节，约 1.24 GB / 1.16 GiB**。包含 SHA-256 文本、较短合成路径和基本元数据，**不包含**大量归属历史、原始 AI 响应、缩略图和 RAW 写入备份。

容量按真实长度另算：每资产 2 KB 搜索文档约 2 GB，5–20 KB AI 响应约 5–20 GB，再加索引/历史与数据库维护空间。每张 50 KB 缩略图，百万张就约 50 GB；应延迟生成并设置可重建 LRU 缓存容量。原片必须放业务数据库之外。尤其 RAW 安全写入备份会接近原片大小，不能当普通缓存静默删除；应另定用户确认的保留/外部备份策略。

保持 WAL、短事务、小批写入和现有持久化任务；写入可以排队，检索不能等待 OCR 或 RAW 校验。SQLite 仍是单写者，定期在后台检查 WAL checkpoint、碎片与索引统计；大量导入后运行 `PRAGMA optimize`/必要的统计更新，不每次查询全库 ANALYZE 或 VACUUM。索引首次迁移可能暂时占用时间和临时磁盘，先备份并预留空间；不要声称百万既有库首次启动迁移也瞬时完成。

备份使用 SQLite backup API；多个库间的恢复水位与 outbox 需要一起保留，不能在线复制单个 .sqlite3 而漏掉 WAL。至少预留数据库维护副本空间及 RAW 最大工作文件/备份空间；仅当权威数据和版本证据一致时重建搜索投影。多人/多机版本应把 asset_id 和服务 API 保持稳定，再把权威存储迁移 PostgreSQL，客户端不直接连远程 DB。

## 可复现验证与实测

运行 `python -X utf8 选片助手/benchmark_asset_search.py`，只向 `build/asset-search-benchmark` 造数，已有库则拒绝覆盖。固定种子，100000 种 SKU、10 个项目、细节/模特两种类型、两组件、两位置。生成和索引统计约 **66.41 秒**，`quick_check=ok`。每次查询新建 SQLite 连接，**OS 文件缓存没有清空**；首调用不等于冷盘验收，查询不含图像读取。

| 场景 | P50 ms | P95 ms | P99 ms |
| --- | ---: | ---: | ---: |
| SKU 精确 | 1.377 | 1.766 | 1.880 |
| 宽 SKU 前缀首屏 | 2.077 | 2.639 | 3.696 |
| 项目+拍摄类型 | 2.149 | 3.027 | 3.328 |
| 无条件资产首屏 | 1.834 | 2.152 | 2.244 |
| 无匹配 SKU | 1.175 | 1.662 | 2.149 |
| 跨越约 90% 数据的游标 | 2.163 | 3.217 | 5.248 |

每组后 100 次统计，另记录第一次请求；宽前缀 max 32.56 ms，未用平均值隐藏尾延迟。EXPLAIN 确认精确、项目/类型、深游标均使用对应索引，不产生排序临时 B-tree。记录在 `build/asset-search-benchmark/result.json`。

最终 PyInstaller 引擎访问同一百万隔离库，HTTP+JSON、每页60项、50次：**P50 4.646 ms，P95 28.266 ms，max 32.226 ms**；真实 Everything 查60项 **368.72 ms**，正式部署后 **377.03 ms**。不是用 mock 时延冒充真实 SDK。最终包另在小型真实 JPEG 目录用 Chrome 验证预览加载、真实 Everything 返回、无页面脚本异常；截图已人工查看。

相关测试分批覆盖共26项：asset_search 6、已有资产区间/写入/撤销与视觉/RAW 回归19（含已有浏览器1）、新增浏览器1。首轮唯一错误为新 fixture 手填 normalized 含中文而既有规则只保留字母数字，已改用同一 normalize 并复测6项全通过。游标同时间不重不漏、条件绑定、类型精确隔离、上限/索引、搜索不探测磁盘、SDK超时回退、路径大小写关联均有验证。

新浏览器用稳定 mock 验证分页、未知候选及 Everything 退出后的回退；真实 SDK与最终引擎单独验证。证据在 `build/search-acceptance/`：`search-browser.png`、`packaged-search.png`、`packaged-result.json`。冷盘/网络盘、满载持续写入、OCR全文和百万缩略图首屏没有测试，不宣称通过。
