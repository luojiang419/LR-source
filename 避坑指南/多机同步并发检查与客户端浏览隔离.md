# 多机同步并发检查与客户端浏览隔离

## 表现与根因

- 多台客户端共用IP时，若成功登录也计入失败次数，会在第11次连接时被429拦截。
- 按令牌登记而不按设备替换，会留下同一机器的多个会话；只有“全部断开”无法管理单台客户端。
- 全量复制来源会话的浏览字段，并在每次业务变化时重新loadSession，会使客户端回到主机选中项或首张，丢失布局与滚动位置。仅缓存小图无法修复定位。
- Windows Python3.12的`time.monotonic()`基于GetTickCount64，精度15.625毫秒。用“检查结束时间>=请求开始时间”合并并发时，同一计时刻内真正先后发生的请求也会被合并，漏掉刚写入的XMP；日志打印带来的延时可能使问题暂时消失。

## 处理与验证

成功鉴权不消耗失败次数，同设备重连替换令牌并提供逐台撤销；仍保留错误密码限流。主机共享短时检查结果、固定清单修订及历史文件映射，接收端复用已校验文件。并发合并使用高精度`time.perf_counter()`，快照前后文件签名不一致时下一轮必须复核。

业务字段由主机同步，客户端本地浏览字段在数据投影时保留。前端按本地选中项获取当前批次，刷新记录而不重装整段会话，并保留滚动位置；请求期间用户换图时丢弃该次界面更新，下一轮重试。
