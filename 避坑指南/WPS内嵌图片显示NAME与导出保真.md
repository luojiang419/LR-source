# WPS 内嵌图片显示 #NAME? 与导出保真

## 表现与根因

2026-10-20，用户 `100拍图10.19.xlsx` 在腾讯文档有图片，通用预览却显示 `#NAME?`。源文件的图片列使用 `_xlfn.DISPIMG("ID_...",1)`，缓存也为 DISPIMG 文本，图像 ID 对应 `xl/cellimages.xml` 及其关系文件，二进制图片在 `xl/media/`。渲染器不认识函数，与图片资源丢失是两类问题。

## 已采用的处理

- `sku_workbook.py` 仅解析 DISPIMG 的图片 ID，不执行表格公式，按 `cellimages.xml → r:embed → cellimages.xml.rels → xl/media` 读取位图；也支持标准 drawing 的单/双单元格锚点。
- `sku_service.py` 把图片映射保存到任务 metadata，旧任务首次读取自动补索引。公开 URL 只传已知行 ID 和图片序号，由后端定位受管源件；拒绝任意文件路径、外链和非位图资源。
- 对账界面直接显示图片并支持放大；只读表格预览也直接使用图片资源，避免依赖不支持的公式计算。
- 状态导出只增量修改两份 sheet XML；保留原单元格、公式、cellimages、关系和媒体部件。不能为了修预览重新构建整表，也不能用空值覆盖原公式后宣称无损。

## 验证证据

该表 49 + 36 个款号行共 85 个图片引用，引用了 67 个不同媒体文件；原包共有 68 个媒体文件，未引用部件也保留。85 行图片实际读取和浏览器加载成功。源件 SHA-256 为 `85a4d2385737282069ad9fbf93891628e78f9b7e42427f5d5bb6249c9b3ca86d`，导入导出后未变；导出仅两份工作表 XML 内容变化，其余包部件逐项相同，原有单元格 XML 逐项相同。

这解决末帧和自有预览显示；普通 Excel 是否支持原 DISPIMG 取决于版本。需要跨软件通用文件时，应另做可选的标准浮动图兼容副本并单独验收，而不是改写用户原件。
