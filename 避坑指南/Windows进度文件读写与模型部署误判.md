# Windows 进度文件读写与模型部署误判

## 表现与根因

完整模型准备过程中，冻结引擎持续写进度 JSON，安装器和验收程序同时读取。真实安装出现 `WinError 5`：临时文件替换进度文件被拒绝，随后事务误判组件准备失败并回滚程序。

Windows 上读取文件的句柄若未允许 `FILE_SHARE_DELETE`，即使 JSON 写入使用临时文件和 `os.replace`，也可能遇到短暂替换冲突。问题出在进度通信，不能据此认定模型损坏或强制重新下载。

## 解决方法

- 组件 JSON 使用唯一临时文件，只针对 `PermissionError` 短暂重试，结束清理自己的临时文件；其他异常保持明确错误。
- 模型准备进度按状态变化或 200 毫秒节流，降低读写竞争；冻结的 windowed 引擎通过状态文件通信，不依赖可能为 `None` 的 stdout。
- 模型逐文件校验和已完成记录独立持久化；程序回滚保留模型，重试复用。首次回滚留下的空目录允许再次安装，但未知文件和链接仍拒绝。
- 验收时“手动 OCR”应设为手动模式但保持未暂停。误设 `paused=True` 会返回“OCR 队列已暂停”，不应把它归因于运行时或模型缺失。

## 验证

故障注入覆盖读句柄短暂占用后的重试和临时文件清理；实际安装、重启、768 个程序载荷哈希和真实 OCR 均通过。最终安装后读取 LCJ81166，再导入文档开启全自动 OCR，零星照片自动入库，图像像素及星级保持。证据为 `build/complete-install/final-native-result.json`；缺少 NVIDIA 环境的独立 CPU 推理也已通过，结果 `cpu-result.json`。
