# 归档刷新空白与预览连接阻塞

- 表现：右键刷新后目录树空白，界面误报尚未添加；数据库 roots 记录仍存在、removed=0，单独访问归档接口能返回根目录。
- 根因：只读 API 无谓等待完整会话和写入令牌；目录树又通过 Promise.all 等待素材、统计和参考进度全部成功。刷新时拍摄页图片及邻图预取还会竞争有限的同源 HTTP 连接，使问题在慢 NAS 上更明显。
- 解决：GET 直接读取、POST 继续校验凭证；目录结果独立显示，其他数据失败保留目录并明确提示；页面初始化先让脚本完成，隐藏拍摄页取消图片及预取，返回时恢复，后台解码队列保持持久化。
- 验证：连续空白右键+刷新、慢参考接口、会话/列表/统计失败、数据库重开和令牌写入；使用实际冻结引擎无资源替换验证，目录保留、移出请求为 0、源照片哈希不变。见任务 107 和 `test_archive_refresh_browser.py`。
- 排查时先确认数据库路径及 removed 状态，避免把界面加载失败误认为数据被删除；不要以禁用右键刷新、重建库或清空缓存代替修复。

## 2026-11-10：后端缓存完成不等于浏览器已经预取

只对 `IntersectionObserver` 的120px边缘发图片请求，再把下一页请求绑在滚动事件上，会让已生成的缩略图仍在首次滚到时等待HTTP读取。进入目录后应自动逐页取回图片，并给每批完成信号；不能只扩大观察范围或预取首120项。

当前方案共享图片调度器，首屏优先、总四路、纯后台最多两路；使用当前页真实图片节点，后续页只保留一页临时Image对象，完成后释放，不批量挂载整目录卡片。后续滚动时沿用相同图片URL以命中浏览器HTTP缓存，目录/筛选/页面变化通过AbortController取消。分页预取使用独立client序号，不取消前台分页，普通资料回显不重开预取。

`test_browser_prefetches_every_page_without_scrolling_and_reuses_http_cache` 验证136项不滚动全部取回、DOM保持120张，滚动后的新增图片不增加后端预览调用；另覆盖后台两路上限、取消及临时图片释放。实际安装版721文件目录在240秒观察中未滚动已自动准备360张，不能把它报告为721张全部就绪；大目录首次准备仍受真实网络和本地缓存盘读取影响。
