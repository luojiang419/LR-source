# Tauri依赖版本与桌面退出

表现：Tauri 2.11.5被Cargo解析到更新的宏/运行时后，编译出现`UnexpectedMenuKind`不存在等库内部错误。根因是未锁定的内部依赖组合不一致。本次统一到Tauri 2.12.4、tauri-build 2.7.3并提交Cargo.lock，使用`cargo build --locked`后成功；不要在crate缓存源码里打补丁。

关闭窗口时先阻止关闭，通过前端`FramekeepIO.flush()`保存，再调用Rust退出；Rust持有后台Child，只终止自己启动的引擎，并用每实例令牌发出正常关闭请求。引擎同时观察父进程退出，避免主窗口异常结束后残留后台。隔离窗口Alt+F4与引擎8776端口消失已验证。

截图限制：本机Windows窗口截图两次返回`window capture timed out`，UIA仍能读取完整WebView2文档。此时不能凭可访问性树宣称原生目录/保存对话框已点击成功；明确记录未验证项。

## 更新退出与慢盘写入（2026-10-29）

更新交接不能只依赖页面 setTimeout：网络异常可能中止轮询，托盘里的页面也可能被节流。worker 校验包后登记绑定 root、parentPid、enginePid 的交接文件，由当前引擎认领；原生每两秒检查并调用前端保存入口，作为页面轮询的兜底。

更新使用专用退出命令，先保存评级与尚未提交的图片元数据，等待关键迁移，再正常关闭引擎和全部窗口，绕过普通关闭询问与托盘偏好。worker 等待双方 PID 退出并检查目录进程/端口释放，才写 pending 并替换程序；不能靠同名进程批量强杀。

可恢复 queued 项不等于必须拒绝更新，但正在写原文件的线程必须完成。原 `AssetArchive.close` 和 `RatingSync.close` 只等待 3/5 秒，daemon 线程可能仍在写入；改为停止领取后等待当前 writer 完成。原生更新等待 60 秒仍未结束时保留程序，不强杀、不安装；长期离线/文件占用不能冒充成功退出。

验证：控制 writer 超过原 3/5 秒超时仍不得返回 close，释放后才结束；真实新协议客户端设为 tray，校验后约 2344ms 自动退出旧主程序/引擎，冻结 worker 更新 827 文件并正常启动，资料与偏好保留。完整证据见任务 060 与 `build/updater-auto-close-final/`。此验证针对新版后续更新，旧二进制需先升级后才具备新协议。
