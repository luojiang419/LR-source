# 归档区间身份冲突阻断自动匹配

## 表现

OCR 原文唯一命中已启用规则，界面仍显示“请核对后应用”；识别记录为 review、模型错误为空，规则本身检查通过。归档队列持续积压，日志有 `UNIQUE constraint failed: segments.job`。

## 根因与处理

- 同一照片会话可以切换工作表形成多个 stream。补识别段旧 ID 仅使用会话和标签 capture，在另一 stream 补入同一历史标签时碰到全库唯一索引。补识别身份应使用 stream 与 capture，保持已有历史主键，不用删除旧段或清空资料修复。
- 后台 OCR 先持久化 review，再在 `_finish` 进行导出和归档，最后才执行公司自动规则。历史事件抛异常时，job 已不是 running，外层也不再写 failed，最终留下正常 OCR 候选。持久化后的导出/归档异常应各自记录并保留重试，不能跳过自动确认。
- 复现使用 SQLite backup 快照、关闭所有写入 worker，只重放事件，不调用 `process_one`；写入队列留在快照。禁止启动指向真实原图路径的隔离引擎来“试修”，否则它会按旧任务写真实照片。

## 已验证证据

2026-10-27 本机 XSY_9704 的 LC7877499-P905 唯一命中 contains=LC，无长度限制、无旧确认或资产 SKU。`build/sku-auto-apply-archive-block/replay-before/report.json` 真实快照重放复现同一堆栈；修改后 `replay-after/report.json` 确认 67 条积压重放至 0。三个新增回归覆盖跨 stream 幂等、历史归档异常和 Excel 导出异常；102 项相关回归通过。冻结程序使用生成照片与本机 HTTP 测试模型，确认不点候选就自动确认、整款入库和页面无脚本错误。
