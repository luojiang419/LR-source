# 大目录分页与局部保存保护

## 表现与根因

目录索引和预览队列可以管理很多照片，但网页仍可能因全量读取照片 JSON、无限合并已访问页的评级映射、渲染全部卡片而变慢。先读取所有记录再切片，不能解决数据库解码和内存问题；后台标签轮询、目录树和偏好保存触发的 RAW 重扫也会抵消分页收益。

## 已验证的处理方式

- 用原生 SQLite 触发器维护轻量浏览索引，先在 SQL 中搜索、排序和定位，再按 ID 解码最多 240 条完整记录。触发器只使用 SQLite 内建函数，避免外部导入连接缺少自定义函数而失败。
- 全目录分组独立于页边界，尾帧对比只取真实组尾。网页只保留当前页覆盖映射，网格/列表只渲染可见行及缓冲区。
- 保存局部差异而非当前页整个状态，保留其他页评级；删除离页 SKU 标记时发送显式空值，跨页撤销记录真实旧值。保存/回调和分页加载按顺序执行，保留 revision 冲突保护。
- `json_each` 的人工评级 CTE 使用 `AS MATERIALIZED`，避免十万行与人工评级数量相乘。缓存分组、共享评级与总数，并分别按结构、资料和评级版本失效。
- 照片路径变化必须失效共享评级映射；选择位置或视图修订不应重建。无时区拍摄时间按本地时区转换，明确时区按其偏移转换。
- 只读偏好不启动 RAW 扫描；单张评级任务持久保存相关 ID，合并后可重启恢复。全量发现任务维持优先级，不能被局部任务缩小范围。

## 验证

`test_session_browser.py` 验证全目录搜索/排序/计数、跨页保存、真实组尾、并发冷读、路径失效和局部队列；`test_session_browser_ui.py` 通过 Edge 验证有界 DOM、密集人工评级映射、空搜索和跨页撤销。

`benchmark_session_browser.py --rows 100000` 使用合成目录记录，明确没有十万张真实源文件。冻结引擎另以十万记录和 480 份生成 JPEG 文件验证旧库索引升级、真实预览、跨页操作、评级及重启恢复。完整首次导入、批量导出和归档完整校验仍执行各自的全目录工作。
