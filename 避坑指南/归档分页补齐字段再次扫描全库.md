# 归档分页补齐字段再次扫描全库

## 表现

归档已暂停解码，目录和照片网格仍长时间空白。正式接口可超过 15–30 秒，纯分页选 ID 看似很快。

## 根因

`SELECT * FROM capture_items WHERE id IN (...) ORDER BY modified DESC,id` 会因视图内 online 条件选择 online/时间索引，重新遍历全归档。配对相关子查询还可能逐行回表。归档监控、参考目录和任务摘要的长查询同时争用磁盘。

## 解决

用当前页 ID 的 VALUES 表 CROSS JOIN capture_items，让主键驱动行补齐。配对及目录统计增加覆盖索引，关键路径明确选择索引。缓存提示查询有时间预算，失败不阻塞列表。仅查询目录配置时不调用全库状态聚合。

## 验证

EXPLAIN QUERY PLAN 应显示扫描当前页常量行、按素材主键查找，而不是扫描 online/时间索引。12,000 项测试以 SQLite progress_handler 限定指令量，真实浏览器检查卡片、目录、实际图片与错误恢复。最终正式库 120 张卡片约 1.5–6.7 秒，首张图片约 6–8 秒，页面错误 0。时间包含正常后台负载，未清操作系统缓存。
