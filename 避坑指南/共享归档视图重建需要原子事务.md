# 共享归档视图重建需要原子事务

## 表现

首次添加目录或共享参考索引初始化时，并发的归档列表查询可能返回 HTTP 500。隔离并发用例明确复现 `sqlite3.OperationalError: no such table: capture_items`。

## 根因

`AssetCatalog.__init__` 使用 `executescript` 执行 `DROP VIEW` 和 `CREATE VIEW`。Python 连接的 `with` 上下文不会自动把 `executescript` 内每条语句包进同一事务；另一个连接可在视图删除后、重建前读到空窗。共享参考目录会创建新的 `ReferenceCatalog`，因此运行期间也会触发这段初始化。

## 解决方法

在包含视图重建的脚本内显式使用 `BEGIN IMMEDIATE` 和 `COMMIT`。WAL 读连接在事务提交前继续看到完整旧视图，提交后看到完整新视图。

## 验证

`test_catalog_metadata.CatalogMetadataTests.test_shared_catalog_schema_refresh_keeps_browsing_available` 通过 SQLite trace 在 `CREATE VIEW` 前暂停初始化，另一个连接同时查询列表和详情。修复前稳定复现缺失视图，修复后两个查询均成功。基线证据：`build/catalog-metadata-schema-baseline.log`；修复验证：`build/catalog-metadata-after-schema-fix.log`。
