# 历史归档任务阻挡选片引擎启动

## 表现

桌面提示“选片引擎启动超时”，引擎进程仍存在，端口已绑定但 HTTP 健康检查不响应。空数据库测试正常，带活动拍摄流的现有数据库可以复现；单看 engine.log 未必有异常。

## 根因

`server.main` 在完成共享评级初始化之前启动 `AssetArchive` 后台线程。后台 `sync_stream → ensure` 持有归档锁进行照片路径解析、哈希或元数据读取；主线程首次访问懒加载的 `ARCHIVE.ratings` 也需要同一把锁。主线程停在等待锁阶段，未进入 `serve_forever`，触发桌面的 30 秒超时。

## 解决

创建归档服务后、启动任何使用归档的后台服务前，先初始化共享评级并播种已有会话；配置完其他服务和回调再启动归档线程。既不依赖历史照片处理速度，也无需延长启动超时或清空用户数据库。

## 验证

`test_engine_startup.py` 用真实隔离数据库及 HTTP 健康检查，让归档线程一直持锁，确认引擎仍能就绪且四星评级保留。修复前顺序稳定失败，修复后通过；连同生产和共享评级共 44 项回归通过。本机原有数据发行版首屏 1884 ms，健康检查正常。详见 `开发任务/057-选片引擎启动超时修复.md`。
