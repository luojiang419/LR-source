# 库存 USB 增量同步与数据保护

## 不按拍摄时间推进同步游标

- 表现：先拍的记录可能最后完成 OCR；若按最大拍摄时间过滤，会漏掉迟到的确认记录。
- 解决：schema v4 增加 `sync_changes` 单调序号，用同事务触发器记录“变成 ready”及“还原 ready”；旧库只回填有效 ready 行。删除后仍推进已读日志序号，还原产生新事件，ACK 不产生事件。
- 验证：Android 实机覆盖迟到 OCR、ACK 不重复发布、删除跳过/还原重新发布、清空后新记录序号不回退；电脑游标重启保留、失败回执重放不重复计数。

## 自动配对不向网络暴露凭据

- `ContentProvider.call()` 显式校验调用方的系统 DUMP 权限，不能仅依赖 query 的 readPermission；已授权 ADB 调用获取临时会话，客户端不把 USB 令牌返回网页或写入磁盘。
- USB 服务监听 `127.0.0.1:8793`，与手动局域网 8792 独立；数据同步前台服务带低优先级功能通知，心跳超时关闭。连接状态与 ACK 通过应用内广播刷新手机界面。
- 主动断开时先清除 running 标记并广播；不要只在 token 相等的 onDestroy 分支清除，否则提前清空 token 后 UI 可能残留“已连接”。

## 安装时保护大库而不全量读取素材库

- 程序更新使用既有受管清单事务和回滚，仅比较库存库/小配置的哈希，其他大型数据库核对文件元信息；不要为了更新 UI 而读取十余 GB 素材库计算完整哈希。
- ADB 与 DLL/NOTICE 放在受管的 `engine/_internal/runtime/adb/`，不放进现有更新白名单未覆盖的 `runtime/adb/`，不扩大安装器白名单。
- 手机测试先备份全部记录/图片并保存原草稿；只清理明确生成的 id。真实已确认记录同步到电脑后应保留回执，不回滚其 synced 状态。
- MI 9 实测：3 条原有确认记录、6 张原图哈希一致；新扫描确认后自动到电脑，手机从“本机已保存”更新为“已同步电脑”；只移除两端各 1 条测试数据，保留手机原有 4 条（含回收站）、原草稿/设置及电脑 3 条正式记录。

## Windows 原生窗口启动与库存报表保存

- 表现：引擎 `/api/ready` 正常，原生窗口仍停在启动页，窗口截图或输入超时。现有流程把快捷搜索 WebView 创建放进 `run_on_main_thread`，阻塞了 Windows WebView2 消息循环。
- 解决：在已有启动后台线程创建快捷搜索窗口；不再同步投递到主线程。Tauri 官方说明 Windows 应从异步命令或独立线程建窗：https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html 。
- 库存报表通过独立异步原生命令显示带父窗口的系统保存弹窗，取消返回 false；保存时读取固定本机导出接口，校验响应成功及 ZIP 签名后写入用户选择的位置，筛选参数只允许编码后的 URL 查询字符，不允许任意 URL/路径。
