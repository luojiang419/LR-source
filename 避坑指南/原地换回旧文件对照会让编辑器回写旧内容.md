# 原地换回旧文件做对照，编辑器会把旧内容写回

## 表现
- 为了和开始快照对比测试结果，脚本把工作区源码临时替换成旧版本，跑完测试再拷回新版本，哈希核对也一致。
- 之后用编辑工具做一处小修改，结果整个文件变成“旧版本内容加这处修改”，修改还落在错误的位置（例如 `asset-library.js` 出现 `catalogTotal=data.total;=result.ready;`，`archive_capture_service.py` 缩进错误、`retry()` 方法被拆散）。
- 页面启动报 `Unexpected token '='`；Python 报 `IndentationError`。

## 根因
- IDE 监视到文件被替换成旧版本后重新载入了缓冲区。随后的恢复在很短时间内完成，编辑器没有再次载入，缓冲区停在旧内容。
- 编辑工具基于这份旧缓冲区计算替换位置，保存时把旧内容整体写回磁盘。`read_file` 读到的也是这份旧缓冲区，与磁盘不一致。

## 解决方法
- 不要在工作区内原地替换源码。对照测试应使用独立副本：把源码复制到工作区外的目录，在副本里覆盖旧版本文件，其余顶层目录用目录联接（`mklink /J`）指回原工程，并为副本单独建立 `build` 目录。
- 如果已经发生：从替换前保存的工作副本恢复文件（保留原有换行风格），再修改一次文件时间戳，促使编辑器重新载入，然后用 `read_file` 抽查，确认与磁盘一致后才继续编辑。
- 每次编辑后，用 shell 直接从磁盘核对关键标记、文件大小和语法检查（`node --check`、`py_compile`），不要只依赖编辑工具的返回结果。

## 验证
- 任务225：恢复后两个文件与工作副本相比，只多出预期的 2 行修改；`node --check` 和 `py_compile` 通过；补写/归档/二星专项 84 项通过；`read_file` 读到的内容与磁盘一致。
