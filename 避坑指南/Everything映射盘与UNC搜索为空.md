# Everything 映射盘与 UNC 搜索为空

## 表现

Everything 中可以找到图片，SDK 可连接，但末帧按已添加目录搜索没有结果；网络目录长期处于索引中。

## 根因

- 末帧把映射盘规范化成 UNC，Everything 却按映射盘路径保存索引。SDK 连接成功只说明 IPC 就绪，不代表传入的路径表示能命中索引。
- 后台先遍历整个网络目录再调用 Everything，会挡住已有索引的首批结果。仅取 2048 个候选并不能替代完整匹配分页。
- 当前目录范围可能只包含 X，而需要的款号实际位于 Y。搜索路径正确也不能弥补范围选错。

## 已验证解法

用 Windows `WNetGetConnectionW` 读取本用户已有映射，不创建新映射。按目录段把 UNC 与映射盘互换，分别查询同源表示，选择覆盖最多者，将结果规范化回已添加目录。SDK 查询保留进程超时和路径边界，结果预览仍走真实文件授权校验。

Everything 已覆盖时直接就绪，按关键词查询并读取 SDK 的大小/修改时间，只缓存命中结果；不要为复用已有索引再次逐文件探测 NAS。区分连接失败、位置未覆盖和合法零结果。全局搜索以全部已添加的可见目录为范围，结果必须携带自身设备/根目录，不能被当前选中目录覆盖。

## 验证与入口

本机相同关键词用 UNC 原查询返回零，映射盘查询命中 176 个文件。修复后安装引擎经 UNC 全局搜索返回 176 张，约 0.49 秒；两处位置覆盖约 20 万/49 万文件而无需完整目录扫描。性能仅为该机器当时实测。
