# 二星识别与最终归档链路

表现：界面真实标二星却没有 OCR；目录能显示照片但最终副本不自动继承 SKU。

根因：前端没有 Excel 工作表上下文时将二星写成 ignore；后端也要求绑定工作表才排队。文件监控只增量更新 captures，没有二星任务消费者；资产归档页另用 asset_catalog 路径索引，与已有资产／RAW 同步没有连接。

解决：二星独立于文档排队，缺文档自动建上海日期表，未知插拍追加管理表；现场监控的元数据更新触发消费者，重启从持久化会话恢复，自有写入通过 metadata_versions 去重。归档顶级目录增量监控等待稳定后连接既有 RAW/JPG 匹配队列；同名目录只限制候选，永久 ID 和拍摄身份才决定关联。相同文件在两处保存 locations，内容变化追加 versions，filename／拍摄特征保存在 file_fingerprints。

扫描结果先完成事务及后台消费者通知，再发布 completed，避免 UI 或后续流程看到“完成”时消费任务尚未入队。验收文件写入须等待 metadata_jobs 清空并读回文件，不能只用 SKU 库出现图片或 raw_pairs 的瞬时状态判断所有写入完成。

工作簿只增量插入管理表，原图片、DISPIMG 和扩展命名空间保留；XML 声明使用 `utf-8`，非 ASCII 工作表名不能写成不兼容的 `utf8` 声明。原计划近似 OCR 新款另表记录待核对，不擅自改成旧款号。

验证：任务 044 的 101 项相关回归及包内 EXE 实际 HTTP 验收；一次 OCR 建日期表，现场与未携带自有元数据的最终 JPG 同属两个永久资产，四个位置均正确，像素未改，重启不重复识别。仅同名无身份、半张图、冲突及人工保护有专项检查。
