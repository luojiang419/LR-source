# 更新器强制退出不得结束自身进程树

## 表现与根因

旧更新流程等待桌面 120 秒、引擎 60 秒，无响应时只报错。增加强制退出时，不能简单执行 `taskkill /PID <desktop> /T /F`：独立更新窗口和 worker 通常由旧引擎派生，即使使用 `DETACHED_PROCESS`，系统父子关系仍可能保留，结束整棵树会导致更新器一起消失。

## 已验证方案

`更新系统/process_control.py` 使用 Windows 进程快照和完整安装路径确认桌面/引擎身份；在发出退出通知之前保留句柄。强制终止使用原句柄，避免重新按 PID 打开错误对象；子进程同时校验创建时间，排除陈旧父 PID 关系。保留已退出父进程的句柄，补扫退出瞬间派生的孤儿子进程。

从当前 worker 沿父链向上保护，遇到目标软件进程即停止；该保护分支不加入终止队列。不要按通用 EXE 名称结束其它安装目录或系统进程。目标目录内多实例和残留引擎可统一退出；权限不足、明确取消及仍被其它程序占用的端口必须在替换之前报错。

正常退出最多等待 8 秒，随后强制退出并有界确认。事务仍先校验签名与全部文件，再停机、替换、健康检查；失败回滚。强制终止可中断尚未完成的操作，不能宣称所有环境或未完成业务写入均无风险。

## 验证

`python -X utf8 -m unittest discover -s 更新系统/tests -v`：87 项通过，包含真实 Windows 文件锁、同名其它安装、父链自我保护及晚生孤儿进程边界。

`python -X utf8 更新系统/scripts/smoke_force_exit.py --output build/新的隔离目录`：用临时公钥校验隔离载荷，由旧桌面派生真实冻结 worker。默认 8 秒期限下成功约 9.97 秒完成；故意让新版退出时约 9.72 秒回滚，原程序和测试资料保留。永久结果见 `技术文档/验证记录/235-更新强制退出与本地安装包-20261114.json`。
