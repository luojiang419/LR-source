# EOS 联机保存规则与运行中首选项缓存

## 表现与根因

仅改变末帧监控目录不会改变 EOS Utility 的下载位置。EOS 运行时还会缓存首选项；直接改写 `user.config` 不能保证当前传输切到新目录，退出时也可能被旧内存值覆盖。

网络共享根和盘符根的 `Path.name` 为空，会让拍摄目录列表出现空名称。Windows 将映射盘解析为 UNC 是正常的路径规范化，显示时要保留共享根。

## 处理方法

- 先校验现存绝对目录及写入权限，再保存用户选择。EOS 运行中只暂存，明确提示关闭后自动应用；不要强制关闭 EOS 或声称已经切换。
- EOS 退出后安全合并其实际保存字段。EOS 3.20.21.1 的字段关系已用只读托管元数据及 ILSpy 静态重建核对：`SaveFolder` 为根目录；`SubFolderDownload=True`；文件规则各索引选 0 保留原名；目录规则各索引选 0 为拍摄日期；`FolderNameSeparator=1`、`FolderDateOrder=0`、`FolderDateFormat=0` 对应四位年 `YYYY-MM-DD`。
- 不猜其他 EOS 版本的支持程度。按实际 EXE 默认配置校验所需字段，不支持时明确报错；不改写 Canon 二进制或自行复制／重命名原照片。
- 保存设置可能晚于链接登记，必须把新增字段的原值补入已有备份；恢复按最后接管值逐字段核对，保护用户后来修改的值。
- `Path.name` 为空时回退到去掉末尾斜杠的 anchor；前端统一解析普通／扩展 UNC 与盘符，避免归档和联机显示不一致。
- 弹窗异步读取旧设置时记录输入版本；用户先输入或浏览选目录后，不用稍后返回的旧值覆盖。关闭或重新打开弹窗后丢弃旧请求。

## 验证

任务 062 的隔离配置测试覆盖生效、运行中暂存、恢复与只读共享失败；浏览器覆盖四主题、三尺寸、自动提示与输入竞态。已有真实映射盘及 IP 共享完成独立临时目录读写、原名 JPG 索引与清理。安装版冻结接口／弹窗通过，真实 EOS 配置哈希保持。

这些结果验证配置和文件系统接入，未验证相机实拍下载、EOS 运行时实际应用或长期连拍。

## 自动跟随已有 EOS 设置（任务 082）

- EOS 已登记当前桌面程序时，启动只读检测并跟随它的 `SaveFolder`；不要把历史末帧保存目录当作新的写入意图。主动「设置联机保存目录」才应用末帧目录和命名规则。
- EOS 的「记录…」可能先更新内存，用户配置尚未落盘；经过桌面实例令牌认证的照片回调可先启动接入。在这种等待落盘状态之外，检测到 EOS 换用其他链接软件就停止自动跟随。
- 自动跟随保持根目录递归监控；接收子目录照片通知时不要反复切到单个日期目录，否则会漏掉下一次创建的同级拍摄目录。旧磁盘配置与回调中的新保存位置不一致时，优先保留实际照片位置，等待 EOS 配置更新。
- 自动关闭、暂停和手动现场监控应有明确优先级。关闭自动跟随需记住关闭偏好；暂停不得被下一轮检测重开，也不应在只读跟随的关闭流程中恢复旧登记备份。
- 已用隔离配置、真实目录监控和 HTTP／页面联测确认：跨两级子目录及新同级日期目录各有一张照片自动入库，EOS 配置 SHA-256 保持；目录变化、断线恢复、暂停／关闭／重启和独立手动监控均有回归覆盖。未把生成的测试 JPG 当作相机实拍。
