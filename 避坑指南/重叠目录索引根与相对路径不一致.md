# 重叠目录索引根与相对路径不一致

## 表现

资产页能看到照片，但归档提示“所选目录不存在或已离线”。来源显示重复路径：已登记日期根后再次拼接相对于上级共享根的目录段。NAS和映射盘实际都可访问。

## 根因

父根和其下日期目录同时登记，共用按绝对路径唯一的items记录。参考库两处upsert在冲突时更新relative/folder但没有更新root：子根拥有的记录被父根扫描后，三个字段采用了不同基准。仅检查is_dir或强行截断重复文字会掩盖索引错误。

## 解决

- ReferenceCatalog.store_records与ReferenceLibrary._index_paths冲突更新同时维护root/relative/folder，保持Path(root.path)/relative == Path(item.path)。
- 通过catalog_path_consistency.repair_relative_paths按已登记绝对path修复历史relative/folder，写前保留日志；业务主键、SKU、评级、指纹及照片不改变。不擅自重分配越界记录。
- 归档弹窗打开前由后端确认实际来源；兼容旧索引只接受精确旧folder下全部记录一致指向同一目录，并验证仍在登记根内。多位置/越界阻断，不按画面或字符串猜配。

## 验证

python -X utf8 -m unittest test_catalog_path_consistency test_folder_archive_main test_folder_archive_commit test_sku_folder_archive test_sku_archive_preprocess

33项通过；另test_reference_library test_asset_catalog共31项通过。包含两条索引入口的父子根交替更新、SKU保护、历史修复幂等、真实HTTP旧目录兼容、歧义与越界拒绝和原照片哈希保持。生产目录另进行只读路径验证；不能把弹窗打开成功称为完成了真实整理/归档。

生产验证：2026-11-07核查640076条索引，纠正6789项；用户日期根4217条全部恢复为直接文件。修复版已覆盖本机安装目录，正式页面使用原来源/大档/目标通过路径校验并创建准备任务后安全取消，没有执行整理/复制。
