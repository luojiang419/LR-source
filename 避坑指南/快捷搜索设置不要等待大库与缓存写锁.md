# 快捷搜索设置不要等待大库与缓存写锁

## 表现与根因

- 外观设置长期停在读取中，保存也超时：界面借用检索 bootstrap，保存复用完整检索状态；即使移除统计，向大型 SQLite 写一行偏好仍可能等待检查点和其他写入。
- 真实线程栈确认保存停在 `intelligence_settings` 写语句；不能只在小临时库验证，也不能以延长超时或去掉错误文案作为修复。
- 缓存收缩误报文件被占用：后台继续按旧额度填充缓存，而删除前后的用量在锁外分别采样，将并发新增误当作本批没有删除。

## 处理

- 外观四字段独立保存为资料目录 `quick-search-appearance.json`，使用原子写入与单独短锁，启动覆盖历史 SQL 外观；读取及专用保存不打开主库、不等待模型或检索初始化。
- 通用配置写入等待期间允许外观独立保存，通用配置提交时合并最新外观；保留字段校验、重启持久化与原有模型配置行为。
- 外观读取超时有明确重试入口；当前设置不能被陈旧读取覆盖。筛选建议异步返回，不挡住资产结果首屏。
- 无词资产首屏复用独立文件索引；稀疏解析结果/维度从自身索引驱动关联，避免从全部在线素材开始扫描。
- 最近归组不能对全部大 JSON 行执行 CASE 排序：沿 `(status,updated)` 索引各取50个键，合并优先级后仅取最终50份证据；用同一只读快照保留未知旧状态及 review/ready 优先。
- 收缩期间停止领取新预生成任务，在途与前台请求可收尾；同锁核对本批删除量，状态查询使用独立只读快照。原有登记、哈希、未知文件保护和 LRU 保持。

## 验证

- 任务156主修订冻结157项通过，随后前台查询让路修正62项、归组补强48项通过。覆盖禁止主库访问仍可读写外观、通用配置写锁阻塞时独立保存且合并不丢字段、检索bootstrap卡住仍可设置、失败可重试、慢筛选不挡首屏、缓存写事务阻塞时状态返回已提交值、收缩暂停/恢复后台领取及大量归组的有界读取。
- 真实安装设置0.557s显示、资产首屏0.951s、快捷输入至结果76ms；完整状态由超12s恢复至约3s，页面异常0。自然语言样例仍约5.7s，不能用普通文件码的快响应代表全部查询。
- 用户授权的离线清理复用登记、LRU及Windows同句柄SHA-256/链接校验删除，8路文件操作与批量索引事务，连接复用并在收尾截短WAL；原照片、未知/替换文件受保护的临时验证通过。真实释放96.24GB、32GiB目标完成；业务SQLite清单与其他配置/快捷索引哈希保持，缓存索引quick_check和用量/数量核对通过。
- 实际安装验收结果和性能范围见 `开发任务/156-快捷搜索设置加载与缓存收缩超时.md`；业务照片与数据库不作为测试夹具，不伪造生产缓存命中。
