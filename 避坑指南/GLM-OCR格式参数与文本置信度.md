# GLM-OCR 格式参数与文本置信度

## 表现与根因

本机 LM Studio 已加载 `glm-ocr`，`/v1/models` 成功，但图片识别返回 HTTP 400：`response_format.type` 仅支持 `json_schema` 或 `text`，不能接收 `json_object`。去掉格式参数后正常返回图片全文，但可能只有 `text`，没有提示词要求的 codes/confidence/is_label 字段。

## 处理

`sku_vision.py` 尊重模型卡片的 JSON 模式开关；明确的格式参数 400 才移除参数重试一次，鉴权失败及无关 400 不重试。纯文本或只有 text 的 JSON 保留原文、提取可读候选，缺少 confidence 时标记 unscored，不能伪造高置信度自动记账。

资产备案的手动解析只填入可编辑草稿，多款号供点选，核对后仍走预览和确认写入。请求期间手动改字或切换图片时，旧结果不得覆盖新输入。

## 验证

`test_sku_vision.py` 验证参数降级、关闭 JSON、鉴权和无关 400；`test_asset_ocr.py` 验证草稿填入与异步保护。真实 `XSY_5232` 标签和发行引擎已调用本机模型读出 `LCJ81166`。该手写读数未获得模型置信度，不能据此宣布精确款号或已拍摄。

## 安装版原生任务提示与 CPU 预算（2026-10-21）

安装资料中出现过“尚未部署模型”、HTTP 400、连接失败，以及把“完整可见文本／逐字读取的完整款号”模板原样当作 OCR 结果。应分别核对当前进程使用的资料目录、模型选用、组件状态和真实推理日志，不能仅以服务加载成功或一次请求成功判定工作流可用。

内置 GLM-OCR 使用原生 `Text Recognition:` 提示，强制关闭 JSON 格式约束，仍从 OCR 原文提取款号；提示模板回显、输出截断和超时分别显示实际原因。外部 API 的提示、协议与格式降级保持原路径。OCR 请求此前忽略卡片 `image_size` 而总取 2400px 预览，现在内置请求按卡片限制缩放；仍保留已校正的图片方向。

本机 Intel Iris Xe、无 NVIDIA，走 CPU。原 4096 图像 token 的实拍请求需 174–179 秒；限制为 1024、旧卡片也保证 300 秒等待后，新冻结程序 8 张标签约 31–37 秒。2048 token 对照约 67 秒且未修好同一手写标签的字母误读，未采用。GPU 完整卸载路径仍保留 4096 图像 token；没有实测本机不具备的 NVIDIA 加速效果。

安装版关闭内置开关且未选 OCR 时，组件文件即使完整也不会被使用。全自动状态现在明确显示“等待选用模型”和设置入口，保留用户原选择，不自动打开会写入照片的已有队列。

本次 8 张标签和 1 张普通产品图的原图及手动副本哈希保持；印刷 SKU `LC7832730-P705`、`LC7832730-P804`、`LC7832730-P604` 已对照原图。手写 LC 仍可能读成 L= 或 10，不伪造置信度或按文档纠正 OCR 原文。当前工作表没有这些完整印刷款号，须核对拍摄表与真实后缀。实际无模型安装包在隔离目录写入 759 文件、逐项哈希通过，从安装后引擎用匹配的独立测试文档执行真实自动 OCR，32.484 秒匹配 `LC7832730-P604` 并记录已拍摄，原图哈希及副本像素保持。

完整证据见 `build/ocr-repair/`。94 项定向回归通过；浏览器公共状态测试先前仅等待另一轮询的计数，现等待表格本身完成刷新，避免把暂时旧数据显示当作最终状态。

## 二星与全图队列共存时的入库和角标

全自动 OCR 不能吞掉用户二星标签，也不能仅按扫描顺序等待几百张普通图。应优先调度二星，保留原单任务和忽略／暂停语义。GLM 标签全文可能同时出现款号和生产批号，先取明确款号字段或完整混合编码，保留原文与真正的多个款号。

“入队较早、完成较晚”的自动任务不能被“创建较晚、完成较早”的旧手动读数遮住；应记录并使用处理时间。只读取 OCR 表也会漏掉用户已人工备案的 SKU，库与缩略图应投影已确认的现场资产归属。全图识别按单图处理，不能因某张读取到 SKU 就把之前所有照片归组。

另一个实际阻塞是 RAW 索引在 SQLite 写事务内访问 `archive.ratings` 属性争用归档写锁，同时归档线程持写锁等待 SQLite，形成锁顺序倒置。已初始化评级对象无需再争用写锁；后台审计写入也要容忍同一次占用，避免错误处理自身异常杀死工作线程。用持归档锁的线程与持 SQLite 事务的评级读线程进行确定性回归，结合真实后台／浏览器链路验证。

已按用户确认策略将二星表外真实 SKU 写入临时插拍，原计划近似款不更改。正式部署 `20261021131456` 已确认 P804/P604 两条真实款号和角标、P704 未拍摄，照片像素与二星保持；证据见同一 051 任务文档及 `build/ocr-repair/two-star/`。

## 主款号确认与辅助资料检索

后续用户明确要求由人选择正确 SKU：不能因把批号从主候选中过滤掉就丢掉原始 OCR，也不能让新的辅助读数覆盖已确认款号。保存原文、其他字段和历史到独立资料表，主 SKU 单独保存确认记录；只读搜索支持普通照片继承款末标签辅助资料。确认时核对资料版本与文件状态，迟到模型输出只补充辅助资料。

FTS5 trigram 可搜索中文／批号子串；少于 3 字符用转义 LIKE，避免中文经 SKU 英数规范化变成空查询而匹配全部。查询采用参数与字面短语，不执行输入中的 FTS 运算符。旧确认应迁移沿用；二星标签需扩展其区间，普通全图输出保持单图，未知二星不能被下一款吞并。正式 `20261021142823` 已验证 276 张（251/25）区间角标、历史辅助查询和原图哈希保持。
