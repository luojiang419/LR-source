# SKU 补漏标签与区间重划

表现：已经用 A、B 的款末标签封口后，补识别中间的 C，只从 pending 照片取成员会得到空区间，旧 B 区间仍包含 C 的产品。把 last_boundary 直接改成迟到的 C，还会让后续边界倒退。

解决：按同目录、同相机的完整标签集合重新划分结束区间，标签自身属于其结束的款；时间齐全按时间，否则保持整个流的入库顺序。仅重算受影响段，用原自动操作的补偿链路撤销旧自动归属，再写新版本；永久资产 ID 保持。人工锁定版本不回退、不覆盖，部分保护也明确标为需复核。

普通 OCR 的可视分组和自动归档要共用同一划分算法。手动 OCR 结果持久化与后续归档事件在同一事务提交，事件回执防重复；只有已启用且有归组的自动段才沿用原写入规则。独立 OCR 不能因显示区间就自行开启原图写入。

验证：`test_sku_intervals.py` 11 项覆盖迟到、重复、撤销、已写／未写、普通 OCR 与自动段混合、重启和人工保护。实际包内 EXE 通过一次本机模拟 OCR 请求，从 A/B 两段变为 A/C/B 三段，JPEG XMP 回读正确、A 文件哈希和全部照片像素保持。证据见任务 043 与 `build/sku-intervals/packaged-result.json`。

## 角标整段正确但实际只入库标签

表现：首张为产品图、最后才拍二星 SKU 标签；角标按区间显示，但资产库和实际文件仅标签拥有 SKU。根因是全自动 `_full_commit` 和主款号选择 `choose_ocr_sku` 绕过了分段，只对 `[capture_id]` 单图备案。只测区间投影无法发现这个问题。

解决：二星全自动与主 SKU 选择创建持久化归档事件，共用 `AssetArchive.confirm_ocr_interval` 接入已有 reserve／handle_event。尚未识别的二星也要参与实际分段的隔断，普通逐图结果保持单图。实际入库行覆盖显示投影时，要保留同款的 `interval_id`，否则辅助 OCR 搜索只能返回标签一张。旧版单图手工标签可由用户再次确认后补齐产品图；保留其他人工锁定归属。

验证：任务 052 的 84 项回归及冻结程序验收通过。两次本机模拟 HTTP OCR + 浏览器确认形成各 3 张的两款，6 张 JPEG 内嵌 SKU 回读正确、像素保持，未封口尾图完整哈希保持。虚拟缩略图列表必须逐张定位验证角标，不能断言整段所有角标同时存在于 DOM。正式安装 759 文件哈希与资料数量保持。

## 换入文档后记账成功但未写入

表现：同一照片目录已有旧文档或现场记录的绑定，换入新文档后，明确选择 SKU 显示整款数量，文档也已记账，却没有写入操作。`start_stream` 默认跳过所有旧绑定，新项目的活动段没有当前照片；`reserve` 找不到标签后直接返回，事件仍被标记为已交付。

解决：`confirm_ocr_interval` 找不到当前项目／类型的标签绑定时，先用 `group_context` 确定本款首图，明确从该图接续新拍摄段，再复用 reserve／handle_event。区间边界及原有人工保护继续保留。不能仅以 SKU 投影数量或文档状态判断文件写入成功，须核对返回的具体操作及全部文件任务，再从 JPEG XMP 回读。

另一个对账漏记原因是手动 OCR 只生成 `parse_jobs`，导出却从 `jobs` 汇总拍摄证据。明确选择时需保存当前工作表的确认记录、真实 EXIF 时间和目标行；同一规范款号在当前表重复出现时共同更新，其他工作表仍独立。

验证：任务 066 新增“旧拍摄段后换入新文档”测试、区间与人工保护回归及最终安装版隔离验收；整款两张 JPG 实际内嵌、文档状态／时间／首图同步、另一工作表与无关照片保持。最终 Excel 经本机 Microsoft Excel 只读打开验证图片锚点及状态，并导出 PDF 检查。
