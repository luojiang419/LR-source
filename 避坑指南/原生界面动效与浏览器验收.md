# 原生界面动效与浏览器验收

## 表现与原因

- 原生dialog直接隐藏会跳过离场动画；用JS延迟close则会改变open、焦点、Escape和遥控暂停判断的时机。
- 动画后立即断言可见性/侧栏宽度，会测到中间状态；不能继续以同步最终几何作为验收条件。
- 本机Chrome155中，`details::details-content` 能进行高度过渡，但其动画未通过 `getAnimations()` 暴露；动画列表为空不能证明没有动效。

## 处理

- 弹窗使用 `@starting-style`、`display/overlay allow-discrete`，保留原生showModal/close语义；关闭后的残留画面禁用指针事件。减少动态模式直接取消过渡。
- 页面隐藏同步让出布局，只对新页面播放入场动画，避免旧新页面同时占据Flex空间；不对每张新入库照片和海量缩略图播放入场动画。
- 等待几何或最终计算样式满足条件后再断言折叠结果。对普通动画可通过WAAPI暂停并设定中间进度；details内容块采用真实时间中间帧及最终高度检查。
- CSS Animation的缓动可能在关键帧easing上，effect.getTiming().easing仍是linear；检查实际关键帧，不能只看effect整体参数。

## 验证

`选片助手/test_ui_motion.py` 实测页面/弹窗进出、同步close/returnValue、Escape、反向折叠、侧栏宽度、菜单恢复、评级保存和减少动态模式。最终打包引擎中详情内容从112px经32.3438px中间帧收起到0；146项完整回归通过。对应任务：`开发任务/020-全界面贝塞尔动效.md`。

## details 内部长清单的 Flex 约束

表现：2026-10-20 拍摄进度右栏改造后，外层 details 高度已约束为847px，内部36款清单仍撑到4250px，底部内容被 overflow 裁掉且不能滚动。少量两行 fixture 不会暴露问题。

根因：现代浏览器用 `details::details-content` 内容盒承载 summary 之外的节点。只给 details 本身设置 display:flex 和列表 flex:1，不能让这个中间内容盒自动传递高度约束。

解决：为 `#progress-table::details-content` 设置 `display:flex; flex-direction:column; flex:1; min-height:0; overflow:hidden`，列表本身保留 `flex:1; min-height:0; overflow:auto`。折叠态仍使用原生details与既有动效。

验证：进度浏览器专项在7种宽度中追加30行检查自身滚动和固定表头；发行引擎真实36款清单可视764px、内容4250px，滚动500px后表头偏移0且右栏不滚动。参见 `开发任务/016-拍摄进度标签页与完成时间.md` 的右侧栏记录。

## 不需要折叠的清单不要复用 details

拍摄进度的款号清单在右栏改造后仍沿用 details 和持久化的 progress-table 开关，用户收起后可能留下空白主区域。2026-10-20 根据最新交互要求改为普通 section 和静态 h3，不再加入 folds 或读取该开关；旧 selection/monitor 中保存 false 也不能隐藏列表。不要用CSS强制展开details而继续保留可点击summary和旧状态。

回归应显式注入旧收起偏好，并验证清单可见、标题点击不折叠，同时验证右侧仍需折叠的卡片能反复开关。本轮test_progress_browser及正式引擎36款清单已验证，左侧已不再需要上节的details内容盒Flex处理。
