# 局域网拍摄投影与指纹版本链

## 表现

跨机接收到清单、已确认 SKU 和 JPG 后，SKU 库可显示照片，但重新打开拍摄进度却由已拍摄变为未拍摄；日期目录下的随机字母数字会话名还可能在归档准备时被误判为 SKU，导致目录款号与确认款号冲突。

## 根因与处理

- 识别作业保存识别时的照片指纹，JPG 元数据写入后照片指纹改变。正式 `_valid`／目录进度通过 `metadata_versions` 的 before→after 链认可同一照片；只传作业和当前照片不够，必须同步这条版本链。
- 共享评级与会话人工覆盖都是评级来源。快照合并来源实际评级，接收端直接投影共享评级数据库，不通过会排队写文件的 `ratings.set`。接收会话登记为拍摄来源，避免重启时把收到的 JPG 当普通历史目录重新写星。
- 永久 AssetId／FileId 已写在原始 JPG／XMP，不能随会话 ID 一起重新命名，否则后续大档归档身份不一致。保留永久身份，业务会话与文档按来源映射；永久身份发生不同来源冲突时明确停止。
- 接收目录采用 `机器名称 [设备摘要]/拍摄日期/拍摄-会话摘要/原路径`。中文「拍摄-」与方括号使内部标识无法被完整目录 SKU 规则命中，原有真实 SKU 子目录仍可正常识别。
- 来源标记独立存放在设置表，不能只依赖 `session.state`：本地保存选片视图会重建该对象。独立标记防止退出后接收到的资料被再次广播、自动解析或写回。
- 直接导入 `ocr_documents` 后须按真实 rowid 增量更新 `ocr_document_search`，否则原文存在但全文检索为空。
- 接收预览不能永久沿用源索引中的旧指纹。以实际 JPG／XMP 摘要生成本地指纹，并补齐来源末端指纹→本地指纹映射，才能同时满足预览失效与拍摄进度校验。

## 验证

`python -X utf8 -m unittest test_lan_capture_sync -v` 验证真实 HTTP 双端、元数据写入后指纹变化、二星确认、OCR 原文搜索、SKU／标签双图引用与导出、离线归档来源快照、退出留存和阻止再次转发。合成样片写入可由 ExifTool 实际读回的相机型号、序列号、子秒和原始编号；不依赖文件名猜配。

## 2026-11-20：当前套增量同步与真实状态

- 表现：主机登录成功，但接收目录始终为空；界面仍显示“正在发送／正在接收”，元数据任务持续等待归档锁。
- 根因：原清单在三把业务锁内整表读取、散列所有历史 JPG/XMP；客户端超时先于清单生成完成。登录或角色不能证明正在传输。
- 解决：只读 WAL 事务用监控 session 与上海入库日期筛选当前套，散列放事务外并缓存到 `lan_sync_hashes`。业务表触发器记持久修订，提交后复用条件变量唤醒；差异批次与递增 seq 持久写入，客户端文件校验及业务投影结束后才确认游标。
- 监控 session 会复用文件夹身份，因此套 ID 还需包含 generation；generation 随监控配置持久保存，程序重启继续同一套，停止再开始才换套。跨零点在新照片首次入库时切换，入库字段优先于 EXIF，后到配对沿用首次入库日期。
- 逐台状态依据 ACK、待下载数和最后心跳；空闲显示同步完成，超过 30 秒显示中断。自连在认证层校验设备及同机数据目录；不同数据目录的同机测试实例明确标为“本机另一实例”。长轮询期间先注销令牌再等接收事务退出，避免主动断开／关闭开关卡满 25 秒。
- 失败照片和其关联业务行一起跳过，已收到的历史文件保留；可重试失败由当前套重新补齐。不能仅记录内存 revision：必须持久保存已应用 seq、套和业务投影状态，重启后从游标继续。
- 验证：24,000 历史 + 30 当前在约 0.2 秒返回，历史文件读取 0；散列暂停期间归档元数据提交约 0.003 秒。真实 HTTP 三接收端验证断网 60 秒、跨日、双向进程重启、自连拒绝及缺图容错；四个正式发行引擎实测照片约 0.45–0.53 秒到达，字节一致，四主题及 1440/768/390 无页面错误。相关验收入口见任务 246。

- 状态补充：在途文件名在下载开始时登记，字节数在流读取过程中累加；只有实际存在在途下载才显示“正在发送”。延迟取主机该 seq 的创建时间到首次 ACK 的时间，空闲心跳复用原值，不能把“距上次同步的时间”误报成越来越大的同步延迟。

## 2026-11-20：接收端退出与先于入库的共享原图

- 接收端退出前调用通用 flush，会把本地视图和接收到的评级一起保存，触发只读校验，断开 API 根本未执行。接收模式的 flush 只保留本地视图，退出跳过远端业务保存；后端取消连接不等待阻塞的网络读取，并用连接代际拒绝迟到响应。
- 只把“最新三张已入库照片”另开快速下载仍不够：真实大屏的入库/元数据队列可让新照片等约 20 秒。要直接订阅当前共享目录的 ReadDirectoryChangesW，复用 DirectJpegFeed 与独立原图通道，把 SMB 中的 JPEG 原字节先送到浏览器；业务 ID、XMP 和游标随后按正式协议接续。
- 临时原图预览不创建临时业务照片，不提前确认完整批次；开始监听时把已有文件加入已知集合，避免旧照片的元数据回写被误判为新快门。退出或换套后撤销旧预览路径。
- SMB 沿用 Windows 已建立的登录凭据，同步密码并非 Windows 共享密码。自动共享只授予当前 Windows 用户读取权限；已有可读共享可在联机时指定 UNC 路径。所有源图以 rb 打开，下载校验后仍原子保存到本地。
- 首次散列不能每张各提交一次 SQLite。使用线程内缓存读取连接、一次性批量提交散列表，避免大目录同步把时间消耗在数千次提交上。
- “最新照片”时间可能同时包含 UTC 入库时间与 +08:00 EXIF 时间，必须比较时间点，不能按 ISO 字符串排序，否则旧套完整投影会把最新图切回旧图。
- 真实验证：大屏共享 `\\192.168.0.231\d\套图拍摄\2026-11-20`，新照片 XSY_3381.JPG 从共享出现到显示 0.875 s，千余文件积压期间退出 0.172 s，页面错误 0；源文件未写入、未改名、未删除。

- 显示验收补充：naturalWidth>0 只证明图片已加载，异步绘制的首帧截图仍可能为空。稳定画面验收应等待 decode 与两个动画帧，再比对原图与截图的像素；本轮最终实拍 XSY_3841.JPG 确认 1.078 s 画面可见、0.110 s 退出。早期 0.875 s 为加载口径，不能替代实际绘制时间。
