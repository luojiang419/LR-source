# 纯数字款号误报与归档写入进度

## 表现与根因

手填纯数字 SKU 后整款报“Windows 图片属性读回不一致”。ExifTool 的默认 JSON 会把纯数字主题变为整数，程序用整数与预期字符串比较；小数、科学记数和布尔形文字还会失去原样表示。修正款号后，旧 revision 失败仍被未按版本筛选的错误列表展示。

## 已验证处理

1. Windows 属性按文本核验；CLI 用 JSONQ，常驻内存通道固定把自定义 XMP、描述／关键词和 XP 字段输出成字符串。目录元数据读取也用相同规则；相机 ISO、评级等数字字段保持数字类型。不要仅用 `str()` 补救已丢失的 `123.00`、`1E3`、大小写布尔形文本。
2. 旧错误保留历史，但当前状态仅展示当前确认 revision 的写入错误。不能删除旧任务伪装恢复，也不能把旧完成任务冒充新款号写入成功。
3. 手动确认只代表写入入队。独立持久进度保存目标记录和 revision，与区间补写共用排队／写入／失败／完成及卡片动画，实际提交并回读后才能变为完成。以用户发起时间选择进度，不能让后台更新的时间戳抢走较新操作。
4. 归档只显示媒体须使用正向白名单，并覆盖文件枚举、索引查询、两种排序、搜索、分页、缓存及启动快照；不能只屏蔽 XMP／DOC 几个后缀。PDF／INDD 是文档，PSD／PSB／AI／EPS 是保留的图像源文件。过滤显示不删除文件，照片的 XMP 配套操作仍保留。

## 验证

2026-11-13：原目录 52 张 JPG 当前 SKU、主题、标记均与 `LC7876953` 一致；52 条旧失败属于另一确认 revision。隔离安装引擎在右栏手填 `中文 Ab-001 / 123.00`，4 张 JPG 均精确写入，进度 4/4、失败 0；真实改写 Windows 属性仍拒绝通过核验。严格媒体用例覆盖 PDF／INDD 和其它未知文档、旧索引、启动快照、搜索及分页，原文件全部保留。详见开发任务 227 和本轮增量补丁。
