# 二星清零后旧识别与归档区间残留

## 表现与根因

二星标签清零后，清单可能只剩款号记录，图片和拍摄完成时间为空；重新标二星时，旧 OCR、`ocr_choices` 或全自动已完成任务仍可能被复用。只取消 `jobs` 不会清掉手动 `parse_jobs`、OCR 全文索引和人工确认款号。

归档段的 `job` 还可能使用 `choice:session:capture` 或 `ocr:session:capture` 合成身份，仅按真实识别任务 ID 撤销会漏掉这些区间。复用已取消段时，旧创建时间又可能使该段被较新的待确认段标为 `superseded`，导致清单已经恢复、归档仍未恢复。

前端保存若在异步队列开始执行时才读取状态，同一事件循环的 `0→2` 会被合并，服务端根本收不到清零操作。

## 已验证的处理

- 清零在同一 SKU 事务内取消该照片的识别任务、清空结果和运行令牌，删除 OCR 文档、FTS 索引及款号确认；立刻重算清单贡献。保留原图、原始清单和其他照片的有效贡献。
- 用 `ocr_resets` 持久记录主动清空，阻止全自动扫描在零星时重新恢复资料；再次二星后解除并重新识别。其他非零评级沿用全图 OCR 原规则。
- 按标签照片身份撤销所有相关自动区间；持久事件顺序投递。重标复用任务身份时，把已取消／淘汰段保留为历史身份，再使用当前有效区间，避免旧段吞掉新确认。
- 前端在保存入队时冻结状态；保存完成主动刷新清单，用请求序号和修改代次拒绝迟到轮询。
- 所有结果提交继续核对 `run_token`；旧推理或手动读取完成后不得恢复已清空的资料。

## 验证

`test_rating_ocr_reset` 的 7 项专项和相关回归合计 90 项通过。冻结引擎使用生成照片与本地测试模型，实测两次二星分别调用一次模型，清零删除 OCR 与确认，重标恢复两张整款照片及 EXIF 时间，页面错误为 0。证据位于 `build/rating-ocr-reset/`。

冻结测试照片必须在真实文件内写入 EXIF，不能只向测试索引注入时间；真实评级同步会重新读取文件元数据，后者会造成测试夹具时区丢失的假失败。
