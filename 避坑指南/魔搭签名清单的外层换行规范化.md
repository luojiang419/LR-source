# 魔搭签名清单的外层换行规范化

## 表现与根因

`release.py publish` 已成功上传完整包、安装器并激活 `public/latest.json`，最后却报“激活清单匿名回读不一致”。Windows 生成的外层 JSON 使用 CRLF，魔搭文本入库后规范化为 LF；本次差 3 字节。双方解析后的 JSON、`payload` 字符串和 Ed25519 `signature` 完全一致，公网清单验签成功。

## 解决方法

激活回读先解析 JSON，与原 envelope 对象完整比较，再执行 `verify_envelope()` 并比较验证后的 manifest。仅允许外层 JSON 的等价文本表示，不规范化或重写签名载荷。ZIP 和 EXE 仍必须逐字节 SHA-256 相等。

## 验证

`1.0.0 / 20261021065231` 发布时验证 JSON、签名载荷及签名相等，公网验签、755 个载荷记录和不可变产物哈希通过。修复后的发布流程完成 `publication.json`，旧版实际更新客户端返回发现新版本。证据见 `build/mouse-fixed/modelscope-release/online-client-check.json`。
