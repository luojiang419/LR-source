# 安装版隔离验收不得改写资料路径

## 表现

安装版验收通过后，正常启动读不到原有目录、模型配置和识别任务；标星看似无反应。安装标记与 HKCU Framekeep 的 DataLocation 指向已经删除的临时验收目录，真实业务库仍然存在。

## 根因

隔离验收通过 FRAMEKEEP_DATA 为已安装引擎提供临时库。UpdateClient 启动后自动刷新 Windows 安装注册，旧 `refresh_registered_install(root,data)` 将本次运行的数据目录写回安装标记、注册表和快捷方式参数。验收退出删除临时目录，后续正常启动因此选择错误资料库。

## 解决方法

- 自动刷新使用 `data_directory(root,integration=WindowsIntegration())` 解析已有持久安装资料，禁止将运行时覆盖保存为安装身份。正式资料迁移仍由安装或更新事务执行。
- 修复已经污染的本机指向前，核对历史安装备份、现有业务库、模型配置及注册项，确认真实持久目录；只修复安装指向，不迁移、合并或删除用户库。
- 运行安装版验收前后比较安装标记与注册资料路径，退出后再次检查真实数据库存在；不能仅凭隔离测试通过就宣称正常启动无误。
- 真实模型验收查 `ocr_documents` 的持久原文；自动应用 SKU 后，`jobs.result` 可能已转为确认资料，不能继续假设其中一定包含 `readings`。
- Windows 临时 SQLite 查询用 `contextlib.closing(sqlite3.connect(...))` 关闭连接；单独使用 Connection 上下文只提交/回滚事务，不关闭句柄，可能导致临时目录清理失败。

## 验证

任务 `076-标星触发链路修复与安装资料保护.md`：两个安装路径回归用例验证普通及隔离启动、有/无安装标记的持久目录保护；按钮、键盘、遥控验收均实际发送请求；真实安装引擎与内置 GLM-OCR 在无导入文档场景识别 `LC7877496-P905` 并自动确认，安装标记和注册资料路径保持不变。
