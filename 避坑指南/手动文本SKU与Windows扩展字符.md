# 手动文本SKU与Windows扩展字符

## 现象

现场侧栏能输入中文，但纯中文或符号点击确定被拒绝；表情符号等扩展字符则可能在准备写入阶段提示“Windows 图片属性读回不一致”。

## 原因与修复

- 原有 `sku_match.normalize` 只保留ASCII字母／数字，纯文本变成空键，随后被SKU校验、清单建行和归档写入拒绝。业务键增加纯文本回退；传统款号保持原键，实际SKU文本不参与改写。
- 自动OCR继续调用 `normalize_code`；自动插拍也只接收原编码规则，手动确认使用独立的 `literal=True` 路径。不能直接把OCR的任意原文都变成自动款号。
- ExifTool 默认将XPSubject／XPKeywords按UCS2转换，写入 `🙂`（U+1F642）会截断成U+F642。通过程序自有ExifTool配置将这两个标签改为UTF16LE读写，BMP字符保持兼容。
- 通用归档读取通道没有加载写入器配置，因此还需按JPEG实际EXIF字节解码这两个Windows属性，避免详情页把正确的代理对显示成问号。

## 验证

`test_live_manual_text_sku.py` 使用隔离生成照片，逐次验证纯中文、纯符号、表情、数字、前导零、`123.00`、`1E3`、`TRUE`及混合文本。核对私有XMP、伴随XMP、Windows主题／标记，以及Pillow读取的原始UTF16LE字节；同时检查像素、邻款、重启、浏览器确定／Enter和模型调用次数。首尾空白沿用原行为去除，内部文字保持原样。
