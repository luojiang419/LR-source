# 二星待核对候选自动显示

## 表现与根因

标记二星后，底部显示“OCR 待核对”，右侧没有候选款号。后台识别已保存资料，但 `asset-metadata.js` 只有手动解析入口填充候选；自动识别的 `framekeep:capture-status` 事件仅被状态栏和识别动效使用。

## 修复

- 右栏监听当前照片的 review 状态，按需读取既有 OCR details 接口，显示最新推荐款号和原文按钮；自动展开照片设置和款号备案，候选滚动到可见区域。
- 沿用原有 choose 接口、资料版本校验及整款应用逻辑；只展示候选，保留手动输入，点击后才确认归属。
- 按照片上下文、任务和候选内容去重；切图、任务变化及手动重新解析中止旧请求，迟到结果不得覆盖新图。轮询不重复重建同一组候选。

## 验证（2026-10-23）

- 7 项既有回归通过：解析状态、OCR 资料与搜索、整款确认、旧资料/图片拒绝确认、全自动等待选择及 review 候选语义。
- Browser 实际标二星后自动显示两个候选；手动输入保持，点击后确认并归属两张区间照片。右栏折叠/处于当前拍摄页时自动恢复照片设置；候选响应人为延迟 3 秒，切图后不串结果；手动解析保持正常。
- 安装目录前端资源再次验证自动候选、Enter 选择并应用整款；1024px 无横向溢出，页面错误日志为空。JS 语法及按项目 CRLF 规则的 diff 检查通过。
- 源码同步到五处受管资源，维护对应清单；版本、资料路径保持。验收使用隔离数据及模拟 OCR 返回，不操作真实照片。运行窗口正常重开后加载更新。
- 本地证据：`build/ocr-review-sidebar/`，不提交验收及构建产物。
