# 正式安装的资料定位与卸载自复制

## 表现与根因

程序装入 Program Files 后仍把数据库和缓存放在程序旁，会受写权限影响；安装阶段使用临时环境变量指定资料，后续桌面快捷方式直接启动时也会定位错误。已有工程启动器还有一层 `.framekeep` 优先级，不能用程序旁的残留文件夹覆盖它。

Windows 正在执行的卸载 EXE 不能直接删除自身；直接递归删除整个安装目录又可能误删用户另存照片、模型和评级资料。

## 解决方法

安装记录持久保存实际资料目录，桌面壳正常启动直接读取，旧工程／旧安装资料按原优先级继承。资料定位记录与系统注册一起进入安装事务备份，健康检查失败或中断恢复时一并还原。

卸载器先复制到当前用户临时目录再展示确认窗口，冻结 worker 按受管文件清单及哈希移除应用，未知和修改过文件保留；仅移除属于本安装的注册及链接，不递归删除用户目录。

## 验证

任务 047 的 31 项安装更新测试、3 项资料路径测试及完整包实跑验证了正常启动、改装目录、修复、升级和原生卸载。四星／三星旧评级、外部原图和未知照片保持，卸载旧副本不会影响当前已注册安装。证据见 `build/formal-install/latest-result.json`。
