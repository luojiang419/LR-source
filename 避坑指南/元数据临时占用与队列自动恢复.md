# 元数据临时占用与队列自动恢复

## 表现与根因

- 拍摄清单长时间显示“等待后台写入”，后续照片不推进。同图 `file_lock` 原先无限等待，单消费者因此无法处理其它图片；任务领取后异常遗留的 `running` 也只在重启时恢复。
- 临时 Windows 分享锁／字节锁冲突在第 8 次重试后永久失败，占用解除后也不会继续。归档手动确定与现场队列共用此策略。
- 归档准备阶段直接请求 ExifTool，部分文件被写句柄占用时只得到空输出，导致 JSON 解析错误，丢失可重试的真实占用原因。
- SMB 连接失效后，本地仍保留旧编辑句柄，原实现只报失效、不会关闭自身失效句柄并重新取得权限。有待写任务的历史目录还可能因没有正在浏览而一直不恢复。

## 处理边界

- 消费者同图锁等待 0.2 秒、提交所需归档锁等待 0.5 秒后让行，短退避后接续；绝不把活跃写入者的锁强行释放。普通调用默认仍使用阻塞式同图锁，RAW／JPG／XMP 共锁关系不变。
- 临时占用按 1、2、4、8、16、30 秒退避，此后保持 30 秒，直到占用解除；权限、外部内容变化、身份冲突等仍明确失败。
- 持有唯一消费者锁后恢复孤儿任务；已提交 journal 经实际哈希和字段回读核验后补记成功，不重复提交。并行文件执行器异常结束也恢复遗留领取回执。
- 共享盘重连仅针对本客户端曾取得且未主动交接的编辑会话；关闭自身失效句柄后，重新取得 OS 锁、刷新共享版本并发布待提交事件。其它客户端活跃时等待系统正常交接，不删除锁文件、不按心跳时间抢占。
- 任何可能重连的权限检查都要放在读取并比较确认版本之前；否则权限检查里刷新了另一客户端的新款号，调用方却仍可能沿用刷新前的旧记录。现场已有DecisionId的文件任务同样校验共享确认版本。
- 归档准备阶段先取得短期只读保护，以真实 Windows 错误进入重试；历史待写目录恢复独立于当前浏览位置。

## 验证

2026-11-13：96 项组合回归通过，含真实 Windows 分享锁、超过旧上限后自动续写、连续改款保留最新值、提交日志接续、失效系统句柄重连、双客户端交接及真实浏览器等待状态收尾。额外覆盖待写目录恢复优先级、并行执行器回执中断和重连旧确认取消；补充兼容55项中53通过／1缺RAW跳过／1原有OCR浏览器取消请求异常（修改前基线复现）。测试使用隔离生成照片和本地 OS 共享句柄，未取得客户机实际日志或模拟特定 NAS 固件的全部网络行为。
